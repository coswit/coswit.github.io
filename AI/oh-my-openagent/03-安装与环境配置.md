# 第三章：安装、订阅与环境配置

本章把 oh-my-openagent（OmO）从零跑起来的全过程一步步走一遍：先选发行版、盘点订阅，再用安装器把插件装上，最后配置 Auth、做 Doctor 检查并跑出第一个 `ultrawork`。

> **重要前提**：Ultimate 版是 OpenCode 插件，**不能脱离 OpenCode 单独运行**。如果你还没装 OpenCode，先去 [opencode.ai/docs](https://opencode.ai/docs) 看一眼。最低版本要求：**OpenCode ≥ 1.4.0**。

---

## 3.1 准备工作

### 3.1.1 选发行版

OmO 三个发行版怎么选，官方给的选择题很简单：

| 你的情况 | 选择 | 命令 |
| --- | --- | --- |
| 用 OpenCode，或想要测试最充分的路径 | **Ultimate** | `bunx oh-my-openagent install` |
| 已经在用 Codex CLI | **Light（LazyCodex）** | `npx lazycodex-ai install` |
| 想一条命令、不先装宿主 | **Senpi（beta）** | `npm i -g omo-ai@beta` |
| 两边都想要 | Ultimate + Light | `bunx oh-my-openagent install --platform=both` |

三条纪律：

1. Ultimate **必须**通过 `bunx` 调起，**不要** `npm install -g` / `bun add -g`——全局安装不受官方支持，插件必须能被 OpenCode 从它的加载路径解析到；
2. Senpi 版必须带 `@beta` 标签，裸 `npm i -g omo-ai` 会故意失败（npm 上还有一个同名无关的 `omo` 包，**不要** `bunx omo` / `npx omo`）；
3. 安装器是幂等的，重复执行安全。

### 3.1.2 提前盘点你的"订阅资产"

Ultimate 的安装流程会问你一连串"你有没有 X 订阅"的问题，答错或漏答会直接影响后面的模型分配。建议提前对照下面这张表，把自己有的订阅勾出来：

| 订阅 | CLI 标志 | 说明 |
| --- | --- | --- |
| Claude Pro / Max | `--claude=yes` 或 `--claude=max20` | Sisyphus / Prometheus / Atlas 的主力来源 |
| ChatGPT Plus / OpenAI | `--openai=yes` | Hephaestus（GPT-5.6 Sol）、Momus（GPT-5.6 Terra）的来源 |
| Gemini（Antigravity） | `--gemini=yes` | Gemini 系列，前端/视觉备援 |
| GitHub Copilot | `--copilot=yes` | 兜底回退（代理 Claude / GPT / Grok 等模型） |
| OpenCode Zen | `--opencode-zen=yes` | 提供 `opencode/` 前缀模型 |
| Z.ai Coding Plan | `--zai-coding-plan=yes` | 提供 `glm-5.2` / `glm-4.6v` |
| OpenCode Go（$10/月） | `--opencode-go=yes` | 提供 GLM 5.2、Kimi K3/K2.7、MiniMax M2.7/M3，性价比极高 |
| Kimi for Coding | `--kimi-for-coding=yes` | Sisyphus 的关键 Claude-like 备胎 |
| Bailian Coding Plan | `--bailian-coding-plan=yes` | 阿里系（Qwen 等） |
| MiniMax CN Coding Plan | `--minimax-cn-coding-plan=yes` | minimaxi.com |
| MiniMax Coding Plan | `--minimax-coding-plan=yes` | minimax.io |
| Vercel AI Gateway | `--vercel-ai-gateway=yes` | 通用网关 |

**提供商选择是按 Agent 维度的**，OmO 不存在"全局优先级"，每个 Agent 都跑自己独立的 fallback 链。所以多勾一个订阅都意味着多一条逃生通道。

> ⚠️ 强提醒（官方原文级别的强调）：如果**没有 Claude 订阅**，Sisyphus 智能体很可能不在最佳状态。Sisyphus 的提示词按 Claude 模型族调校，退而求其次的"Claude-like"是 Kimi K3 / GLM 5.2。官方 README 也给出"低保组合"：ChatGPT 订阅（$20）+ Kimi Code 订阅（$19）+ GLM Coding Plan（$10），`ultrawork` 也能跑得不错。

### 3.1.3 选一种工作方式：让 Agent 装，还是自己装？

OmO 文档明确推荐"**让另一个 LLM Agent（Claude Code、Cursor、Codex 等）来帮你装**"，理由是 Ultimate 的安装涉及订阅探测、11 个 Agent 的模型选择、逐提供商认证和旧配置迁移——人类配环境太容易敲错字母。

**给 Agent 看的指令**（推荐）：

```text
Install and configure oh-my-openagent by following the instructions here:
https://raw.githubusercontent.com/code-yeongyu/oh-my-openagent/refs/heads/dev/docs/guide/installation.md
```

或者让 Agent 直接 curl 一份安装手册回来：

```bash
curl -fsSL https://raw.githubusercontent.com/code-yeongyu/oh-my-openagent/refs/heads/dev/docs/guide/installation.md
```

> 文档里特别强调：Agent 必须用 `curl` 拿这份文件，**不要用 WebFetch**，因为 WebFetch 会做摘要、丢掉 `--platform`、subscription、max20 等关键标志。

**自己手动装**也可以，下面我们就走手动路径，便于你看清每一步实际在干什么。

## 3.2 第 0 步：装 / 校验 OpenCode

```bash
if command -v opencode &> /dev/null; then
    echo "OpenCode $(opencode --version) is installed"
else
    echo "OpenCode is not installed. Please install it first."
fi
```

如果没装：参考 [https://opencode.ai/docs](https://opencode.ai/docs)。装完务必确认版本 ≥ 1.4.0：

```bash
opencode --version
```

（装 Codex Light 版的读者对应检查 `codex --version`，并保证 `~/.codex/` 可写；Windows 原生安装还需要 Git Bash，装不上时用 `OMO_CODEX_GIT_BASH_PATH` 指定路径。）

---

## 3.3 第 1 步：安装 Ultimate 版

最快上手（TUI（Terminal User Interface，终端用户界面）交互式）：

```bash
bunx oh-my-openagent install
```

它会进入 TUI 一个个问你订阅的问题，按你的回答自动写入 `opencode.json` 的 `plugin` 字段，并把每个 Agent 的默认模型映射生成到**统一配置文件** `~/.omo/omo.jsonc` 的 `[opencode]` 块（旧版 `oh-my-openagent.json[c]` / `oh-my-opencode.json[c]` 会被一次性迁移进来，之后不再读取）。

**非交互模式**（适合 Agent 自动执行）：

```bash
bunx oh-my-openagent install --no-tui \
    --platform=<opencode|codex|both> \
    [--claude=<yes|no|max20>] \
    [--gemini=<yes|no>] \
    [--copilot=<yes|no>] \
    [--openai=<yes|no>] \
    [--opencode-zen=<yes|no>] \
    [--zai-coding-plan=<yes|no>] \
    [--opencode-go=<yes|no>] \
    [--kimi-for-coding=<yes|no>] \
    [--bailian-coding-plan=<yes|no>] \
    [--minimax-cn-coding-plan=<yes|no>] \
    [--minimax-coding-plan=<yes|no>] \
    [--vercel-ai-gateway=<yes|no>] \
    [--codex-autonomous|--no-codex-autonomous] \
    [--skip-auth]
```

`--platform` 默认 `opencode`；订阅标志只对 `opencode`/`both` 生效；`--codex-autonomous` 只在包含 Codex 时有效（给 Codex 写入 `approval_policy = "never"`、`sandbox_mode = "danger-full-access"` 等全自主权限）。

几个常见组合的实际命令：

- OpenCode + 全订阅满血流：

  ```bash
  bunx oh-my-openagent install --no-tui --platform=opencode \
       --claude=max20 --openai=yes --gemini=yes --copilot=no
  ```

- 只有 Claude 订阅（最常见）：

  ```bash
  bunx oh-my-openagent install --no-tui --platform=opencode \
       --claude=yes --gemini=no --copilot=no
  ```

- OpenCode Go（极致性价比）：

  ```bash
  bunx oh-my-openagent install --no-tui --platform=opencode \
       --claude=no --openai=no --gemini=no --copilot=no --opencode-go=yes
  ```

- Codex Light 一行流（推荐自主模式）：

  ```bash
  npx lazycodex-ai install --no-tui --codex-autonomous
  ```

- Senpi 独立版：

  ```bash
  npm i -g omo-ai@beta
  omo setup   # 首次运行：探测其他工具的凭证 → 征得同意后导入 → 输出模型可用性报告
  ```

### 3.3.1 安装做了什么

| 平台 | 写入内容 |
| --- | --- |
| `opencode` / `both` | 在 `opencode.json` 的 `plugin` 数组注册 `"oh-my-openagent"`；把 Agent → 模型映射生成到 `~/.omo/omo.jsonc` 的 `[opencode]` 块（旧配置先迁移） |
| `codex` / `both` | 把插件拷进 `~/.codex/plugins/cache/sisyphuslabs/omo/`；写 `~/.codex/config.toml` 的 marketplace / plugin / agent / hook-trust 块；组件 CLI 软链到 `~/.local/bin`；可选自主权限 |

**关于包名**：npm 包与 CLI 双名发布（`oh-my-opencode` 与 `oh-my-openagent`），`opencode.json` 里优先写 `oh-my-openagent`；装好后全局短命令是 `omo-agent-toolkit`。如果 doctor 提示 legacy 包名警告，把 `plugin` 数组里的 `"oh-my-opencode"` 改成 `"oh-my-openagent"` 即可。

### 3.3.2 校验注册结果

```bash
opencode --version                       # 确认 ≥ 1.4.0
cat ~/.config/opencode/opencode.json     # plugin 数组应含 "oh-my-openagent"
bunx oh-my-openagent doctor              # Doctor 健康检查
```

`doctor` 对 OpenCode 目标跑 8 项检查：**System、Configuration、TUI Plugin、Deprecated Reasoning Keys、Tools、Models、Telemetry、Team Mode**（Codex 目标有自己的三项检查）。退出码 0 = 全过或仅警告，1 = 至少一项失败。`--verbose` 能看到每个 Agent / Category 实际解析到哪个模型——这是排错第一站。

## 3.4 第 2 步：配置 Auth

OmO 装好后只是把"路线图"画好了，**模型用的 Auth 必须自己 `opencode auth login`**。下面分提供商展开。

### 3.4.1 Anthropic（Claude）

```bash
opencode auth login
# Provider: Anthropic
# Login method: Claude Pro/Max
# 浏览器完成 OAuth
```

确认登录成功后，Sisyphus / Prometheus / Atlas 等核心 Agent 就能跑起来了。

### 3.4.2 Google Gemini（Antigravity OAuth）

Gemini 在 OmO 里推荐使用 **opencode-antigravity-auth** 这个第三方插件，把它加到 `opencode.json`：

```json
{
  "plugin": ["oh-my-openagent", "opencode-antigravity-auth@latest"]
}
```

然后从 [opencode-antigravity-auth README](https://github.com/NoeFabris/opencode-antigravity-auth) 里复制完整的 model 配置合并进 `opencode.json`。**注意**：该插件用 **variant 系统**——`antigravity-gemini-3-pro` 这种基础模型加 `low / high` 变体，不再用 `-low / -high` 后缀。

**Antigravity 配额**：`google/antigravity-gemini-3-pro`（`low`/`high`）、`google/antigravity-gemini-3-flash`（`minimal`/`low`/`medium`/`high`）、`google/antigravity-claude-sonnet-4-6`（含 thinking 版，变体 `low`/`max`）、`google/antigravity-claude-opus-4-5-thinking`（变体 `low`/`max`）。
**Gemini CLI 配额**：`google/gemini-2.5-flash`、`google/gemini-2.5-pro`、`google/gemini-3.6-flash`、`google/gemini-3.1-pro-preview`。

```bash
opencode auth login
# Provider: Google
# Login method: OAuth with Google (Antigravity)
```

**多账号负载均衡**：插件支持最多 10 个 Google 账号，命中限流时自动切换。
**一个路由技巧**：Antigravity 的 Claude 走稳定 200k 上下文车道，直连 Anthropic 的 Claude 是 1M 长上下文车道——长上下文的规划/评审会话要直连，配额均衡的日常活走 Antigravity。

### 3.4.3 Amazon Bedrock（新增）

OpenCode 自己管 Bedrock 认证：先在 `opencode.json` 或 AWS 环境变量里配好，再在 OmO 的 Agent 路由里直接引用 Bedrock 模型 ID：

```json
{
  "agents": {
    "sisyphus": { "model": "amazon-bedrock/us.anthropic.claude-opus-5" },
    "metis":    { "model": "amazon-bedrock/us.anthropic.claude-sonnet-4-6" }
  }
}
```

### 3.4.4 GitHub Copilot

Copilot 在 OmO 里被定位为**全员通用的兜底回退**（代理提供商，按订阅路由到底层模型）。常见映射：

| Agent | Copilot 默认模型 |
| --- | --- |
| Sisyphus | `github-copilot/claude-opus-4.7` |
| Oracle | `github-copilot/gpt-5.6-sol` |
| Explore | `github-copilot/claude-haiku-4-5` |
| Atlas | `github-copilot/claude-sonnet-4.6` |

注意 Librarian 不走 Copilot——它依赖 OpenCode Go / Zen 的 MiniMax、Qwen、DeepSeek 等高速档。

### 3.4.5 Z.ai Coding Plan

主要贡献 `glm-5.2` / `glm-4.6v` 备胎。如果它是你的主力，核心映射会是：

| Agent | Z.ai 模型 |
| --- | --- |
| Sisyphus | `zai-coding-plan/glm-5.2` |
| visual-engineering | `zai-coding-plan/glm-5.2` |
| unspecified-high | `zai-coding-plan/glm-5.2` |
| Multimodal-Looker | `zai-coding-plan/glm-4.6v` |

### 3.4.6 OpenCode Zen

提供 `opencode/` 前缀的统一目录：`claude-opus-5`、`gpt-5.6-sol`、`gpt-5-nano`、`glm-5.2`、`big-pickle`、`minimax-m2.7`、`minimax-m2.7-highspeed` 等。代表性映射：Sisyphus → `opencode/claude-opus-5`、Oracle → `opencode/gpt-5.6-sol`、Explore → `opencode/minimax-m2.7`。

## 3.5 第 3 步：理解你拿到了什么

装完之后，OmO 会把每个 Agent 配上一条优先级链。这一节回答：**这套阵容里谁是主角谁是替补？**

### 3.5.1 模型家族划分

**Claude-like**（指令跟随强、结构化输出，适合长流程编排）：

| 模型 | 提供商 | 备注 |
| --- | --- | --- |
| Claude Opus 5 | anthropic / github-copilot / opencode / vercel | 当前最强 Opus，Sisyphus 首选 |
| Claude Sonnet 5 | 同上 | 更快更便宜，Atlas / Junior 默认 |
| Claude Fable 5 | 同上 | Prometheus / artistry 类别默认 |
| Claude Haiku 4.5 | anthropic / vercel | 快、便宜 |
| Kimi K3 | opencode-go / kimi-for-coding / moonshotai / opencode / vercel | Claude-like，Sisyphus 推荐替补 |
| Kimi K2.7 | opencode-go / vercel | 克制型 Kimi 备胎 |
| GLM 5.2 | opencode-go / vercel | 当前 OpenCode Go 的 Claude-like 档 |
| GLM 5 | zai-coding-plan / opencode | 覆盖广 |
| Big Pickle（GLM 4.6） | opencode | 免费档兜底 |

**GPT 系列**（原则驱动、显式推理）：

| 模型 | 提供商 | 备注 |
| --- | --- | --- |
| GPT-5.6 Sol | openai / vercel / github-copilot / opencode | 深推理主力：Hephaestus、Oracle、ultrabrain/deep |
| GPT-5.6 Terra | openai / vercel | GPT-5.6 中间档，Momus 默认 |
| GPT-5.6 Luna / Luna Fast | openai / github-copilot / opencode / vercel | 轻量档，检索链常客 |
| GPT-5-Nano | opencode / vercel | 极速极便宜 |

**风格不同的模型**：

| 模型 | 提供商 | 备注 |
| --- | --- | --- |
| Gemini 3.1 Pro | google / github-copilot / opencode / vercel | 视觉/前端强，Oracle 备援 |
| Gemini 3.6 Flash | 同上 | 文档检索、轻量任务 |
| MiniMax M3 / M2.7 / M2.7 Highspeed | opencode-go / vercel / minimax 双计划 | 工具型 Agent 主力 |
| Qwen 3.7 Plus | opencode-go / bailian | 1M 上下文高速推理，Explore/Librarian 默认档之一 |
| DeepSeek v4 Flash/Pro | deepseek / opencode-go / vercel | 高速/深度两档，检索与 low 类别链常客 |
| Grok 4.6 | xai / github-copilot / opencode / vercel | unspecified-low 默认 |

**速度优先**：Grok Code Fast 1（极快，代码 grep 利器，手动覆盖选项）、Claude Haiku 4.5、MiniMax M2.7 Highspeed。GPT-5.3-codex-spark 虽极速但压缩太狠，**官方不推荐**给 OmO 的 Agent。

### 3.5.2 每个 Agent 默认拿到了谁

挑核心几个再看一眼：

- **Sisyphus**：`claude-opus-5 (max)` → `kimi-k3` → `gpt-5.6-sol (medium)` → `glm-5.2` → `big-pickle`
- **Hephaestus**：`gpt-5.6-sol (medium)`，仅此一档（不回退 Claude）
- **Prometheus**：`claude-fable-5 (xhigh)` → `kimi-k3 (max)`
- **Atlas / Junior**：`claude-sonnet-5` → `kimi-k3` → `gpt-5.6-sol` → MiniMax 系 → `big-pickle`
- **Explore / Librarian**：`gpt-5.6-luna-fast` → `deepseek-v4-flash` → `qwen3.7-plus` → MiniMax 系 → `claude-haiku-4-5` → `gpt-5.4-nano`

**重点**：**没有全局优先级**，每个 Agent 自己选。装完跑一次 `bunx oh-my-openagent doctor --verbose` 看看具体每个 Agent 落到了谁身上，最直观。

## 3.6 第 4 步：自定义模型映射

OmO 默认配置已经"开箱满血"，但如果你想覆盖（比如把 Sisyphus 强制换成 Kimi K3），编辑 `~/.omo/omo.jsonc`（用户层）或项目里 `.omo/omo.jsonc`（项目层，就近覆盖用户层）的 `[opencode]` 块：

```jsonc
{
  "$schema": "https://raw.githubusercontent.com/code-yeongyu/oh-my-openagent/dev/assets/omo.schema.json",

  "[opencode]": {
    "agents": {
      // 主编排者：Claude Opus 或 Kimi K3 最佳
      "sisyphus": {
        "model": "kimi-for-coding/kimi-k3",
        "ultrawork": { "model": "anthropic/claude-opus-5", "reasoning": "max" }
      },
      // 检索型 Agent：便宜快的模型就够
      "librarian": { "model": "google/gemini-3.6-flash" },
      "explore":   { "model": "github-copilot/grok-code-fast-1" },
      // 架构顾问：GPT-5.6 Sol 或 Claude Opus
      "oracle":    { "model": "openai/gpt-5.6-sol", "reasoning": "high" }
    },

    "categories": {
      "visual-engineering": { "model": "anthropic/claude-opus-5", "reasoning": "max" },
      "ultrabrain":         { "model": "openai/gpt-5.6-sol", "reasoning": "max" },
      "deep":               { "model": "openai/gpt-5.6-sol", "reasoning": "medium" },
      "artistry":           { "model": "anthropic/claude-fable-5", "reasoning": "xhigh" },
      "quick":              { "model": "kimi-for-coding/kimi-for-coding-highspeed" },
      "unspecified-low":    { "model": "xai/grok-4.6", "reasoning": "xhigh" },
      "unspecified-high":   { "model": "kimi-for-coding/kimi-k3", "reasoning": "max" },
      "writing":            { "model": "kimi-for-coding/kimi-k3", "reasoning": "low" }
    }
  }
}
```

注意统一的**配置文件体系**（2026-07 起）：

- 用户层（最低优先级）：`~/.omo/omo.jsonc`；
- 项目层：从工作目录到 `$HOME` 逐层向上的 `.omo/omo.jsonc`，**就近者胜**；
- 文档内部按 `[opencode]` / `[senpi]` / `[codex]` 块给各宿主解析自己的视图，还支持 `profiles.<name>` 多套配置（用 `OMO_PROFILE` 切换）；
- 旧版 `oh-my-openagent.json[c]` / `oh-my-opencode.json[c]` 由迁移引擎一次性导入后**不再读取**（导入策略 no-clobber：已有值优先，跳过的旧值会以诊断信息报告）。

`reasoning` 是现在的规范字段（取值 `off/minimal/low/medium/high/xhigh/max` 等按模型能力归一化），旧的 `variant` / `reasoningEffort` / `thinking` 仍被接受但会归一化。

### 3.6.1 安全 vs 危险的覆盖

**安全（同家族或有对应提示词路径）**：

- Sisyphus：Opus → Sonnet / Kimi K3 / GLM 5.2（GLM 5.2 有专用校准提示词）；
- Prometheus：Fable → GPT-5.6 Sol（现在同一份轻量提示词，换模型不换提示词）；
- Atlas：Kimi K3 → Sonnet / GPT-5.6 Sol（自动切换提示词路径）。

**危险（不要做）**：

- Sisyphus → 不支持的 GPT 老模型（受支持的 GPT 路径只有 5.4、5.5、5.6 Sol）；
- Hephaestus → Claude（它是为 Codex 风格打造的）；
- Explore / Librarian → Opus（天价浪费 Token，检索根本不需要）。

### 3.6.2 fallback_models：字符串 / 对象混合

每个 Agent / Category 都可以写 `fallback_models` 数组，元素既可以是字符串，也可以是带 reasoning / temperature 等设置的对象：

```jsonc
{
  "[opencode]": {
    "agents": {
      "sisyphus": {
        "model": "anthropic/claude-opus-5",
        "fallback_models": [
          "openai/gpt-5.6-sol",
          { "model": "google/gemini-3.1-pro", "reasoning": "high", "temperature": 0.2 },
          { "model": "anthropic/claude-sonnet-5", "reasoning": "high" }
        ]
      }
    }
  }
}
```

模型解析优先级：UI 选择的模型 → 用户显式 `model` 覆盖 → Category 默认 → 用户 `fallback_models` → 内置提供商链 → OpenCode 默认模型。用户配的 `fallback_models` 会在内置链**之前**尝试。

## 3.7 第 5 步：模型能力缓存（models.dev）

OmO 的模型能力（上下文窗口、是否支持 reasoning、是否多模态等）来自 [models.dev](https://models.dev) 的快照 + 可刷新缓存 + 提供商运行时元数据 + 启发式回退。能力不匹配的设置会被自动归一化而不是报错（例如给不支持的模型配 `temperature` 会被剔除、超出的 `maxTokens` 会被截到模型上限）。

刷新本地缓存：

```bash
bunx oh-my-openagent refresh-model-capabilities
```

启动时自动刷新：

```jsonc
{
  "model_capabilities": {
    "enabled": true,
    "auto_refresh_on_start": true,
    "refresh_timeout_ms": 5000,
    "source_url": "https://models.dev/api.json"
  }
}
```

## 3.9 遥测、隐私与卸载

### 3.9.1 匿名遥测

OmO 默认开启匿名遥测，仅统计活跃安装（日/周/月活跃，DAU/WAU/MAU）：每机器每 UTC 日最多发一次事件，使用 SHA256 哈希化的安装标识，**不创建 PostHog person profile，绝不上传原始主机名**。关闭方式（三选一）：

```jsonc
// 配置方式（[opencode] 块）
{ "[opencode]": { "telemetry": false } }
```

```bash
export OMO_DISABLE_POSTHOG=1
# 或
export OMO_SEND_ANONYMOUS_TELEMETRY=0
```

（Codex Light 版单独用 `OMO_CODEX_DISABLE_POSTHOG=1`；全局标志对它也生效。）详见 [Privacy Policy](https://github.com/code-yeongyu/oh-my-openagent/blob/dev/docs/legal/privacy-policy.md)。

### 3.9.2 卸载

不打算继续用了？分平台走：

```bash
# 1. 从 opencode.json 的 plugin 数组移除入口
jq '.plugin = [.plugin[] | select(. != "oh-my-openagent" and . != "oh-my-opencode")]' \
    ~/.config/opencode/opencode.json > /tmp/oc.json && \
    mv /tmp/oc.json ~/.config/opencode/opencode.json

# 2. 删除统一配置与旧版残留（可选）
rm -f ~/.omo/omo.jsonc ~/.omo/omo.json \
      ~/.config/opencode/oh-my-openagent.json[c] ~/.config/opencode/oh-my-opencode.json[c] \
      .omo/omo.json[c] .opencode/oh-my-openagent.json[c] .opencode/oh-my-opencode.json[c]

# 3. 校验
opencode --version   # 插件不应再加载

# 4. Codex Light 版
npx lazycodex-ai uninstall   # cleanup 是兼容别名
```

## 3.10 安装阶段最常见的坑

下面这些是社区里反复出现的故障，提前知道能省掉一晚上的 debug：

1. **OpenCode 版本不够**：`opencode --version` < 1.4.0 → 升级 OpenCode；
2. **用 `npm install -g` 装了 Ultimate**：不受支持，改回 `bunx oh-my-openagent install`；如果 Bun 报告拦截了生命周期脚本，用 `bun pm -g untrusted` 先审查再信任；
3. **`Using legacy package name` 警告**：把 `opencode.json` 里 plugin 数组的 `"oh-my-opencode"` 改成 `"oh-my-openagent"`；
4. **Claude OAuth 浏览器没回调**：检查防火墙、再次 `opencode auth login`；
5. **Doctor 提示某 Agent 落到了 "compatibility fallback"**：通常是所配模型在 models.dev 缓存中无能力记录，跑 `refresh-model-capabilities`，或改成已知模型 ID；
6. **想要免费/低成本路线但默认配置仍走 Claude**：用 `--claude=no` 重装，或在 `~/.omo/omo.jsonc` 里把 `agents.sisyphus.model` 显式改为 `opencode-go/kimi-k3` / `zai-coding-plan/glm-5.2`；
7. **旧机器装 Senpi 报 EEXIST**：说明还有 4.19.4 及更早的全局旧包占着 `omo` 这个 bin 名，先卸载旧包；
8. **Windows 原生装 Codex Light 找不到 Git Bash**：`winget install --id Git.Git -e` 后重试，或 `setx OMO_CODEX_GIT_BASH_PATH "C:\Program Files\Git\bin\bash.exe"`；
9. **Ollama 本地模型报 `JSON Parse error: Unexpected EOF`**：必须关流式——在 OpenCode 的 provider 设置（不是 OmO 的 agent 配置）里配 `stream: false`。
