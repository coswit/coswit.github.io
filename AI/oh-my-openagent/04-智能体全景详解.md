# 第四章：智能体（Agents）全景详解

oh-my-openagent（OmO）内置 **11 个智能体**。它们不是 11 个独立的 prompt 模板，而是被精心设计成一支"工程团队"——每位有清晰的职责、独特的提示词风格、最佳搭配的模型、明确的工具权限边界。本章逐个介绍它们，并把"在什么时候叫它们出来"讲清楚。

---

## 4.1 11 个 Agent 全景图

按 OpenCode 的会话模式分两组：

| 模式 | 成员 | 说明 |
| --- | --- | --- |
| **primary**（顶层会话 Agent） | **Sisyphus**、**Hephaestus**、**Prometheus**、**Atlas** | 可在 UI / CLI 里直接选择 |
| **subagent**（被委派的工作 Agent） | **Oracle**、**Librarian**、**Explore**、**Multimodal-Looker**、**Metis**、**Momus**、**Sisyphus-Junior** | 通过 `task(subagent_type=...)` 或 `call_omo_agent(...)` 调起 |

按"我什么时候会用到它"分三种交互方式：

1. **默认对话** → 默认就是 Sisyphus；
2. **Tab 切换 Agent** → 进入 Hephaestus / Prometheus 等 primary Agent；
3. **`@xxx` 提及 / `task()` 调用** → 由当前 Agent 内部委派 subagent。

OmO 为 primary Agent 固定了 **tab 循环顺序**：Sisyphus → Hephaestus → Prometheus → Atlas（其余按字母序），避免无意义的顺序漂移；可以用配置 `agent_order` 覆盖。

### 显示名、提供商与模型 ID 的关系

在日志或 TUI 里会同时出现三种名字，别混淆：

- **Agent 显示名**：`Sisyphus - ultraworker`、`Atlas - Plan Executor`、`Hephaestus - Deep Agent`——只是显示名，不是独立的提供商或账号；
- **提供商命名空间**：`anthropic`、`openai`、`github-copilot`、`opencode`、`opencode-go`、`vercel`——决定这次请求走哪个已连接的账号/网关；
- **模型 ID**：`claude-opus-5`、`kimi-k3`、`gpt-5.6-sol`——决定模型家族。

看到 "Sisyphus 跑在 `opencode-go/kimi-k3` 上"的含义是：Sisyphus 的提示词 + 通过 OpenCode Go 这条提供商路径的 Kimi K3 模型，**不是** OmO 偷偷替换了你的提供商。

## 4.2 Sisyphus：主指挥官（The Discipline Agent）

> 名字取自希腊神话：每天推石上山，永不停歇。

### 4.2.1 角色定位

Sisyphus 是 OmO 的 **默认编排者**。他不是"最聪明"的那个，而是"最善于沟通和调度"的那个：

- 制定计划、维护 todo 列表；
- 调用 `task()`、`call_omo_agent()` 并行下发子任务；
- 消息里出现 `ulw` / `ultrawork` 关键词时进入"全力以赴模式"（可用 `agents.sisyphus.ultrawork` 单独覆盖该模式下的模型）；
- 所有任务在没跑完之前不结束，对应 `todo-continuation-enforcer` Hook。

形象地说，Sisyphus 是那种**走遍各处、和每个人都熟、会通过沟通和协调把事情搞定**的项目经理——但纯粹深度技术问题（race condition、内存泄漏）他会让 Hephaestus / Oracle 上。

### 4.2.2 推荐模型

| 模型 | 适配度 | 备注 |
| --- | --- | --- |
| **Claude Opus 5** | 极佳 | 默认首选，提示词按 Claude 调校 |
| **Kimi K3** | 极佳 | Claude-like，官方推荐的"无 Claude 首选"；K3 校准提示词专门治"想太多" |
| **Kimi K2.7 / GLM 5.2** | 良好 | 克制型备胎 / OpenCode Go 主力档（GLM 有专用校准提示词） |
| GPT-5.4 / 5.5 / 5.6 Sol | 一般 | 有各自的 GPT 提示词路径，但仍非首选 |
| 老旧 GPT | ❌ 不推荐 | 无提示词路径，`no-sisyphus-gpt` Hook 会直接拦截 |

完整 fallback 链：

```text
anthropic|github-copilot|opencode|vercel/claude-opus-5 (max)
  → opencode-go|kimi-for-coding|moonshotai|opencode|vercel|.../kimi-k3
  → openai|github-copilot|opencode|vercel/gpt-5.6-sol (medium)
  → zai-coding-plan|opencode|vercel/glm-5.2
  → opencode/big-pickle
```

## 4.3 Hephaestus：正牌工匠（The Legitimate Craftsman）

> 名字取自希腊神话铸造之神。**带有故意的讽刺**：因为这个项目曾被 Anthropic 屏蔽了 Claude API，OmO 团队就为 GPT 系列单独打造了 Hephaestus——"Codex on steroids"。

### 4.3.1 角色定位

Hephaestus 是 **GPT-5.6 Sol 原生的自主深度工作者**，灵感来自 AmpCode 的 deep mode。给他一个目标，不要给他一个食谱——他自己探索代码、自己研究模式、自己端到端实现，**不会让你做保姆**。

适用：

- 复杂架构推理（设计新插件系统、单体拆微服务）；
- 跨多文件的复杂调试（race condition、内存泄漏、异常追踪）；
- 跨域知识合成（Rust 内核 ↔ TS 前端、MongoDB → PostgreSQL 零停机迁移）；
- 任何"我特别想用 GPT 原生推理风格"的场景。

### 4.3.2 模型 & 限制

- 模型：**GPT-5.6 Sol (medium)**，提供商顺序 openai → github-copilot → vercel → opencode，**没有其他档位**；
- 必须有 GPT 系提供商；
- 受 `no-hephaestus-non-gpt` Hook 保护：被强行换非 GPT 模型时会被阻止。

### 4.3.3 与 Sisyphus + ulw 的对比

| 维度 | Hephaestus | Sisyphus + `ulw` |
| --- | --- | --- |
| 模型 | GPT-5.6 Sol (medium) only | Opus 5 / Kimi K3 / GPT-5.6 Sol / GLM 5.2 等 |
| 风格 | 自主深度独行匠 | 关键词激活的全员协作 |
| 适用 | 深架构 / 跨域硬骨头 | 通用复杂任务、"懒人模式" |
| 计划 | 边做边自规划 | 计划驱动的话走 Prometheus → Atlas（`/ulw-execute`），`ulw` 是自主探索 |
| 委派 | 重度使用 explore / librarian | 用 Category 派发 |

**结论**：90% 任务用 `ulw`；只有当你**特别想用 GPT 原生推理风格**或要"AmpCode 深度探索"体验时才切到 Hephaestus（Tab → 选 Hephaestus）。官方也承认：对有界任务，Sisyphus 有过度编排的倾向（issue #6074 在跟踪），此时 Hephaestus 反而干脆。

## 4.4 Prometheus：战略规划师（The Planner）

> 取自希腊神话盗火者，"先思而后行"。

### 4.4.1 角色定位

Prometheus 是 **READ-ONLY 的访谈型规划师**：受 `prometheus-md-only` Hook 限制，只能写 `.omo/*.md` 计划文件，**不能写任何代码**（Bash 与读/搜工具仍可用，也不许借 subagent 之手实现）。

当前版本的访谈流程由 `ulw-plan` 技能驱动，目标是产出 **Decision Complete**（决策完备，零决策残留给实现者）的计划：

1. 你描述需求（"我要重构 auth 系统"）；
2. Prometheus **先探索**：启动 explore / librarian 调研代码库；
3. 意图清晰（CLEAR）时只访谈剩下的"Owner 决策项"；意图含糊（UNCLEAR）时采用合理默认值；
4. 每轮回答后过一遍"放行检查"（核心目标 / 范围 / 关键歧义 / 技术路线 / 测试策略）；
5. **等你明确批准**后才写计划（没有"make it a plan"暗号）；
6. 强制咨询 Metis 做缺口分析；
7. 高准确度模式下进入 **Momus + Oracle 双评审**循环（见 4.6）；
8. 计划落盘到 `.omo/plans/{name}.md`，引导你用 `/ulw-execute` 交给 Atlas。

提示词方面有个重要变化：**Prometheus 现在只用一份轻量基础提示词**（mandatory planner prompt，永远生效，`prompt` / `prompt_append` 只能追加不能替换），由 `ulw-plan` 技能承载规划行为——换模型不再切换提示词。

### 4.4.2 不同意图的访谈策略

| Intent | Prometheus 关注点 | 示例提问 |
| --- | --- | --- |
| 重构（Refactoring） | 安全性 - 行为不变 | "什么测试验证当前行为？""回滚策略？" |
| 从零搭（Build from Scratch） | 发现 - 模式优先 | "代码库里发现模式 X，跟还是偏？" |
| 中等任务（Mid-sized） | 边界 - 精确护栏 | "什么必须不在内？硬性约束？" |
| 架构（Architecture） | 战略 - 长期影响 | "预期寿命？规模需求？" |

### 4.4.3 推荐模型

| 模型 | 备注 |
| --- | --- |
| **Claude Fable 5 (xhigh)** | 默认首选 |
| **Kimi K3 (max)** | 唯一备胎档（同一份提示词，换模型不换行为） |

### 4.4.4 怎么唤出 Prometheus？

- 方式 1：**Tab → 选 Prometheus**（或 `/agent`），适合"我现在就是要规划"；
- 方式 2：`/hyperplan`——不走单一规划者，而是 5 个"恶意评审"多 Agent 对抗式打磨计划（需开启 Team Mode）。

## 4.5 Metis：缺口分析师（The Gap Analyzer）

Metis 在 Prometheus 写计划落盘**之前**强制介入，作用：

- 找出用户请求里隐藏的意图；
- 找出可能让实现偏的歧义；
- 揪出 AI slop 模式（过度工程、scope creep）；
- 找缺失的验收标准；
- 找未被处理的边界情况。

为什么需要 Metis？

> 计划作者（Prometheus）有"ADHD 工作记忆"——它在脑子里建立了很多关联，但从没写到纸上。Metis 强迫这些隐含知识被外显化。

模型：默认 Claude Opus 5 (high)，备胎 Kimi K3 (low)。如果你手里只有一个稀缺的 Claude 高级模型，官方建议优先花在 Metis 这种"计划质量放大器"角色上。

---

## 4.6 Momus：严苛审查官（The Ruthless Reviewer）

### 4.6.1 角色定位

高准确度模式下，计划要过 **Momus + Oracle 双评审**：Momus 查计划质量，Oracle 用最强推理模型独立复审，**两位都批准才放行**。

当前版本的 Momus 是**"批准偏向"**的：只拒有实据的阻断项（verified blockers），检查：

- 引用的文件真实存在、且支持计划的论断；
- 每个任务给执行者可用的起点；
- 任务之间不互相矛盾；
- QA 场景写明了工具、步骤与预期结果；
- 不存在"会让执行完全停摆"的缺失信息。

小缺口、执行者实现时能自行解决的细节**不构成驳回理由**——一份"约 80% 清晰"的计划即视为可执行。任何一位评审拒绝，Prometheus 修完所有被点名的问题后重新提交给两位；**评审轮数上限 5 轮**（除非你明确要求继续）。

### 4.6.2 模型

默认 **GPT-5.6 Terra (high)** → GPT-5.6 Sol (xhigh) → Claude Opus 5 (max) → Gemini 3.1 Pro (high) → GLM 5.2，GPT 派系最严苛。

## 4.7 Atlas：执行指挥棒（The Conductor）

### 4.7.1 角色定位

Atlas 像乐队指挥：**自己不演奏乐器，只负责让大家配合得完美。** 通过 `/ulw-execute` 进入（不需要手动 Tab 切）。

Atlas **能做的**：

- 读文件理解上下文；
- 跑命令验证结果；
- 用 `lsp_diagnostics` 检查错误；
- grep / glob / ast-grep 搜索。

Atlas **被提示词要求必须委派**（注意：当前是 **warn-only** 执法——Atlas 直接写非 `.omo` 文件会收到警告而不是硬拦截，git 提交也不做工具级门禁，纪律主要写在提示词里）：

- 写文件 / 改代码；
- 修 Bug；
- 写测试。

### 4.7.2 智慧累积（Wisdom Accumulation）

每完成一个任务，Atlas 都会：

1. 从子 Agent 的回应中抽取"学到了什么"；
2. 分类成 Conventions / Successes / Failures / Gotchas / Commands；
3. 把这份"经验"传递给后续所有子 Agent——**第二个任务开始就比第一个聪明**。

笔记本（notepad）目录结构：

```text
.omo/notepads/{plan-name}/
├── learnings.md       # 模式、约定、成功做法
├── decisions.md       # 架构选择和理由
├── issues.md          # 遇到的问题、阻塞、坑
└── problems.md        # 未解决问题、技术债
```

### 4.7.3 触发方式

`/ulw-execute` 命令进入——它会读 `.omo/boulder.json` 决定续作还是初始化，并自动把会话切到 Atlas，无需手动 Tab 切。模型：默认 Claude Sonnet 5 → Kimi K3 → GPT-5.6 Sol (medium) → MiniMax M3/M2.7。

## 4.8 Sisyphus-Junior：执行小弟（The Task Executor)

Sisyphus-Junior 是被 Sisyphus 或 Atlas 调用 `task()` 时召唤出来的"专属执行 Agent"，特点：

- **focused**：不能再用 `task()` 委派（工具被禁）；`call_omo_agent` 仍可用于 explore / librarian 检索；计划文件的写入不受工具级拦截；
- **disciplined**：极度强迫地维护 todo；
- **verified**：完成前必须通过 `lsp_diagnostics`；
- **constrained**：拿到的任务说明自带 MUST DO / MUST NOT DO 约束。

### 模型按 Category 决定

Junior 没有固定模型，而是按调用时 `category` 字段动态选：`visual-engineering` → Opus 5、`ultrabrain` → GPT-5.6 Sol、`quick` → Kimi highspeed……通用 fallback：`claude-sonnet-5` → `kimi-k3` → `gpt-5.6-sol` → MiniMax 系 → `big-pickle`。

### 为什么"普通模型"也够用？

因为 Junior 拿到的是：

1. 来自 Atlas 的详细任务说明（50–200 行）；
2. 累积下来的 wisdom；
3. 明确的 MUST DO / MUST NOT DO 约束；
4. 强制验证要求。

**智能在系统里，不在单个 worker 上。**

### 系统提醒：拒绝半途而废

如果 Junior 想"我做完了"但 todo 还有未勾选项，会被 Hook 强行注入：

```text
[SYSTEM REMINDER - TODO CONTINUATION]

Incomplete tasks remain in your todo list. Continue working on the next pending task —
without asking, and re-examining any false completion claims.
```

这就是"推石头"机制的代码体现。

## 4.9 Oracle：架构顾问（The Consultant)

Oracle 是 **READ-ONLY 高 IQ 顾问**：不能 write / edit / apply_patch / task，但 **`call_omo_agent` 被允许**——它可以为了研究而进一步委派 explore / librarian（这是与 Librarian / Explore 的重要差异）。

适用：

- 架构决策（"这个模块该不该拆？"）；
- 代码评审、计划独立复审（高准确度模式与 Momus 并行）；
- 复杂调试咨询；
- 不熟悉模式的解读；
- 安全 / 多系统权衡。

模型：GPT-5.6 Sol (xhigh) 默认 → GPT-5.6 Sol (high)（github-copilot）→ Gemini 3.1 Pro (high) → Claude Opus 5 (max) → GLM 5.2。灵感来自 AmpCode 的 oracle agent。

调用：

```text
Ask @oracle to review this design and propose an architecture
```

## 4.10 Librarian：图书管理员（Docs / OSS）

Librarian 做"基于证据的多仓库分析、文档查询、开源实现示例"。禁 write / edit / task / call_omo_agent（比 Oracle 管得更严）。

适用：

- 不确定的库 API 用法；
- 跨仓库比对实现；
- 找最佳实践；
- 找标准（OAuth 2.1 PKCE / RFC 9728 等）。

模型链主打"快而便宜"：`gpt-5.6-luna-fast (low)` → `deepseek-v4-flash (max)` → `qwen3.7-plus` → MiniMax 高速档 → MiniMax M3/M2.7 → `claude-haiku-4-5` → `gpt-5.4-nano`（与 Explore 同链）。

---

## 4.11 Explore：代码勘探者（Codebase Grep）

Explore 做"快速代码库勘探 + 上下文 grep"，是 OmO 的检索主力。禁 write / edit / task / call_omo_agent，READ-ONLY。

模型链与 Librarian 相同（速度优先）；想让它更快可以手动覆盖成 `github-copilot/grok-code-fast-1`。

```text
Ask @explore for the policy on this feature
```

---

## 4.12 Multimodal-Looker：视觉小组

视觉 / 截图 / PDF / 图表内容分析专家。**白名单**：`read` only。

模型：GPT-5.6 Sol (low) → Kimi K3 → GLM-4.6V → GPT-5-Nano。

调用方式独特：通过 `look_at(path=...)` 工具自动启动，不需要手动 `@`。

## 4.13 工具权限速查表

OmO 通过 Hook 与配置严格控制每个 Agent 能调用的工具：

| Agent | 限制 |
| --- | --- |
| oracle | 禁 write / edit / apply_patch / task；`call_omo_agent` 允许（仅限研究性委派） |
| librarian | 禁 write / edit / task / call_omo_agent |
| explore | 同上 |
| multimodal-looker | 白名单：仅 `read` |
| momus | 禁 write / edit；task 未被禁 |
| prometheus | 只能写 `.omo/*.md`（`prometheus-md-only`） |
| atlas | 写操作 warn-only（提示词纪律 + 警告，非硬拦截） |
| sisyphus-junior | 禁 `task()`（防无限委派） |

另外要区分**指令与执法**：`AGENTS.md` 这类文件只是"指令上下文"，不是确定性权限边界；真正的硬边界来自配置权限（`agents.*.permission`、`tools`）、内置 Agent 限制、OpenCode 自身权限门与 guard hooks（`write-existing-file-guard`、`prometheus-md-only`、`team-tool-gating` 等）。

## 4.14 调用对照速查

下面这张表是日常工作中最常用的"我现在该叫谁"：

| 场景 | 该用谁 | 调用方式 |
| --- | --- | --- |
| 通用复杂任务、犯懒 | **Sisyphus + ulw** | 在默认会话写 `ulw 任务...` |
| 多日 / 关键变更，要做战略规划 | **Prometheus → Atlas** | Tab → Prometheus 访谈，完事 `/ulw-execute` |
| 对抗式高强度规划 | **hyperplan** | `/hyperplan`（需 Team Mode） |
| 深度架构推理、跨文件硬调试 | **Hephaestus** | Tab → Hephaestus |
| 评审一段设计 / 怀疑架构 | **Oracle** | `@oracle` |
| 找代码模式、做大范围 grep | **Explore** | `@explore`，可后台 |
| 查官方文档 / OSS 实现 | **Librarian** | `@librarian`，可后台 |
| 让 AI 看 PDF / 截图 | **Multimodal-Looker** | `look_at(path=...)` |
| 持续追击一个目标直到完成 | **Goal** | `/goal "目标描述"` |
| 真正并行的多 Agent 团队 | **Team Mode** | 开启后 `team_create` |
| 计划缺口分析（自动） | **Metis** | Prometheus 自动召唤 |
| 计划双评审（高准确度） | **Momus + Oracle** | 高准确度模式自动触发 |
| 单任务执行（系统调度） | **Sisyphus-Junior** | Sisyphus / Atlas 内部 `task()` |

## 4.15 一句话记忆每个 Agent

- **Sisyphus**：项目经理，把石头推上山；
- **Hephaestus**：独行匠人，硬骨头交给我；
- **Prometheus**：访谈式规划师，先想清楚再动手；
- **Metis**：缺口分析师，把你脑子里的隐含信息抠出来；
- **Momus**：严苛审稿人，与 Oracle 双签才放行；
