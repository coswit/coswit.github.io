# 第九章：命令、模型回退与配置参考

本章是一份**速查手册**：把前面分散在各章里的模式关键词、命令、CLI 子命令、配置项、模型回退链集中起来，便于你查工具时直接翻到本章。

---

## 9.1 模式关键词（直接打在消息里）

| 关键词 | 适用版本 | 效果 |
| --- | --- | --- |
| `ultrawork` / `ulw` | 全部 | 全员编排模式，不停直到做完 |
| `team mode` / `team-mode` / `team_mode` / `teammode` | Ultimate | 强制 `team_*` 工具编排（需 `team_mode.enabled`；单独 `team` 不触发） |
| `hyperplan` | Ultimate | 对抗式规划（5 个恶意评审） |
| `hyperplan ultrawork` | Ultimate | 两者叠加 |

## 9.2 内置斜杠命令

全部为 **Ultimate 专属**（Codex CLI 没有斜杠命令层）：

| 命令 | 用途 |
| --- | --- |
| `/goal` | 设置 / 查看 / 暂停 / 恢复 / 清除持久线程目标，空闲自动续跑 |
| `/ulw-execute` | 从 `.omo/plans/` 的 Prometheus 计划启动 Atlas 工作会话 |
| `/stop-continuation` | 停掉本会话全部持续机制（todo continuation、Goal、boulder） |
| `/refactor` | 智能重构：LSP + AST-grep + 架构分析 + TDD 验证 |
| `/handoff` | 生成结构化交接文档，新会话无缝续接 |
| `/remove-ai-slops` | 从近期改动中剔除 AI 生成的代码异味并复查 |
| `/hyperplan` | 直接调起 hyperplan 技能（需 Team Mode） |

### 9.2.1 `/goal`

```text
/goal "Build a REST API with authentication"
/goal            # 查看当前目标
/goal pause      # 暂停空闲续跑
/goal resume     # 恢复
/goal clear      # 清除目标
```

- 状态存 `.omo/goal/<sessionID>.json`，会话删除自动清；
- 配套工具 `create_goal` / `update_goal` / `get_goal` 仅在 `goal.enabled: true` 时注册（**默认 false**；`auto_start` 字段暂未接线）；
- 旧 `ralph_loop` 配置自动迁移为 `goal` 并打弃用警告；`default_mode.ralph_loop` 更名 `default_mode.goal`。

```jsonc
{
  "goal": { "enabled": true, "auto_start": false, "default_max_iterations": 100 }
}
```

### 9.2.2 `/ulw-execute`

```text
/ulw-execute [plan-name] [--worktree <path>] [--make-pr] [--ship]
```

切到 Atlas（Atlas 未注册则 Sisyphus），注入计划 + boulder + worktree/PR 上下文后执行；首批动作是 `create_goal` 与注册 todo，不是直接写码。`--make-pr` 隐含 worktree 模式；`--ship` 隐含 `--make-pr` 并干到 PR 合并。

### 9.2.3 自定义命令位置

按优先级（高→低）：

- `.opencode/commands/*.md` 与 `.opencode/command/*.md`（项目，OpenCode 原生）
- `~/.config/opencode/commands/*.md` 与 `~/.config/opencode/command/*.md`（用户，OpenCode 原生）
- `.claude/commands/*.md`（项目，Claude Code 兼容）
- `~/.claude/commands/*.md`（用户，Claude Code 兼容）

关闭内置命令：`{ "disabled_commands": ["refactor", "ulw-execute"] }`（当前枚举不含 `handoff`）。

## 9.3 CLI 子命令速查

推荐的调用名是 `bunx oh-my-openagent <cmd>`（等价旧名 `bunx oh-my-opencode <cmd>`；安装后全局短命令 `omo-agent-toolkit`）：

| 命令 | 用途 |
| --- | --- |
| `install [flags]` | 交互 / 非交互安装（`--platform=opencode\|codex\|both`、各订阅标志、`--codex-autonomous`、`--skip-auth`） |
| `doctor` | 健康检查。OpenCode 目标 8 项：System / Configuration / TUI Plugin / Deprecated Reasoning Keys / Tools / Models / Telemetry / Team Mode；`--verbose` 输出模型解析细节 |
| `boulder` | 查看 `.omo/boulder.json` 的工作状态与每任务统计 |
| `refresh-model-capabilities` | 刷新 models.dev 能力缓存 |
| `mcp oauth login/logout/status <server>` | Skill MCP（Model Context Protocol）的 OAuth 预认证 / 登出 / 状态 |
| `config migrate` | 手动跑旧配置迁移（`--dry-run` / `--json`） |
| `get-local-version` | 本地版本 vs npm 最新 |
| `version` | 打印 CLI 版本 |
| `run <message>` | 非交互会话：跑到 todo 清空、后台任务闲置为止 |

## 9.4 配置文件体系

**一个统一文件配置所有宿主**（2026-07 配置统一迁移之后）：

| 层 | 位置 | 说明 |
| --- | --- | --- |
| 用户层（最低） | `~/.omo/omo.jsonc` | 全局默认（`omo.json` 后缀也接受） |
| 项目层 | 工作目录到 `$HOME` 逐层向上的 `.omo/omo.jsonc` | **就近者胜**，压过用户层 |

文档内部各宿主解析自己的视图（后者胜）：共享基础键 → `[opencode]` / `[senpi]` / `[codex]` 块 → `profiles.<name>` → `profiles.<name>.[宿主]`，最后套默认值。Profile 用 `OMO_PROFILE` > `OCX_PROFILE` > `OPENCODE_CONFIG_DIR` 尾部 `profiles/<name>` 激活。

要点：

- **JSONC**：支持 `//` 行注释、`/* */` 块注释与尾逗号；
- **模型目录**：顶层 `models` 记录短名 → `{ model, reasoning? }` 的规范形状，Agent / Category 引用短名即可；
- **安全不变量**：`mcp_env_allowlist` 与 `browser_automation_engine.playwright_mcp_args` 只认用户层，项目层不能扩展；
- **旧配置迁移**：`oh-my-openagent.json[c]` / `oh-my-opencode.json[c]` / `~/.omo/config.jsonc` 由迁移引擎**一次性导入**（no-clobber：目标已有值优先，跳过项以诊断报告；源文件备份到 `~/.omo/migration-backup-*`；迁移 ID 记在 `_migrations` 数组，重跑无副作用）；
- **schema 提示**：`"$schema": "https://raw.githubusercontent.com/code-yeongyu/oh-my-openagent/dev/assets/omo.schema.json"`。

> 常见误会：往旧的 `~/.config/opencode/oh-my-openagent.json` 里改配置**不生效**——它只在迁移时被读一次。改 `~/.omo/omo.jsonc`。

### 9.5.2 `agents`

可配置的 Agent：`sisyphus`、`hephaestus`、`prometheus`、`oracle`、`librarian`、`explore`、`multimodal-looker`、`metis`、`momus`、`atlas`、`sisyphus-junior`。常用字段：

| 字段 | 说明 |
| --- | --- |
| `model` | 模型覆盖（`provider/model`） |
| `models` | 有序模型链（字符串 / 对象混排） |
| `fallback_models` | 兼容回退链（字符串 / 对象混排，对象可带 `reasoning` / `temperature` / `top_p` / `maxTokens`） |
| `reasoning` | 规范推理档（`off`~`max`，按模型能力自动归一化；取代旧 `variant` / `reasoningEffort` / `thinking`） |
| `temperature` / `top_p` / `maxTokens` | 采样与输出上限（不支持的项自动剔除） |
| `prompt` / `prompt_append` | 替换 / 追加系统提示词，支持 `file://` URI（绝对 / `./` 项目相对 / `~/` 限定目录）。Prometheus 的基础规划提示词永远保留，两者都只会追加 |
| `tools` | 工具开关 map |
| `permission` | 按工具的权限：`edit` / `bash` / `webfetch` / `doom_loop` / `external_directory`，取值 `ask` / `allow` / `deny`（`bash` 可按命令细分） |
| `mode` | `primary` / `subagent` / `all` |
| `disable` | 关闭该 Agent |
| `ultrawork` | ultrawork 消息下的模型 / reasoning 单独覆盖 |
| `compaction` | 压缩用模型覆盖 |
| `category` | 从某类别继承模型 |
| `skills` | 注入该 Agent 提示词的技能名列表 |
| `color` / `displayName` / `description` | UI 展示 |

### 9.5.3 `categories`

类别选项与 `agents` 大同小异：`model` / `models` / `fallback_models` / `reasoning` / `temperature` / `top_p` / `prompt_append`（支持 `file://`）/ `tools` / `max_tokens` / `max_prompt_tokens` / `description` / `is_unstable_agent` / `disable`。关闭某类别：`"ultrabrain": { "disable": true }`。

### 9.5.4 `background_task`

| 字段 | 默认 | 说明 |
| --- | --- | --- |
| `defaultConcurrency` | 5 | 全局并发上限（0 = 不限） |
| `providerConcurrency` | - | 按提供商限额（如 `{"anthropic": 3}`） |
| `modelConcurrency` | - | 按模型限额，压过提供商限额 |
| `staleTimeoutMs` | 2 700 000 | 无活动中断 |
| `maxToolCalls` | 4000 | 每子任务工具调用上限 |
| `circuitBreaker` | 开 | 熔断器（`maxToolCalls` / `consecutiveThreshold`） |

### 9.5.5 `sisyphus_agent`

```jsonc
{
  "sisyphus_agent": {
    "disabled": false,          // 全关 Sisyphus 编排，还原原生 build/plan
    "tdd": true,                // TDD 模式
    "default_builder_enabled": false,
    "planner_enabled": true,    // 启用 Prometheus
    "replace_plan": true        // 把默认 plan agent 降为 subagent
  }
}
```

这些是遗留兼容开关，不控制 Atlas 编排，没事别动。

### 9.5.6 `memory`

持久化、按 Agent 的记忆，存成一个 git 仓库，**默认开启**且主动学习：自我反思（每 25 步或压缩时）、提醒未落盘的持久事实（每 10 轮）、后台事实抽取、空闲 30 分钟的"梦境整理"（dream pass，重组记忆、审计技能使用、更新人物卡片）。

```jsonc
{
  "memory": {
    "enabled": true,
    "agent": "auto",
    "tool_exposure": "direct",
    "reflection": { "trigger": { "step_count": 25 } },
    "nudge": { "every_user_turns": 10 },
    "dream": { "idle_minutes": 30 },
    "agents": { "reviewer": { "dream": { "enabled": false } } }
  }
}
```

### 9.5.7 `runtime_fallback`（默认关闭）

```jsonc
{
  "runtime_fallback": {
    "enabled": true,
    "retry_on_errors": [429, 500, 502, 503, 504],
    "max_fallback_attempts": 3,
    "cooldown_seconds": 60,
    "timeout_seconds": 30,
    "notify_on_fallback": true,
    "restore_primary_after_cooldown": false
  }
}
```

- 触发条件：可重试 HTTP 错误、提供商 Key 配置错误、重试信号（`timeout_seconds > 0` 时的 `message.updated`；结构化 `session.status` 重试事件不受此限）；
- 用代理 API 时可以把 `retry_on_errors` 加上 `401/403/404` 并调短 `timeout_seconds`，让 fallback 秒切；
- 简写 `"runtime_fallback": true` 用默认参数开启。

## 9.6 模型解析与回退总表

### 9.6.1 解析优先级

1. **UI 选择的模型**（primary Agent）；
2. **用户显式 `model` 覆盖**——原样使用，冷缓存也优先于内置链；
3. **Category 默认**（从所属类别继承）；
4. **用户 `fallback_models`**——先于内置链尝试；
5. **内置提供商回退链**（下表）；
6. **OpenCode 默认模型**。

同一条解析链同时驱动**派生时选择**与**运行时重试回退**。

## 9.7 Claude Code 兼容层 & Rules

| 类型 | 位置 |
| --- | --- |
| Commands | `~/.config/opencode/commands/`、`.claude/commands/` |
| Skills | `~/.config/opencode/skills/*/SKILL.md`、`.claude/skills/*/SKILL.md` |
| Agents | `~/.config/opencode/agents/*.md`、`.claude/agents/*.md` |
| MCPs | `~/.claude.json`、`~/.config/opencode/.mcp.json`、`.mcp.json`、`.claude/.mcp.json` |
| Hooks | `~/.claude/settings.json`、`./.claude/settings.json`、`./.claude/settings.local.json` |

分项开关：`claude_code.mcp / commands / skills / agents / hooks / plugins`，`plugins_override` 可精确到单个插件（如 `claude-mem@thedotmack`）。MCP 支持 `${VAR}` 环境变量展开。

**Rules 系统**：`.claude/rules/*.md` / `.mdc` 按条件注入：

```markdown
---
globs: ["*.ts", "src/**/*.js"]
description: "TypeScript/JavaScript coding rules"
---

- Use PascalCase for interface names
- Use camelCase for function names
```

`globs` 匹配、`alwaysApply: true` 无条件注入；`rules-injector` 从文件向项目根逐层搜索，外加 `~/.claude/rules/`。
