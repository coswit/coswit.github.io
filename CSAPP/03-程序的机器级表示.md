## 3.1 历史观点

x86-64 是 Intel 于 2000 年代推出的 64 位指令集,是 IA32 的 64 位扩展（AMD 率先实现,称 AMD64）。演进路线:8086（1978,16 位）→ 80386（1985,IA32 32 位）→ Pentium 系列（MMX/SSE）→ x86-64（2003）。摩尔定律推动下,每个后代都在前代基础上加指令、加寄存器,**x86-64 机器可完全向后兼容运行 IA32 代码**。

## 3.2 程序编码

### 3.2.1 机器级代码

对机器级编程来说,两类抽象至关重要:

- **指令集架构（Instruction Set Architecture,ISA）**:定义机器级程序的格式与行为,处理器状态（PC、寄存器）、指令格式与每条指令对状态的影响。ISA 给程序的假象是:指令一条接一条按序执行（实际硬件乱序并行执行,但保证等价）。
- **虚拟地址**:内存模型是一个巨大的字节数组,实际实现是多个硬件与操作系统层协作的复合系统（第 9 章）。

编译器完成大部分工作:把 C 的控制结构（ if/while/for）、算术与逻辑表达式、指针、数组、结构体翻译成低级的指令操作:**寄存器、内存引用、算术运算、控制转移**。

### 3.2.2 代码示例

```bash
gcc -Og -o mstore mstore.c   # -Og: 生成符合原始 C 代码结构的机器码,适合阅读
gcc -Og -S mstore.c          # 只到汇编,生成 mstore.s
gcc -Og -c mstore.c          # 只到目标文件 mstore.o(二进制)
objdump -d mstore.o          # 反汇编
```

multstore 的 C 与汇编（基于原书示例,注释为中文解说）:

```c
long mult2(long, long);

void multstore(long x, long y, long *dest) {
    long t = mult2(x, y);
    *dest = t;
}
```

```asm
multstore:
    pushq   %rbx            ; 保存 %rbx(被调用者保存寄存器)
    movq    %rdx, %rbx      ; 复制 dest 到 rbx,留作调用后使用
    call    mult2           ; 调用 mult2,返回值在 %rax
    movq    %rax, (%rbx)    ; 将返回值存到 dest 指向的内存
    popq    %rbx            ; 恢复 %rbx
    ret                     ; 返回
```

要点:

- 以 `.` 开头的行是**汇编伪指令**（directive）,指示链接器/汇编器工作,与机器执行无关。
- **反汇编器（objdump）与 GCC 汇编输出格式略有差异**:如 `push %rbx` vs `pushq %rbx`,机器代码的长度由反汇编器计算得出。

### 3.2.3 关于格式的注解

GCC 生成 AT&T 格式汇编（本书采用）,与 Intel 格式区别:

| 项目 | AT&T（本书/GCC） | Intel |
| --- | --- | --- |
| 源/目的顺序 | `movl %eax, %edx`（源在前） | `mov edx, eax`（目的在前） |
| 寄存器前缀 | `%` | 无 |
| 立即数前缀 | `$` | 无 |
| 内存引用 | `movl $0x1, (%eax)` | `mov DWORD PTR [eax], 1h` |

## 3.3 数据格式

C 数据类型与汇编后缀:

| C 声明 | Intel 数据类型 | 汇编后缀 | 大小（字节） |
| --- | --- | --- | --- |
| `char` | 字节 | b | 1 |
| `short` | 字 | w | 2 |
| `int` | 双字 | l | 4 |
| `long` / `char*` | 四字 | q | 8 |
| `float` | 单精度 | s | 4 |
| `double` | 双精度 | l | 8 |

浮点用 SSE 寄存器（`%xmm`）操作,后缀 s/l;整数后缀常可省略（由寄存器名推断）。

## 3.4 访问信息

x86-64 的 16 个 64 位通用寄存器（命名源于历史演变）:

| 64 位 | 32 位 | 16 位 | 8 位 | 用途约定 |
| --- | --- | --- | --- | --- |
| %rax | %eax | %ax | %al | 返回值 |
| %rbx | %ebx | %bx | %bl | 被调用者保存 |
| %rcx | %ecx | %cx | %cl | 第 4 个参数 |
| %rdx | %edx | %dx | %dl | 第 3 个参数 |
| %rsi | %esi | %si | %sil | 第 2 个参数 |
| %rdi | %edi | %di | %dil | 第 1 个参数 |
| %rbp | %ebp | %bp | %bpl | 被调用者保存 |
| %rsp | %esp | %sp | %spl | 栈指针 |
| %r8~%r15 | %r8d... | %r8w... | %r8b... | 参数 5~8 及其他 |

对寄存器的低字节操作时,其余字节**保持不变**;写 16/32 位寄存器时,**高位字节清零**（如 `movl $-1, %eax` 后 %rax 高 32 位为 0,值为 4294967295）;64 位指令才会设置全部。

### 3.4.1 操作数指示符

大多数指令有一个或多个**操作数（operand）**,三种类型:

- **立即数（immediate）**:`$` 前缀,如 `$-577`/`$0x1F`,1/2/4 字节。
- **寄存器（register）**:`%rax` 等 16 个。
- **内存引用（memory）**:根据有效地址访问,格式 `Imm(rb, ri, s)` = $Imm + R_{b} + R_{i} \cdot s$,其中基址寄存器 rb、变址寄存器 ri、比例因子 s ∈ {1, 2, 4, 8}。

### 3.4.2 数据传送指令

`MOV S, D`（把 S 复制到 D）按大小分:`movb`/`movw`/`movl`/`movq`,以及 `movabsq`（传 64 位立即数,普通 movq 只能传 32 位补码扩展的立即数）。

**限制**:

- **源和目的不能都是内存**（内存到内存要两条指令:先加载到寄存器）。
- mov 指令会把寄存器高位清零的规则只适用于 32 位;`movl %eax, %edx` 同时清 %rdx 高 32 位。
- **movq 类的符号扩展**:`movsbq`/`movzbq` 等做符号/零扩展;`movl` 等价于隐式零扩展。

零扩展与符号扩展传送指令:`movzbw/movzbl/movzbq`（零扩展）、`movsbw/movsbl/movsbq`（符号扩展）。没有 `movzsq`（movl 隐式零扩展已覆盖）。

### 3.4.3 数据传送示例

原书 exchange/swap 示例,展示指针参数通过寄存器传递:

```c
long exchange(long *xp, long y) {
    long x = *xp;
    *xp = y;
    return x;
}
```

```asm
exchange:
    movq    (%rdi), %rax    ; x = *xp(rdi 为第 1 个参数 xp)
    movq    %rsi, (%rdi)    ; *xp = y(rsi 为第 2 个参数 y)
    ret                     ; 返回值在 %rax
```

局部变量 x 直接驻留在寄存器中——**编译器尽量把局部变量放寄存器,内存引用只发生在必要时**。

### 3.4.4 压入和弹出栈数据

栈在内存中,栈顶地址最低（%rsp 指向栈顶元素）:

```asm
pushq %rbp        # 等价于: subq $8, %rsp; movq %rbp, (%rsp)
popq  %rax        # 等价于: movq (%rsp), %rax; addq $8, %rsp
```

push/pop 是仅有的"内存作为目的且隐含栈指针"的常用指令。

## 3.5 算术和逻辑操作

| 指令 | 效果 | 说明 |
| --- | --- | --- |
| `leaq S, D` | D = &S | 加载有效地址 |
| `inc D` / `dec D` | D+1 / D−1 | 加一/减一 |
| `neg D` / `not D` | −D / ~D | 取负/取反 |
| `add S, D` / `sub S, D` | D+S / D−S | 加/减 |
| `imul S, D` / `xor S, D` | D×S / D^S | 乘/异或 |
| `and S, D` / `or S, D` | D&S / D\|S | 与/或 |
| `sal k, D` / `shl k, D` | D << k | 左移（两者相同） |
| `sar k, D` / `shr k, D` | 算术/逻辑右移 | 补符号位/补 0 |

### 3.5.1 加载有效地址

`leaq`（load effective address）把**地址计算结果**直接放进寄存器,根本不访问内存:

```c
long scale(long x, long y, long z) {
    long t = x + 4 * y + 12 * z;
    return t;
}
```

```asm
scale:
    leaq    (%rdi,%rsi,4), %rax     # x + 4y
    leaq    (%rdx,%rdx,2), %rdx     # z + 2z = 3z
    leaq    (%rax,%rdx,4), %rax     # (x+4y) + 12z
    ret
```

lea 常被用来**做紧凑的算术**:加法、乘 2/4/8、组合下标计算,没有任何内存访问。

### 3.5.2 一元和二元操作

- 一元操作（如 `incq %rax`）:只有一个操作数,既是源又是目的。
- 二元操作（如 `subq %rbx, %rax`）:**第二个操作数是目的**,AT&T 顺序读作"从 rax 中减去 rbx"。

### 3.5.3 移位操作

移位量可以是立即数或**单字节寄存器 %cl**（只取低 8 位,实际对 w 取模）;移位的目的操作数可以是寄存器或内存。

### 3.5.5 特殊的算术操作

64 位乘除法需要 128 位的乘积/被除数（%rdx:%rax 拼成 octa）:

- `imulq S` / `mulq S`:有/无符号全乘,结果高 64 位在 %rdx、低 64 位在 %rax。
- `cqto`:把 %rax 符号扩展到 %rdx:%rax。
- `idivq S` / `divq S`:有/无符号除法,商在 %rax、余数在 %rdx。

## 3.6 控制

### 3.6.1 条件码

CPU 维护**条件码（condition code）寄存器**,描述最近算术/逻辑运算的属性:

- **CF**（Carry Flag）:无符号溢出。
- **ZF**（Zero Flag）:结果为零。
- **SF**（Sign Flag）:结果为负。
- **OF**（Overflow Flag）:有符号（补码）溢出。

`leaq` 不改变条件码;`xorl` 会清 CF 与 OF;inc/dec 影响 ZF/SF/OF 不影响 CF。

### 3.6.2 访问条件码

三种使用方式:**set 指令**把条件码组合存入字节寄存器;条件跳转;条件传送。

set 指令族（以 `sete`/`setne`/`setg`... 为例）:

| 指令 | 同义名 | 效果 | 设置条件 |
| --- | --- | --- | --- |
| `sete`/`setne D` | setz/setnz | D = ZF | 相等/不等 |
| `sets`/`setns D` | | D = SF | 负/非负 |
| `setg`/`setge D` | setnle/setnl | 有符号 >、≥ | ~（SF^OF） 且 ... |
| `setl`/`setle D` | setnge/setng | 有符号 <、≤ | SF^OF |
| `seta`/`setae D` | setnbe/setnb | 无符号 >、≥ | ~CF & ~ZF / ~CF |
| `setb`/`setbe D` | setnae/setna | 无符号 <、≤ | CF / CF\|ZF |

注意有符号用 SF/OF/ZF 组合,无符号用 CF/ZF。

### 3.6.3 跳转指令

`jmp`（无条件,可 `jmp .L1` 标签或 `jmp *%rax` 间接跳转）+ 条件跳转 `je/jne/js/jg/jge/jl/jle/ja/jae/jb/jbe`,条件与 set 一致。

### 3.6.4 跳转指令的编码

跳转目标编码方式:**PC 相对的**（目标 = PC + 偏移量）与绝对地址。PC 相对编码使代码可不加修改地重定位到内存不同位置（链接一章的基础）。

### 3.6.5 用条件控制来实现条件分支

C 的 if-else 翻译为"先算条件、条件跳转、两段代码":

```c
long ltcount = 0;
long absdiff(long x, long y) {
    long result;
    if (x < y) { ltcount++; result = y - x; }
    else       { result = x - y; }
    return result;
}
```

汇编形态:跳转点分支（当条件不满足时跳过 then 部分）,或分支与直落结构相反——**GCC 常把"then/else 谁直落"按概率估计选择**。

### 3.6.6 用条件传送来实现条件分支

**条件传送（conditional move）**:`cmovXX S, D`,条件成立才复制。先计算两个分支的结果,再按条件选择,例如 `cmovge %rdi, %rax`。

**为什么条件传送更快**:现代 CPU 采用**流水线 + 分支预测**。预测错误时必须丢弃错误路径上的计算并回填流水线,**预测错误处罚约 15~25 个时钟周期**。条件传送把控制依赖转化为**数据依赖**,无预测风险。

**适用条件**:两个分支都能无副作用地提前计算,且开销不大。若分支内有内存越界风险或大量计算,编译器仍会用跳转。总体上,x86-64 上 `x < y ? x : y` 这类"取小/取大"会被编译成 cmp + cmov。

### 3.6.7 循环

汇编没有专门的循环结构,用条件测试 + 跳转组合。GCC 遵循**do-while 形式**最直接:

```c
long fact_do(long n) {
    long result = 1;
    do {
        result *= n;
        n = n - 1;
    } while (n > 1);
    return result;
}
```

```asm
        movl   $1, %eax         ; result = 1
.L2:    imulq  %rdi, %rax       ; result *= n
        subq   $1, %rdi         ; n--
        cmpq   $1, %rdi         ; 比较 n 与 1
        jg     .L2              ; n > 1 则继续循环
        ret
```

- **while 循环**:两种翻译策略——跳转到中间（guard 式）或"转到初始判断"形式;`-O2` 下常用初始测试。
- **for 循环**:先初始化,再按 while 的方式处理 continue（直接跳到更新步骤,避免重复初始化）。

### 3.6.8 switch 语句

switch 根据整数索引做**多重分支**,用**跳转表（jump table）** 实现——一个数组,J 是表项下标,程序跳转到表项指定的地址:

```asm
        cmpq   $6, %rdi         # 与 case 上限比较
        ja     .L8              # default(无符号比较,负数也大于 6)
        jmp    *.L4(,%rdi,8)    # 按索引间接跳转
.L4:    .quad  .L3 ...          # 跳转表: 每个 case 的地址
```

跳转表优点:**一次内存访问 + 间接跳转,O（1）**,case 稀疏时 GCC 自动降级为 if-else 链。

## 3.7 过程

过程调用依赖**运行时栈**传递数据与控制、管理内存。

### 3.7.1 运行时栈

C 的过程调用机制的关键特性（源于递归可能的内存需求）用栈实现:每个函数有自己的**栈帧（stack frame）**:

```mermaid
graph BT
    A[当前正在执行的函数的帧: 最底部的局部变量 若需要则先保存寄存器]
    B[调用者的返回地址 + 保存的寄存器区域]
    C[ Caller 的帧: 为超出寄存器数量的参数准备 1~6 号参数在寄存器]
```

- %rsp 指向栈顶;通过 push/pop 或直接对 %rsp 减/加分配释放帧空间。
- 超过 6 个整型参数的部分**从右向左**压栈;返回地址由 call 压入。

### 3.7.2 转移控制

```asm
call multstore   # 将返回地址压栈, 跳到 multstore
ret              # 弹出返回地址, 跳回
```

leave 指令等价于"释放栈帧 + ret 准备"。

### 3.7.3 数据传送

x86-64 传参寄存器约定（整型与指针）:**%rdi %rsi %rdx %rcx %r8 %r9** 对应第 1~6 个参数;更多参数入栈。返回值（≤64 位）在 %rax。浮点参数用 %xmm0~%xmm7。

### 3.7.4 栈上的局部存储

寄存器不够（取地址、需要长期保存）时局部变量放栈上:在帧内显式为它们分配空间（对 %rsp 减常数）。原书 swap_add/swap 指针交换的例子说明:局部变量若被取地址（&）,必须驻留内存。

### 3.7.5 寄存器中的局部存储空间

寄存器是**唯一**由所有函数共享的资源（约定管理）:

- **调用者保存（caller-saved / caller-save）**:%rax %rdi %rsi %rdx %rcx %r8~%r11——调用别的函数前若还需用,由**调用者**保存。
- **被调用者保存（callee-saved）**:%rbx %rbp %r12~%r15——**被调函数**用前必须保存、返回前恢复。

### 3.7.6 递归过程

递归无需特殊机制——每次调用获得自己的栈帧,寄存器值由保存惯例保证。阶乘递归示例展示 %rbx（保存 n）在帧间独立。

## 3.8 数组分配和访问

### 3.8.1 基本原则

`T A[N]` 在内存中是 L 字节 × N 的连续块（L = sizeof（T））,地址 $A + L \cdot i$ 指向 A[i]。**数组名 A 本质是首地址指针**（作为参数传递时退化为指针）。

### 3.8.2 指针运算

C 的指针运算自动按指向类型缩放:`&A[i]` = $A + 8i$（long 数组）。`A[i]` 等价 `*(A+i)`。

### 3.8.3 嵌套的数组

`int A[5][3]` 是 5 行 3 列的**行主序（row-major）** 连续存储。寻址:

$$A[i][j] = A + L(N \cdot i + j), \quad \text{N 为列数}$$

编译器常用 `leaq` + `imulq` 组合:外层循环中 $N \cdot i$ 的计算可**归纳变量（induction variable）** 提升,每次循环只加 N,避免乘法。

### 3.8.4 定长数组

`#define N 16` 后,GCC 把固定大小的数组运算**完全展开优化**（如固定 16×16 的矩阵转置）,甚至用 SIMD。

### 3.8.5 变长数组

ISO C99 允许 `int A[n][m]`（运行时确定维度）,计算地址需要乘法指令（不能归纳提升,但循环内仍可增量优化）。

## 3.9 异构的数据结构 Heterogeneous Data Structures

### 3.9.1 struct 

struct 把不同类型对象聚合在一块连续内存中,字段偏移在编译期确定:

```c
struct rec {
    int i;      // 偏移 0
    int j;      // 偏移 4
    char a[8];  // 偏移 8
};
```

访问 `r->j` 编译为基址寄存器 + 常量偏移,与数组下标计算组合即可表达任意嵌套结构。

### 3.9.2 union

**联合（union）** 用**同一块内存**在不同时刻容纳不同类型:

```c
union U3 {
    char c;     // 偏移 0, 大小 1
    int i[2];   // 偏移 0, 大小 8
    double d;   // 偏移 0, 大小 8
};              // 总大小 8(取最大成员)
```

- **大小 = 最大成员对齐后的尺寸**;访问哪个成员就按哪个类型解释这块内存。
- 经典用法 1:判断大小端（写 int 后读 char）;用法 2:强制类型转换访问位模式;用法 3:实现"二义性"数据结构（BST 节点中叶子/内部节点的代码块共享）。
- 结构 vs 联合:struct 各字段**都同时存在**,union 字段**互斥**。

### 3.9.3 数据对齐

**对齐（alignment）**:数据地址必须是其对齐值（K）的倍数,硬件与总线效率要求。规则:**任何 K 字节基本对象的地址必须是 K 的倍数**:

- `char` 任意、`short` 2、`int`/`float` 4、`long`/`double`/指针 8。
- **struct 的每个成员按各自对齐放置,总大小向最大成员对齐的倍数取整**（尾部可能填充）。
- 编译器在数组场景必须严格对齐（数组元素间同样要对齐）。
- `.align 8` 汇编伪指令、`sizeof(struct S)` 体现填充:`struct {char c; int i;}` 大小为 8（c 后填 3 字节）。
- **对齐例外**:x86-64 允许未对齐访问但慢;某些 SIMD 指令（如 `vmovaps`）强制要求对齐。

## 3.10 在机器级程序中将控制与数据结合起来

### 3.10.1 理解指针

- 每个指针有**类型**与**值**（地址）两部分。
- `&` 创建指针、`*` 解引用;指针转为无符号时表达式 `%rdi` 中的地址可直接比较。
- **数组与指针**:数组变量在表达式中退化为首地址;`sizeof` 例外（返回整个数组大小）。
- **指针转换**:指向不同类型的指针共享机器级表示,只是解释不同;`void *` 是通用指针（C 中无需显式转换）。
- 函数指针:`void (*f)(int)` 的值即函数机器码首地址,支持间接调用/回调。

### 3.10.2 应用:使用 GDB（GNU Debugger）调试器

```bash
gdb prog
break main / break *0x400540   # 断点: 符号或地址
run / continue / stepi / nexti # 运行/继续/单步一条指令
print $rax / print /x $rsp     # 检查寄存器与内存
x/14xb $rsp                    # 以十六进制查看 14 字节
disassemble                    # 反汇编当前函数
```

### 3.10.3 内存越界引用和缓冲区溢出

C 不做任何边界检查,写越界的字节会破坏栈上其他数据。经典 gets/echo 示例:输入长于缓冲区的字符串会**覆盖返回地址**:

```c
void echo() {
    char buf[8];      // 栈上 8 字节
    gets(buf);        // 不检查长度! 已废弃的 API
    puts(buf);
}
```

攻击者可以:覆盖返回地址 → 跳转到注入代码（code injection）;或更高级的 **ROP（Return-Oriented Programming）**:利用程序已有指令片段（gadget）组合作恶。历史上大量安全漏洞源于此。

### 3.10.4 对抗缓冲区溢出攻击

现代系统的多层防御:

- **栈随机化（Address Space Layout Randomization,ASLR 的栈部分）**:栈起始地址每次运行随机变化,攻击者难以预测注入代码位置。
- **栈破坏检测（canary, 金丝雀值）**:函数入口在栈上返回地址前放一个**哨兵值**（随机产生）,返回前检查是否被改动,改动则 abort（`-fstack-protector`）。
- **限制可执行代码区域**:NX（No-eXecute）位,栈/堆内存页标记为不可执行。
- 更根本的:**用带边界检查的语言/库**（`fgets` 替代 `gets`,C++ std::vector::at 等）。

栈随机化与"nop sled"（大量 nop 指令滑梯增大命中概率）是攻防的经典对抗。

### 3.10.5 支持变长栈帧

`alloca`/变长数组需要**帧指针 %rbp** 动态记录帧基址（因为 %rsp 在帧内可变）,先保存旧 %rbp 再调整 %rsp。

## 3.11 浮点代码

x86-64 浮点基于 **SSE（Streaming SIMD Extensions）/AVX（Advanced Vector Extensions）**:`%xmm0~%xmm15`（128 位 XMM）,AVX 扩展到 256 位 `%ymm`。本书第 3 版使用 **AVX2**（gcc `-mavx2`）。AVX 指令以 `v` 开头,采用**两操作数或三操作数**格式（目的操作数只能是寄存器,如 `vaddsd %xmm2, %xmm1, %xmm0` 计算 xmm1+xmm2 存入 xmm0）。

### 3.11.1 浮点传送与转换操作

- 传送:`vmovss`/`vmovsd`（标量单/双精度,寄存器↔寄存器或内存）、`vmovaps`/`vmovapd`（寄存器间传送整个 xmm,要求对齐）。
- 转换:`vcvtsi2ss`（整数→float）、`vcvtsi2sd`（整数→double）、`vcvtss2sd`（float→double）、`vcvtsd2ss`（double→float）、`vcvttss2si`/`vcvttsd2si`（浮点→整数,**截断**为向零舍入）。
- 浮点→整数越界或 NaN 时,结果为 $TMin_w$（称为**整数不确定值**,integer indefinite）。

### 3.11.2 过程中的浮点代码

- 浮点参数与返回值走 **%xmm 寄存器**:最多 8 个 xmm 参数（与最多 6 个整型寄存器参数**并行**计数）,返回值在 %xmm0。
- %xmm0~%xmm7 全部是**调用者保存**;其余 %xmm8~%xmm15 是被调用者保存。

### 3.11.3 浮点算术操作

- `vaddss/vsubss/vmulss/vdivss`（单精度标量）、`vaddsd/vsubsd/vmulsd/vdivsd`（双精度标量）;AVX 还提供打包（packed）版本对整个向量并行运算。
- 与整数指令不同,浮点算术的目的操作数只能是寄存器。

### 3.11.4 定义和使用浮点常数

AVX 浮点指令**不支持立即数操作数**:编译器把常数放入**只读内存（.rodata）**,再读入寄存器;`vbroadcastss` 可把一个标量复制到 XMM/YMM 的所有位置,用于向量化的常数初始化。

### 3.11.5 在浮点代码中使用位级操作

`vxorps`/`vorps`/`vandps` 对浮点寄存器做按位运算。经典技巧:**`vxorps %xmm0, %xmm0, %xmm0` 一条指令生成 +0.0**（全零位模式）,比从内存加载常数更快。

### 3.11.6 浮点数比较操作

`vucomiss`/`vucomisd S1, S2` 比较两个浮点数并设置条件码（CF/ZF/PF）。浮点比较存在第三种结果——**无序（unordered,任一操作数为 NaN）**,此时三个标志全置 1。因此:

- 判断 `x < y`:用 `jb`（CF=1）;
- 判断 `x == y`:用 `je` 且**必须先用 `jp` 排除 NaN**（NaN 与任何数比较都是无序,je 会误判相等）。

GCC 对 `x == y` 生成的汇编通常是 `jp`（NaN 时跳到"取 0/假"分支）+ `je` 的组合。

### 3.11.7 对浮点代码的观察

浮点代码高度依赖**编译器版本与机器能力**（SSE2/AVX/AVX2 的选择、`-mavx2 -O1` 等选项）,同一 C 代码可能生成相当不同的汇编;分析浮点性能时要注意标量与向量（SIMD）路径的差异。

## 3.12 小结

- 机器级程序 = 寄存器操作 + 内存访问 + 条件码 + 控制转移;C 的结构最终都落到这几类操作。
- 过程调用与递归的栈机制、寄存器保存惯例是理解程序运行时的钥匙。
- 对齐、数组寻址、struct/union 布局决定内存利用率与缓存友好性（第 6 章）。
- 缓冲区溢出根植于 C 的无边界检查 + 栈结构,防御是系统级的（canary、NX、ASLR）。
