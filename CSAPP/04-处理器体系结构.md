## 4.1 Y86-64 指令集体系结构

本章用教学指令集 **Y86-64** 从零构造处理器。它比 x86-64 简单（指令少、格式规整）,但保留足够真实度:能实现完整的程序控制、内存访问与简单函数调用,且能设计出与真实处理器同构的流水线。

### 4.1.1 程序员可见的状态

- **寄存器**:%rax ~ %r14 共 15 个（无 %r15）,每个 64 位;%rip（PC）。
- **条件码**:ZF、SF、OF（比 x86-64 少了 CF）。
- **程序状态 Stat**:指示程序正常（AOK）或异常（HLT/ADR/INS）。

### 4.1.2 Y86-64 指令

| 指令 | 含义 | 对应 x86-64 |
| --- | --- | --- |
| `halt` | 停机 | — |
| `nop` | 空操作 | nop |
| `rrmovq rA, rB` | 寄存器→寄存器 | movq |
| `irmovq V, rB` | 立即数→寄存器 | movq |
| `rmmovq rA, D(rB)` | 寄存器→内存 | movq |
| `mrmovq D(rB), rA` | 内存→寄存器 | movq |
| `OPq rA, rB` | addq/subq/andq/xorq | 算术逻辑 |
| `jXX Dest` | jmp/jle/jl/je/jne/jge/jg | 条件跳转 |
| `cmovXX rA, rB` | 条件传送 | cmovge 等 |
| `call Dest` / `ret` | 调用/返回 | call/ret |
| `pushq rA` / `popq rA` | 压栈/出栈 | pushq/popq |

限制:立即数只能是 64 位常数;没有字节级操作,全为 64 位;运算指令只有 4 个。

### 4.1.3 指令编码

定长指令设计（1~10 字节）:首字节为**指令代码 icode:ifun**（高 4 位/低 4 位）,后跟可选的**寄存器指示字节**（高 4 位 rA、低 4 位 rB,无寄存器操作数用 0xF 标记）、8 字节常数字（小端）。跳转目标用**绝对地址**编码。

RISC 与 CISC 对比:CISC（x86）指令变长、格式多样;RISC（ARM/MIPS）指令定长、内存访问只能用 load/store。**x86 现代实现内部先把 CISC 指令拆成类 RISC 微操作**,两种流派在实现层融合。

### 4.1.4 Y86-64 异常

状态码 Stat:AOK（正常）、HLT（halt 指令）、ADR（无效地址）、INS（非法指令）。异常时处理器停止执行指令。真实系统中异常会交给操作系统处理（第 8 章）。

### 4.1.5 Y86-64 程序

原书用 Y86-64 汇编重写了 x86-64 的 Sum 函数与调用链:链接器 YAS 汇编、指令存储在内存中按序执行。要点:

- 目标代码与汇编写法一一对应;
- Y86-64 的 `irmovq $…` 必须显式加载立即数,比 x86-64 多几条指令;
- 汇编 `.pos`/`.align` 伪指令设置地址与对齐。

### 4.1.6 一些 Y86-64 指令的详情

pushq/popq 的实现细节:压栈时先减 %rsp 再写;popq 先读再加 %rsp。**Y86-64 中 pushq %rsp 压入的是原值（减之前的 rsp）,与 x86-64 行为一致**。

## 4.2 逻辑设计和硬件控制语言 HCL

数字系统 = **组合逻辑**（输出只是输入的函数）+ **存储单元**（保存状态）。

### 4.2.1 逻辑门

基本逻辑门:AND、OR、NOT,由晶体管实现,是数字电路的原子。

### 4.2.2 组合电路和 HCL 布尔表达式

**组合电路（combinational circuit）**:无环、无记忆,输出仅由当前输入决定。HCL（Hardware Control Language,Y86-64 配套的硬件控制语言）用 C 风格语法写布尔表达式:

```hcl
bool out = (s && a) || (!s && b);   # 多路复用器: s 选择 a 或 b
```

区别于 C 表达式:HCL 是**硬件描述**（逻辑门网络）,而非顺序执行的语句。

### 4.2.3 字级的组合电路和 HCL 整数表达式

- **多路复用器（Multiplexer,MUX）**:按选择信号从多个源中选一个,字级写法:

```hcl
word Out4 = [
    !s1 && !s0 : A;   # 00 选 A
    !s1 && s0  : B;   # 01 选 B
    s1 && !s0  : C;   # 10 选 C
    1          : D;   # 默认选 D
];
```

- **四路一字宽 ALU（Arithmetic and Logic Unit,算术逻辑单元）**:由三个 64 位加法器/逻辑单元 + 2 个多路复用器构成。
- 零检测 / 符号检测:`bool eq = (A == B)`、`bool sgn = A[63]`。

### 4.2.4 集合关系

判断集合成员关系的 HCL 语法:

```hcl
bool scond = code in { IJMP, IJLE, IJL, IJE, ... };
```

用于"是否为跳转指令"这类判断,比一串布尔或更可读。

### 4.2.5 存储器和时钟

**时序电路（clocked circuit）**:状态随**时钟（clock）** 周期改变。

- 寄存器:时钟上升沿保存输入值,其余时间输出不变。
- 随机访问存储器:虚拟寻址的字数组。**读**可随时发生（组合行为）;**写**在时钟边沿生效。
- 处理器中唯一改变状态的指令:寄存器写、内存写、条件码写、PC 更新。

## 4.3 Y86-64 的顺序实现

### 4.3.1 将处理组织成阶段

所有 Y86-64 指令按统一六阶段流动:

| 阶段 | 工作 |
| --- | --- |
| **取指（fetch）** | 从 PC 读 10 字节指令,抽 icode:ifun、rA:rB、valC、valP |
| **译码（decode）** | 读寄存器 rA/rB 得 valA、valB |
| **执行（execute）** | ALU 运算得 valE、设置条件码;或算跳转目标 |
| **访存（memory）** | 读/写内存得 valM |
| **写回（write back）** | 写寄存器 |
| **PC 更新（PC update）** | PC ← 下一条指令地址 |

典型指令的六阶段数据流:

- **OPq**:valB OP valA（注意 Y86-64 中是 `valB op valA`）→ valE 写入 rB。
- **rmmovq**:valE = valB + valC（地址）,内存写 valA。
- **jXX**:条件码成立则 new PC = valC,否则 valP（PC+指令长）。
- **call**:内存写返回地址 valP,new PC = valC。
- **pushq**:valE = %rsp−8,写内存 valA,同时更新 %rsp。
- **ret**:从内存读返回地址 valM,new PC = valM。

### 4.3.2 SEQ 硬件结构

组合逻辑单元（ALU、多路复用器等）连接成六阶段流水,内存与寄存器堆是唯一的时序元件。同一周期内信号从取指逐级流向 PC 更新。

### 4.3.3 SEQ 的时序

**核心原则:处理器从来不需要回读当前指令执行结果的状态**——PC、条件码、寄存器、内存的更新都在时钟周期末尾同步发生。这使 SEQ 能在一拍内完成一条指令,简化了实现,代价是时钟周期必须容纳最慢的指令路径。

### 4.3.4 SEQ 阶段的实现

各阶段的 HCL 描述（选录）:

```hcl
int dstE = [
    icode in { IRRMOVQ, IOPQ }   : rB;
    icode == IPUSHQ              : RSP;   # pushq 要更新栈指针
    icode == ICMOVXX && Cnd      : rB;    # 条件传送: 条件成立才写
    1                            : RNONE; # 0xF 表示不写任何寄存器
];
```

`Cnd`（来自条件判断逻辑的信号）驱动 cmovXX 与 jXX 共享判断电路。

## 4.4 流水线的通用原理

### 4.4.1 计算流水线

洗衣店类比:分批交错执行（洗衣→烘干→叠衣）各阶段,总吞吐量提升。**流水线通过重叠连续任务的阶段提高吞吐率,单任务延迟不变**。

- 未流水线:完成 3 个任务需 3 × 完整时间;
- 流水线:稳态下**每周期完成一个任务**（各阶段并行处理不同任务）。

### 4.4.2 流水线操作的详细说明

设各阶段耗时均匀为 1 拍:n 个任务的流水线总时间 = $(k + n - 1)$ 拍（k 为级数）。吞吐率提升接近 k 倍;若各阶段不均匀,时钟周期取决于**最慢阶段**。

### 4.4.3 流水线的局限性

- **不一致的划分**:慢阶段拖累整体时钟频率;
- **流水线寄存器开销**:寄存器自身有延迟,级数过多反而降低收益（深度与频率的权衡）。

### 4.4.4 带反馈的流水线

相邻指令存在**数据依赖**（后指令用前指令结果）与**控制依赖**（跳转改变后续指令流向）时,直接流水会出错——引出 4.5 的**冒险（hazard）** 与应对（暂停/转发/预测）。

## 4.5 Y86-64 的流水线实现

### 4.5.1 插入流水线寄存器

PIPE 处理器在六阶段间插入 5 组流水线寄存器（F/D/E/M/W）,每组保存下游阶段所需的所有信号（icode、valC、valA、valP、Cnd 等）:

```mermaid
graph LR
    F[取指 F] --> D_reg[D 流水线寄存器]
    D_reg --> D[译码 D] --> E_reg[E 流水线寄存器]
    E_reg --> E[执行 E] --> M_reg[M 流水线寄存器]
    M_reg --> M[访存 M] --> W_reg[W 流水线寄存器]
    W_reg --> W[写回 W]
```

### 4.5.2 对信号进行重新排列和标号

- **寄存器 ID 与 valP 前移**:call 的返回地址 valP 需要在跳转发生前保持,故把 valP 顺延传递（选择"预测的 PC"提前一拍用）。
- 信号带阶段前缀标注来源（D_valP、E_valC 等）。

### 4.5.3 预测下一个 PC

取指阶段必须**在跳转结果出来之前**决定下一条指令:预测（总预测跳转/总不跳）。Y86-64 PIPE 默认**预测不跳转**,即选择 valP。**预测错误（mispredicted branch）** 的代价:已进入流水线的两条错误路径指令必须**冲刷（flush）**——用气泡（bubble）替换。

### 4.5.4 冒险

- **数据冒险（data hazard）**:后指令需要前指令尚未写回的结果（寄存器/内存/PC）。
- **控制冒险（control hazard）**:跳转方向未定,取指无法确定。

### 4.5.5 用暂停来避免数据冒险

**暂停（stalling）**:在译码阶段发现依赖,插入**气泡（bubble）**——动态插入 nop,让生产者指令先走。对**加载/使用冒险（load/use hazard）**（mrmovq 之后紧跟用其结果的指令）,暂停是必须的——内存数据在访存阶段才可用,无法提前转发。

### 4.5.6 用转发来避免数据冒险

**转发/旁路（forwarding/bypassing）**:不必等写回,把 **E/I 阶段刚算出的 valE** 或 **M 阶段的 valM** 直接回送到译码阶段的输入多路复用器:

- 源点:ALU 输出（E_valE）、访存结果（M_valM）、前一条的 ALU 结果（M_valE）。
- 转发优先级选择最近的值（SEL_FWD 逻辑）。
- PIPE 中大部分数据冒险被转发解决,唯一剩下的是 **load/use 冒险 → 一拍暂停 + 转发**。

### 4.5.7 执行阶段

执行阶段整合 ALU、条件码逻辑、转发源输出;cond 用条件码组合电路判断跳转/传送是否成立。

### 4.5.8 避免控制冒险

- 跳转预测错误时,在**访存阶段**发现 Cnd 与预测不符,向 D、E 注入气泡冲刷错误指令。
- ret 指令无法预测返回地址:必须在访存段读栈,故 **ret 至少暂停 2~3 拍**（气泡填充）。真实处理器用**返回地址缓冲区（return address stack）** 预测 ret。

## 4.6 小结

- 指令集（ISA）是对处理器硬件的抽象;Y86-64 演示了"指令 → 六阶段数据通路 → 时序电路"的完整路径。
- 顺序实现 SEQ 说明"一条指令一拍"的原理;流水线 PIPE 说明吞吐量提升的关键:重叠执行 + 流水线寄存器。
- 冒险是流水线的本质矛盾:数据冒险用**转发**与**暂停**消除,控制冒险用**预测 + 冲刷**降低代价。这些机制在现代乱序处理器中以更复杂的形式存在,但原理同源。
