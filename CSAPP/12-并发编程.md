## 12.1 基于进程的并发编程

### 12.1.1 基于进程的并发服务器

服务器为每个客户端 fork 一个子进程处理:

```c
while (1) {
    connfd = accept(listenfd, ...);
    if (fork() == 0) {                 /* 子进程处理连接 */
        close(listenfd);               /* 子进程关闭监听描述符 */
        echo(connfd);
        close(connfd);
        exit(0);
    }
    close(connfd);                     /* 父进程关闭连接描述符, 继续监听 */
}
```

**必须双重 close**:描述符在父子进程中都指向文件表项,只有两边都关闭才释放（引用计数）。

### 12.1.2 进程的优缺点

| 特性 | 基于进程 |
| --- | --- |
| 优点 | 地址空间隔离,一个进程崩溃不殃及其他;模型清晰 |
| 缺点 | 进程间共享信息难（必须 IPC,Interprocess Communication:管道、消息队列、共享内存、信号、套接字、文件）;进程开销大（虚拟内存复制 + 上下文切换慢） |

## 12.2 基于 I/O 多路复用的并发编程

### 12.2.1 基于 I/O 多路复用的并发事件驱动服务器

**I/O 多路复用（I/O multiplexing）**:用一个进程显式地同时监听多个 fd:

```c
#include <sys/select.h>

fd_set read_set, ready_set;
FD_ZERO(&read_set);
FD_SET(listenfd, &read_set);
FD_SET(STDIN_FILENO, &read_set);

while (1) {
    ready_set = read_set;
    select(listenfd + 1, &ready_set, NULL, NULL, NULL);  /* 阻塞等待任一 fd 就绪 */
    if (FD_ISSET(STDIN_FILENO, &ready_set))
        /* 处理标准输入(如命令行) */
    if (FD_ISSET(listenfd, &ready_set)) {
        connfd = accept(listenfd, ...);   /* 新连接 */
        /* 加入监听集合, 或直接 echo */
    }
}
```

### 12.2.2 I/O 多路复用的优缺点

- **事件驱动（event-driven）**:select/poll/epoll 把"逻辑流显式建模为状态机";epoll 是 Linux 高性能标配（避免 select 的 O（n） 扫描）。
- 优点:**单进程（无进程/线程控制开销）、并发流共享全部数据、对"定时/同时等待多事件"自然支持**;
- 缺点:**编码复杂**（状态机化,回调地狱）、无法利用多核（单线程）。

## 12.3 基于线程的并发编程

### 12.3.1 线程执行模型

**线程（thread）**:运行在进程上下文中的逻辑流,同进程的线程共享:代码、数据、堆、共享库、打开的文件;**各自私有**:栈、栈指针、PC、寄存器、errno。线程 = "进程内的进程"。

- 每线程有唯一 **TID（Thread ID,线程 ID）**;
- **对等线程（peer thread）**:同进程线程无父子层级,一个线程可杀任意对等线程。

### 12.3.2 Posix 线程

**Pthreads（POSIX Threads,POSIX 即 Portable Operating System Interface）**:`pthread_create/pthread_exit/pthread_join/pthread_cancel/pthread_detach/pthread_self`,编译加 `-pthread`。

### 12.3.3 创建线程

```c
typedef void *(thread_func)(void *);

pthread_t tid;
pthread_create(&tid, NULL, thread, (void *)arg);
/* thread(void *arg) 返回 void * */
```

### 12.3.4 终止线程

- 顶层例程返回（隐式 pthread_exit）;
- pthread_exit 显式退出;主线程 return/exit 结束**整个进程**（所有线程）;
- 别的对等线程 pthread_cancel。

### 12.3.5 回收已终止线程的资源

```c
void *retval;
pthread_join(tid, &retval);   /* 阻塞等待 tid 结束, 收取返回值 */
```

（与 waitpid 类似,但必须 join 指定线程。）

### 12.3.6 分离线程

任何时刻线程是**可结合的（joinable）**或**分离的（detached）**:

```c
pthread_detach(pthread_self());   /* 自我分离: 结束后自动回收, 不需 join */
```

### 12.3.7 初始化线程

```c
pthread_once_t once = PTHREAD_ONCE_INIT;
pthread_once(&once, init_routine);   /* 全进程只执行一次(如首个线程初始化) */
```

### 12.3.8 一个基于线程的并发服务器

```c
void *thread(void *vargp);            /* 线程例程 */

while (1) {
    int *connfdp = malloc(sizeof(int));
    *connfdp = accept(listenfd, ...);
    pthread_create(&tid, NULL, thread, connfdp);   /* 每连接一线程 */
}

void *thread(void *vargp) {
    int connfd = *((int *)vargp);
    pthread_detach(pthread_self());   /* 分离: 自动回收 */
    free(vargp);                      /* 释放堆上的 connfd 副本(避免竞争) */
    echo(connfd);
    close(connfd);
    return NULL;
}
```

**传参必须 malloc 复制**:直接传 &connfd 会与主线程的下一轮赋值**竞争**（经典 bug）。

## 12.4 多线程程序中的共享变量

### 12.4.1 线程内存模型

- 共享:全局变量、堆数据（静态分配与动态分配的）;
- 私有:自动（局部）变量——但在栈帧中,**寄存器缓存/编译器优化可能推迟写回**,读写交叉导致旧值。

### 12.4.2 将变量映射到内存

分析示例（cnt++）:

- 全局 `cnt`:一份实例,所有线程共享;
- 局部 `i`（寄存器）、局部 `myid`（各自栈）:每线程私有。

### 12.4.3 共享变量

**共享变量**:被多于一个线程引用,且至少一个引用是写 → 计数器 `cnt++` 是**竞态（race）**:load/inc/store 三步交错时丢失更新。

## 12.5 用信号量同步线程

### 12.5.1 进度图

把 n 个线程的指令流画成 n 维**进度图（progress graph）**,每条轴是一个线程的进度:

- **安全状态/不安全状态**:不安全 ≠错误,但不安全状态**可能**演进到错误结果（如 cnt 丢失更新）;
- **临界区（critical section）**:更新共享变量的指令段;
- 目标:**互斥（mutual exclusion）**——任一时刻只有一个线程在临界区。

### 12.5.2 信号量

**信号量（semaphore）** s 是非负整数,仅两种原子操作:

```c
#include <semaphore.h>

sem_t s;
sem_init(&s, 0, 1);      /* 0 表示线程间共享, 1 为初值 */

sem_wait(&s);            /* P(s): s-- ; s为0则阻塞 (原子) */
sem_post(&s);            /* V(s): s++ ; 唤醒等待者 (原子) */
```

信号量不变式:**s ≥ 0 永远成立**（P 在 s=0 时阻塞保证）。

### 12.5.3 使用信号量来实现互斥

**二元信号量（mutex,互斥锁）**:

```c
sem_t mutex;
sem_init(&mutex, 0, 1);

void *count_thread(void *arg) {
    for (int i = 0; i < niters; i++) {
        sem_wait(&mutex);       /* 进入临界区(锁) */
        cnt++;                  /* 临界区 */
        sem_post(&mutex);       /* 离开(解锁) */
    }
    return NULL;
}
```

### 12.5.4 利用信号量来调度共享资源

信号量不仅是锁,还是**调度资源**的计数器:

- **生产者-消费者（bounded buffer）**:

```c
sem_t mutex, slots, items;       /* 互斥 空槽 有货 */

void insert(item) {
    sem_wait(&slots);            /* 等空槽(P) */
    sem_wait(&mutex);
    buffer_put(item);
    sem_post(&mutex);
    sem_post(&items);            /* 广播有货(V) */
}

item remove_item() {
    sem_wait(&items);            /* 等有货(P) */
    sem_wait(&mutex);
    item = buffer_get();
    sem_post(&mutex);
    sem_post(&slots);            /* 释放空槽(V) */
    return item;
}
```

**必须先 P 资源信号量再 P mutex**（顺序反了会死锁）。

- **读者-写者**:

  - 写者:独占整个对象;
  - 读者:可并发,只要没有写者;
  - 第一名读者用 mutex 保护计数后锁 w（挡写者）,最后一名读者解锁 w;
  - 饥饿问题:读者流不断时写者可能永远等待。

### 12.5.5 综合:基于预线程化的并发服务器

**预线程化（prethreading）**:固定线程池 + 缓冲区（生产者-消费者）——主线程 accept 后把 connfd 插入缓冲区,worker 线程取出处理:

```c
#define NTHREADS 8
sbuf_t sbuf;                       /* 有界缓冲区(带 mutex/slots/items) */

sbuf_init(&sbuf, SBUFSIZE);
for (i = 0; i < NTHREADS; i++)     /* 预先创建线程池 */
    pthread_create(&tid, NULL, worker, NULL);

while (1) {
    connfd = accept(listenfd, ...);
    sbuf_insert(&sbuf, connfd);    /* 主线程生产 */
}

void *worker(void *arg) {
    while (1) {
        int connfd = sbuf_remove(&sbuf);   /* worker 消费 */
        echo(connfd);
        close(connfd);
    }
}
```

## 12.6 使用线程提高并行性

多核上真正的**并行（parallelism）**（区别于并发的时间片多路复用）:加速比衡量:

$$S_p = \frac{T_1}{T_p}, \quad \text{其中 } T_p \text{ 是 } p \text{ 核上的运行时间}$$

- **强扩展（strong scaling）**:固定总工作量,核数增加的加速比;
- 理想上限受**串行部分限制**（Amdahl 定律,见第 1 章）;
- 原书示例:多线程快速排序,各线程独立子任务,加速比在核数较小时近线性,受内存带宽与调度限制后饱和。

## 12.7 其他并发问题

### 12.7.1 线程安全

**线程安全函数**:被多个并发线程反复调用时始终产生正确结果。四类（典型）**不安全**:

1. 未保护共享变量的函数（全局计数器++）;
2. 跨调用保持状态的函数（如strtok 的静态指针）;
3. 返回静态变量指针的函数（ctime、gethostbyname、localtime）;
4. 调用不安全函数的函数。

**改造**:**可重入化**（去掉静态状态、调用者传缓冲）或**加锁包装**（给 ctime 包一层 P/V 的 Ctime_threadsafe,但损失并行性）。

### 12.7.2 可重入性

**可重入（reentrant）** 函数:不带任何共享状态、参数全由调用者给的函数——是**线程安全的充分条件**但非必要。显式可重入（所有数据由调用者传）、隐式可重入（只访问局部栈数据）。

### 12.7.3 竞争

**竞争（race）**:一个线程的正确性取决于"另一线程到达某点的顺序"——坏在"多数时候没事,偶发出错,极难复现"。12.3.8 的 connfd 传参就是典型,修复方法:malloc 复制。

### 12.7.4 死锁

**死锁（deadlock）**:一组线程互相等待对方持有的资源,永久阻塞。信号量不当使用（反向获取）导致:

```c
/* 线程1: P(a); P(b);   线程2: P(b); P(a);  → 可能互等 */
```

预防:**所有线程按统一顺序申请锁**（信号量有序图/acquisition history 无环）;或用定时尝试 + 回退。

## 12.8 小结

- 三种并发构造对比:进程（隔离强、开销大）、I/O 多路复用（事件驱动、单核）、线程（共享方便、需同步）;
- 共享变量 + 竞态是线程的核心矛盾,P/V 信号量提供互斥与调度两类原语;
- 预线程化线程池是服务器标配;线程安全/可重入是库设计要求;死锁靠加锁顺序预防。
