### 条目 1：考虑用静态工厂方法代替构造器

```java
public static Boolean valueOf(boolean b) {
    return b ? Boolean.TRUE : Boolean.FALSE;
}
```

优势：

- **有名称**：`BigInteger.probablePrime()` 比 `new BigInteger(...)` 更能表达语义；
- **不必每次都创建新对象**：可以返回缓存实例（见条目 6）；
- **可以返回原返回类型的任何子类型**：`java.util.Collections`、`EnumSet` 根据底层枚举大小返回 `RegularEnumSet` 或 `MiniEnumSet`，调用方无感知；
- **返回的对象可以随每次调用而变化**（取决于参数和环境）；
- **方法返回的对象所属的类，在编写该静态工厂方法的类时可以不存在**：服务提供者框架（JDBC）的基础，`Provider`/`ServiceLoader`。

缺点：

- **没有公共构造器，类难以被子类化**（想被子类化就用构造器，如集合抽象类）；
- **程序员不容易发现**：构造器在 API 清单里显眼，静态工厂要靠命名约定识别——`valueOf/of/getInstance/newType/getType` 等。

### 条目 2：多参数时考虑使用 Builder 模式

```java
public class NutritionFacts {
    private final int servingSize;
    private final int servings;
    private final int calories;
    private final int fat;
    private final int sodium;
    private final int carbohydrate;

    public static class Builder {
        // Required parameters
        private final int servingSize;
        private final int servings;
        // Optional parameters - initialized to default values
        private int calories = 0;
        private int fat = 0;
        private int sodium = 0;
        private int carbohydrate = 0;
        public Builder(int servingSize, int servings) {
            this.servingSize = servingSize;
            this.servings = servings;
        }
        public Builder calories(int val){
            calories = val; return this;
        }
        public Builder fat(int val){
            fat = val; return this;
        }
        public Builder sodium(int val){
            sodium = val; return this;
        }
        public Builder carbohydrate(int val){
            carbohydrate = val; return this;
        }
        public NutritionFacts build() {
            return new NutritionFacts(this);
        }
    }
    private NutritionFacts(Builder builder) {
        servingSize = builder.servingSize;
        servings = builder.servings;
        calories = builder.calories;
        fat = builder.fat;
        sodium = builder.sodium;
        carbohydrate = builder.carbohydrate;
    }
}
```

使用

```java
NutritionFacts cocaCola = new NutritionFacts.Builder(240,8)
                        .calories(100)
                        .sodium(35)
                        .carbohydrate(27)
                        .build();
```

重叠构造器模式（telescoping constructor）参数多时难以阅读、易传错位；JavaBeans 模式（set 一堆）允许不一致状态且不可变类做不到。Builder 兼具可读性与安全性，还能带校验（build 里检查不变式，参数非法抛 IllegalStateException）。

抽象层级 Builder

```java
public abstract class Pizza {
    public enum Topping {
        HAM, MUSHROOM, ONION, PEPPER,SAUSAGE
    }
    final Set<Topping> toppings;
    abstract static class Builder<T extends Builder<T>> {
        EnumSet<Topping> toppings =
        EnumSet.noneOf(Topping.class);
        public T addTopping(Topping topping) {
            toppings.add(Objects.requireNonNull(topping));
            return self();
        }
        abstract Pizza build();
        // Subclasses must override this method to return "this"
        protected abstract T self();
    }
    Pizza(Builder<?> builder) {
        toppings = builder.toppings.clone(); // See Item 50
    }
}

public class NyPizza extends Pizza {
    public enum Size {
        SMALL, MEDIUM, LARGE
    }
    private final Size size;

    public static class Builder extends Pizza.Builder<Builder> {
        private final Size size;
        public Builder(Size size) {
            this.size = Objects.requireNonNull(size);
        }
        @Override
        public NyPizza build() {
            return new NyPizza(this);
        }
        @Override
        protected Builder self() {
            return this;
        }
    }

    private NyPizza(Builder builder) {
        super(builder);
        size = builder.size;
    }
}
```

递归类型参数 `Builder<T extends Builder<T>>` 配合抽象 `self()` 让子类 Builder 的链式调用返回正确的类型。Builder 还适合层次结构的类。

### 条目 3：用私有构造器或枚举类型强化 Singleton 属性

```java
public class Elvis {
    public static final Elvis INSTANCE = new Elvis();
    private Elvis() { ... }
    public void leaveTheBuilding() { ... }
}
```

静态单例工厂

```java
public class Elvis {
    private static final Elvis INSTANCE = new Elvis();
    private Elvis() { ... }
    public static Elvis getInstance() {
        return INSTANCE;
    }
    public void leaveTheBuilding() { ... }
}
```

两种方式的隐患：特权客户端可以通过反射访问私有构造器（`AccessibleObject.setAccessible`），构造器中加"第二次实例化抛异常"防御；序列化也会破坏单例（见条目 89）。

**第三种方式（最佳）：声明一个包含单个元素的枚举**

```java
public enum Elvis {
    INSTANCE;
    public void leaveTheBuilding() { ... }
}
```

无偿提供序列化机制，并绝对防止多次实例化——即使面对反射或序列化攻击。**单元素的枚举类型经常是实现 singleton 的最佳方法**（单例需要继承超类除外）。

### 条目 4：通过私有构造器强化不可实例化的能力

工具类（`java.util.Arrays`、`Collections`）不希望被实例化，但缺省构造器会让使用者误以为可以 new：

```java
public class UtilityClass {
    // Suppress default constructor for noninstantiability
    private UtilityClass() {
        throw new AssertionError();
    }
    ... // 工具方法
}
```

副作用：这个类也不能被子类化（子类构造器需要调超类构造器）。

### 条目 5：优先考虑依赖注入来引用资源

```java
public class SpellChecker {
    private final Lexicon dictionary;
    public SpellChecker(Lexicon dictionary) {
        this.dictionary = Objects.requireNonNull(dictionary);
    }
    public boolean isValid(String word) { ... }
    public List<String> suggestions(String typo) { ... }
}
```

类如果依赖底层资源（这里是字典），不要用静态工具类或单例硬编码进去（静态 `Lexicon` 无法换中/英文字典）。把资源作为参数传入构造器——即依赖注入。可变资源多时可用 `Supplier<T>` 注入资源工厂，`Mosaic create(Supplier<? extends Tile> tileFactory)`。

### 条目 6：避免创建不必要的对象

方法2能保证，在同一个虚拟机中，只创建一个对象实例，相同的字符串字面常量，该对象就会被复用。1则会重复创建。

```java
String s = new String("bikini");  // 不要这样
String s = "bikini";              // 这样
```

如果同时提供了构造器和静态工厂方法时，优先使用*静态工厂*方法来避免创建不必要的对象，如使用工厂方法`Boolean.valueOf(String)`，而不是`Boolean(String)`。

`String.matches`方法内部创建了一个Pattern实例来用于正则表达式，这个实例只使用一次，使用完之后它就被垃圾回收了。创建一个Pattern实例是昂贵的，因为它需要将正则表达式编译成一个有限状态机(finite state machine)。

```java
static boolean isRomanNumeral(String s) {
    return s.matches("^(?=.)M*(C[MD]|D?C{0,3})" + "(X[CL]|L?X{0,3})(I[XV]|V?I{0,3})$");
}
```

优化为

```java
public class RomanNumerals {
    private static final Pattern ROMAN = Pattern.compile("^(?=.)M*(C[MD]|D?C{0,3})"
                + "(X[CL]|L?X{0,3})(I[XV]|V?I{0,3})$");
    static boolean isRomanNumeral(String s) {
        return ROMAN.matcher(s).matches();
    }
}
```

优先使用基本类型而不是装箱基本类型，避免频繁创建对象：

```java
// 隐蔽的自动装箱导致的性能问题：sum 声明为 Long 而不是 long
private static long sum() {
    Long sum = 0L;
    for (long i = 0; i <= Integer.MAX_VALUE; i++)
        sum += i;    // 每次 += 都会拆箱再装箱
    return sum;
}
```

对象池要尽量避免（现代 JVM 小对象创建回收廉价），只有真正重量级的对象（如数据库连接）才值得池化。

注意与条目 50 的对立面：该复用的时候复用（本条），该新建保护性拷贝的时候必须新建——保护性拷贝带来的代价远小于必要的防御。

但对于构造器做很少工作的小对象的创建和回收是很廉价的，特别是在现代的JVM实现上，通过创建额外的对象能加强代码的清晰度。

### 条目 7：清除过期的对象引用

栈的实现中隐藏的内存泄漏（弹出的元素不会被 GC，因为过期引用 obsolete reference 仍然存在）：

```java
public class Stack {
    private Object[] elements;
    private int size = 0;

    public Object pop() {
        if (size == 0)
            throw new EmptyStackException();
        Object result = elements[--size];
        elements[size] = null; // Eliminate obsolete reference，清掉过期引用
        return result;
    }
}
```

清空引用应该是例外而非常规：局部变量出了作用域自动失效。**只要类自己管理内存，就应该警惕内存泄漏**。其他来源：

- **缓存**：容易被遗忘的条目——用 `WeakHashMap`（键外部无引用时自动回收）、`LinkedHashMap.removeEldestEntry` 或 `java.util.concurrent`（如 `ConcurrentLinkedHashMap`）；
- **监听器和回调**：注册后忘了注销——只存弱引用（存为 `WeakHashMap` 的键）。

内存泄漏不会立刻报错，可能潜伏多年，Heap profiler（如 MAT）是排查工具。

### 条目 8：避免使用终结方法和清除方法

`finalizer`（终结方法）和 Java 8 的 `cleaner`（清除方法）的缺点：

- **不能保证及时执行**：从对象不可达到执行终结方法之间的时间是任意长的，用它释放资源是错误的选择（不保证何时甚至是否执行）；
- **异常被吞**：终结方法中抛出的异常会被忽略且不会打印，可能让对象处于损坏状态；
- **性能糟糕**：创建/销毁 finalizable 对象慢几十倍（cleaner 稍好但仍慢）。

正确的做法：实现 `AutoCloseable`，需要终止时用 `try-with-resources` 调 `close()`（见条目 9）。

两个合法用途（安全网/后兜底）：

- 兜底：担心资源所有者忘了 close——如 `FileInputStream` 的 finalizer，迟释放好过不释放（要记录日志说明）；
- native peer（通过本地方法持有的非 Java 资源）不适合 close 时。

注意子类覆写 finalize 时必须显式 `super.finalize()`，且要用 try-finally 保证执行；清洁器相对安全的用法是内部静态 Cleaning 嵌套类（AutoCleanable）持有资源，外部对象死亡时触发。

### 条目 9：try-with-resources 优先于 try-finally

```java
// try-finally：关闭第二个资源会掩盖第一个异常
static void copy(String src, String dst) throws IOException {
    InputStream in = new FileInputStream(src);
    try {
        OutputStream out = new FileOutputStream(dst);
        try {
            byte[] buf = new byte[100];
            int n;
            while ((n = in.read(buf)) >= 0)
                out.write(buf, 0, n);
        } finally {
            out.close();
        }
    } finally {
        in.close();
    }
}
```

```java
// try-with-resources：资源必须实现 AutoCloseable
static void copy(String src, String dst) throws IOException {
    try (InputStream in = new FileInputStream(src);
         OutputStream out = new FileOutputStream(dst)) {
        byte[] buf = new byte[100];
        int n;
        while ((n = in.read(buf)) >= 0)
            out.write(buf, 0, n);
    }
}
```

try-with-resources 的优点：可读性好；多个资源时后声明的先关闭；close 抛出的异常不会被业务异常掩盖——被抑制（suppressed）的异常可以通过 `getSuppressed()` 取回。**处理必须关闭的资源时，永远优先 try-with-resources。**
