
### 条目 10：覆盖 equals 时请遵守通用约定

覆写 equals 的时机：当类有自己的逻辑相等（logical equality）规则。值类（Integer/String）通常需要；每个实例都是唯一实体的类（Thread）不需要；枚举不需要（逻辑相等即同一性）。

覆写 equals 遵循的约定：

- 自反性（reflexive）：对于任意非空引用值 x，x.equals(x) 必须返回 true。
- 对称性（symmetric）：对于任意非空引用值 x 和 y，x.equals(y) 必须返回 true，当且仅当 y.equals(x) 返回 true。
- 传递性（transitive）：对于任意非空引用值 x、y、z，如果 x.equals(y) 返回 true 而且 y.equals(z) 也返回 true，那么 x.equals(z) 必须返回 true。
- 一致性（consistent）：对于任意非空引用值 x 和 y，只要 equals 方法中使用的信息没有被修改，那么不管多少次调用 x.equals(y) 都必须一致性地返回 true 或者 false。
- 非空性（non-null）：对于任意非空引用值 x，x.equals(null) 必须返回 false。

#### 对称性

```java
public final class CaseInsensitiveString {
    private final String s;
    public CaseInsensitiveString(String s) {
        this.s = Objects.requireNonNull(s);
    }
    // Broken - violates symmetry!
    @Override
    public boolean equals(Object o) {
        if (o instanceof CaseInsensitiveString)
            return s.equalsIgnoreCase(((CaseInsensitiveString) o).s);
        if (o instanceof String) // One-way interoperability!
            return s.equalsIgnoreCase((String) o);
        return false;
    }
}
```

上述代码，违反了对称性，`cis.equals(s)`返回了true，`s.equals(cis)`返回false

```java
CaseInsensitiveString cis = new CaseInsensitiveString("Polish");
String s = "polish";

List<CaseInsensitiveString> list = new ArrayList<>();
list.add(cis);
```

一旦违反了equals约定，将不知道别的对象在面对你的对象时会产生什么行为，将一个大小写不敏感的字符串放入一个集合里，不能确定会返回什么结果。

修改为：

```java
@Override
public boolean equals(Object o) {
    return o instanceof CaseInsensitiveString && ((CaseInsensitiveString) o).s.equalsIgnoreCase(s);
}
```

#### 传递性

```java
public class Point {
    private final int x;
    private final int y;
    public Point(int x, int y) {
        this.x = x;
        this.y = y;
    }
    @Override
    public boolean equals(Object o) {
        if (!(o instanceof Point))
            return false;
        Point p = (Point)o;
        return p.x == x && p.y == y;
    }
}

public class ColorPoint extends Point {
    private final Color color;
    public ColorPoint(int x, int y, Color color) {
        super(x, y);
        this.color = color;
    }

    // Broken - violates symmetry!
    @Override
    public boolean equals(Object o) {
      if (!(o instanceof ColorPoint))
          return false;
      return super.equals(o) && ((ColorPoint) o).color == color;
    }
}
```

p.equals(cp)返回true，而cp.equals(p)却返回false

```java
Point p = new Point(1, 2);
ColorPoint cp = new ColorPoint(1, 2, Color.RED);
```

下面的方式虽然保证了对称性，但却牺牲了传递性，p1.equals(p2)和p2.equals(p3)都返回了true，但p1.equals(p3)却返回了false：

```java
// Broken - violates transitivity!
@Override
public boolean equals(Object o) {
    if (!(o instanceof Point))
        return false;
    // If o is a normal Point, do a color-blind comparison
    if (!(o instanceof ColorPoint))
        return o.equals(this);
    // o is a ColorPoint; do a full comparison
    return super.equals(o) && ((ColorPoint) o).color == color;
}

ColorPoint p1 = new ColorPoint(1, 2, Color.RED);
Point p2 = new Point(1, 2);
ColorPoint p3 = new ColorPoint(1, 2, Color.BLUE);
```

这是面向对象语言中关于等价关系的一个基本问题。我们无法在扩展一个类的同时，既增加一个值组件，又要保留equals约定，除非我们放弃面向对象的抽象带来的好处。**There is no way to extend an instantiable class and add a value component while preserving the equals contract**, unless you're willing to forgo the benefits of object-oriented abstraction.

改用 getClass 测试替代 instanceof 看似可行，但会让子类实例不再等于超类实例（如 CounterPoint 无法匹配 Point），同时也违反了里氏替换原则（Liskov substitution principle）：

```java
// Broken - violates Liskov substitution principle
@Override
public boolean equals(Object o) {
    if (o == null || o.getClass() != getClass())
        return false;
    Point p = (Point) o;
    return p.x == x && p.y == y;
}
```

```java
// Initialize unitCircle to contain all Points on the unit circle
private static final Set<Point> unitCircle = Set.of(
        new Point( 1, 0), new Point( 0, 1),
        new Point(-1, 0), new Point( 0, -1));
public static boolean onUnitCircle(Point p) {
    return unitCircle.contains(p);
}
```

```java
public class CounterPoint extends Point {
    private static final AtomicInteger counter = new AtomicInteger();
    public CounterPoint(int x, int y) {
        super(x, y);
        counter.incrementAndGet();
    }
    public static int numberCreated() {
        return counter.get();
    }
}
```

解决思路：**用组合代替继承**——不扩展 Point，而是持有一个 Point：

```java
// Adds a value component without violating the equals contract
public class ColorPoint {
    private final Point point;
    private final Color color;
    public ColorPoint(int x, int y, Color color) {
        point = new Point(x, y);
        this.color = Objects.requireNonNull(color);
    }
    // Returns the point-view of this color point.
    public Point asPoint() {
        return point;
    }
    @Override public boolean equals(Object o) {
        if (!(o instanceof ColorPoint))
            return false;
        ColorPoint cp = (ColorPoint) o;
        return cp.point.equals(point) && cp.color.equals(color);
    }
    // Remainder omitted
}
```

也可以在抽象类中扩展（抽象类不能实例化，无上述矛盾），或直接让 ColorPoint 不参与 equals 继承体系。

#### 实现 equals 的高质量配方

```java
@Override
public boolean equals(Object o) {
    if (o == this)                     // 1. 用 == 优化：是否就是本对象
        return true;
    if (!(o instanceof PhoneNumber))   // 2. instanceof 判断类型（同时排除 null）
        return false;
    PhoneNumber pn = (PhoneNumber) o;  // 3. 转换（可结合模式匹配）
    return pn.lineNum == lineNum       // 4. 逐字段比较
        && pn.prefix == prefix
        && pn.areaCode == areaCode;
}
```

字段比较规则：基本类型用 `==`；float/double 用 `Float.compare`/`Double.compare`（处理 NaN 和 -0.0）；引用类型递归 `equals`；数组用 `Arrays.equals` 或逐元素。写完用单元测试验证（Guava 的 EqualsTester）。

### 条目 11：覆盖 equals 时总要覆盖 hashCode

约定：**相等的对象必须具有相等的散列码**。违反后果：HashMap/HashSet 中找不到"相等"的对象。

```java
// 只覆写了 equals 的 PhoneNumber，放进 HashMap 后取不出来
Map<PhoneNumber, String> m = new HashMap<>();
m.put(new PhoneNumber(707, 867, 5309), "Jenny");
m.get(new PhoneNumber(707, 867, 5309)) // → null！
```

好的散列函数（书中 PhoneNumber 的 31 累乘法）：

```java
@Override
public int hashCode() {
    int result = Short.hashCode(areaCode);
    result = 31 * result + Short.hashCode(prefix);
    result = 31 * result + Short.hashCode(lineNum);
    return result;
}
```

简洁但性能稍差的 `Objects.hash(areaCode, prefix, lineNum)`（有装箱和数组创建开销）。不可变类且散列开销大时可以缓存（延迟计算 + 缓存字段，注意线程安全）。不要试图从散列码中排除关键字段来提速——散列质量差导致散列表退化成链表（DoS 攻击面）。

### 条目 12：始终要覆盖 toString

Object 的默认实现是 `ClassName@hashCode`，对使用者毫无用处：

```java
System.out.println(phoneNumber);  // PhoneNumber@a5f3c1 → 无法排查问题
```

提供简洁、易读、信息丰富的 toString，异常信息、日志、调试器都会因此受益：

```java
@Override
public String toString() {
    return String.format("%03d-%03d-%04d", areaCode, prefix, lineNum);
}
```

是否在文档中规定格式要做取舍：规定格式（如电话号码）= 方便解析但长期承诺；不规定则保留灵活性。无论是否规定，都要在注释中表明意图。IDE/Lombok/AutoValue 可以自动生成。

### 条目 13：谨慎地覆盖 clone

Cloneable 接口本身是空接口，却改变了 `Object.clone()` 的行为（native 方法检查实现接口与否），属于非典型的接口用法。clone 的约定很弱："创建并返回对象的一个拷贝"。

**不可变类**才适合用 clone（永远不需要防御性拷贝）。**可变的引用字段必须深拷贝**：

```java
// Stack 内部是数组，浅拷贝会让两个栈共享同一数组
@Override
public Stack clone() {
    try {
        Stack result = (Stack) super.clone();
        result.elements = elements.clone();   // 数组深拷贝
        return result;
    } catch (CloneNotSupportedException e) {
        throw new AssertionError();
    }
}
```

注意：clone 的对象不调用构造器；final 字段无法重新赋值导致深拷贝困难。**更好的替代：拷贝构造器或拷贝工厂**——不依赖有风险的机制、能接收接口类型参数、字段 final 友好：

```java
public Yum(Yum yum) { ... }              // 拷贝构造器
public static Yum newInstance(Yum yum) { ... }  // 拷贝工厂
```

### 条目 14：考虑实现 Comparable

compareTo 是唯一没有在 Object 中声明的方法，实现它意味着类的实例具有自然排序，配合有序集合（TreeMap/TreeSet）和排序方法（`Collections.sort`、`Arrays.sort`）使用。

约定与 equals 类似（自反/对称/传递/一致），**强烈建议但不强制与 equals 一致**：不一致时有序集合的行为会"奇怪"（BigDecimal(1.0) 与 BigDecimal(1.00) compareTo 相等但 equals 不等，放进 TreeSet 只留一个，HashSet 留两个）。

```java
public class PhoneNumber implements Comparable<PhoneNumber> {
    @Override
    public int compareTo(PhoneNumber pn) {
        int result = Short.compare(areaCode, pn.areaCode);
        if (result == 0) result = Short.compare(prefix, pn.prefix);
        if (result == 0) result = Short.compare(lineNum, pn.lineNum);
        return result;
    }
}
```

Java 7 起基本类型用静态 `compare`（不用 `<` `-` 减法——减法有整型溢出风险！）。Java 8 起可用 Comparator 构建链（适合多关键字、无侵入）：

```java
static final Comparator<PhoneNumber> ORDER = 
    Comparator.comparingInt((PhoneNumber pn) -> pn.areaCode)
        .thenComparingInt(pn -> pn.prefix)
        .thenComparingInt(pn -> pn.lineNum);
```
