
### 条目 15：使类和成员的可访问性最小化

信息隐藏/封装是软件设计的基本原则：降低耦合、允许独立开发/理解/修改、提高复用性。

- 成员可见性从低到高：private → package-private（缺省）→ protected → public；
- **实例字段永远不要是 public**：公开可变字段放弃线程安全与不变式控制；
- 静态 final 常量可以是 public（约定大写下划线命名），但**非零长度数组总是可变的**——公开它等于公开可变状态：

```java
// 安全漏洞：客户端可以修改数组内容
public static final Thing[] VALUES = new Thing[...];

// 方案1：返回防御性拷贝
private static final Thing[] PRIVATE_VALUES = { ... };
public static final Thing[] values() {
    return PRIVATE_VALUES.clone();
}
// 方案2：返回不可变列表
public static final List<Thing> VALUES = List.of(...);
```

Java 9 的模块系统（module）提供了包级之下的可见性层次，一般不需要为此打乱常规的可见性降级原则。

### 条目 16：要在公共类而非公共字段上使用访问方法

```java
// 低内聚的退化类
class Point {
    public double x;
    public double y;
}

// 面向对象的做法：私有字段 + 访问器
class Point {
    private double x;
    private double y;
    public Point(double x, double y) { this.x = x; this.y = y; }
    public double getX() { return x; }
    public double getY() { return y; }
    public void setX(double x) { this.x = x; }
    public void setY(double y) { this.y = y; }
}
```

公有类暴露字段后无法再改变内部表示、无法加校验、无法在读取时附加动作。**包私有或私有嵌套类直接暴露字段是允许的**（不进 API，利大于弊）。

### 条目 17：使可变性最小化

不可变类的五条规则：不提供修改状态的方法、类不可扩展（final）、所有字段 final、所有字段 private、确保对可变组件的独占访问（构造器/读访问器做防御性拷贝）。

```java
public final class Complex {
    private final double re;
    private final double im;

    public Complex(double re, double im) {
        this.re = re;
        this.im = im;
    }
    public double realPart() { return re; }
    public double imaginaryPart() { return im; }

    // 不是 add(this, that)，而是返回新实例
    public Complex plus(Complex c) {
        return new Complex(re + c.re, im + c.im);
    }
    ...
}
```

优点：**简单、线程安全（可自由共享）、可缓存、便于组合**。缺点：每个值一个对象，大量小对象有性能开销——多步操作可提供配套的可变类（`String` ↔ `StringBuilder`）；不可变类还可以配合静态工厂缓存常用实例（`BigInteger.ZERO`、`Complex.ONE`）。要允许继承又保持不可变，可把构造器声明为私有并放出静态工厂。

### 条目 18：组合优于继承

继承（跨包继承具体类）破坏封装：子类依赖超类的实现细节，超类演进会破坏子类。

```java
// 计数 HashSet：看似正确，实际 addAll 会双重计数（内部调 add）
public class InstrumentedHashSet<E> extends HashSet<E> {
    private int addCount = 0;
    @Override public boolean add(E e) {
        addCount++;
        return super.add(e);
    }
    @Override public boolean addAll(Collection<? extends E> c) {
        addCount += c.size();
        return super.addAll(c);   // 超类内部会回调 add()！
    }
}
```

组合（装饰者模式）+ 转发类：

```java
public class InstrumentedSet<E> extends ForwardingSet<E> {
    private int addCount = 0;
    public InstrumentedSet(Set<E> s) { super(s); }
    @Override public boolean add(E e) { addCount++; return super.add(e); }
    @Override public boolean addAll(Collection<? extends E> c) {
        addCount += c.size();
        return super.addAll(c);
    }
}

// 可复用的转发类
public class ForwardingSet<E> implements Set<E> {
    private final Set<E> s;
    public ForwardingSet(Set<E> s) { this.s = s; }
    public boolean add(E e) { return s.add(e); }
    public boolean addAll(Collection<? extends E> c) { return s.addAll(c); }
    public void clear() { s.clear(); }
    // ... 其余方法一一转发
}
```

组合的 InstrumentedSet 之所以正确：它把自身传入的超类（`HashSet`）当工具用，不依赖其内部实现。只有在确定 "is-a" 关系且超类自用性文档完备时才用继承（见条目 19）。

### 条目 19：要么设计为专门用于继承，要么禁止继承

- 为继承设计的类必须**文档化自用性（self-use）**：每个可覆写方法在何处被调用、调用顺序、结果如何影响后续处理；
- 构造器绝不能调用可被覆写的方法（子类构造器先于字段初始化执行，覆写方法会读到未初始化状态）：

```java
public class Super {
    public Super() {
        overrideMe();  // 危险！子类覆写时，此时子类字段尚未初始化
    }
    public void overrideMe() { }
}

public final class Sub extends Super {
    private final Instant instant;
    Sub() { instant = Instant.now(); }
    @Override public void overrideMe() {
        System.out.println(instant);  // 构造期间调用会打印 null
    }
}
```

- 通过 clone 和 readObject 也不可调用可覆写方法；
- 想禁止继承：声明 final，或把所有构造器私有化（静态工厂代替，见条目 17 的 Complex）。

### 条目 20：接口优于抽象类

- 现有类可以很容易实现接口，却不能继承抽象类（单继承）；
- 接口是**定义混合类型（mixin）**的理想选择：`Comparable`、`AutoCloseable`；
- 接口允许构造非层次结构的类型框架。

结合两者优点：**骨架实现（skeletal implementation）**——接口 + 抽象类 `AbstractInterface` 提供默认骨架：

```java
static List<Integer> intArrayAsList(int[] a) {
    Objects.requireNonNull(a);
    // 匿名的 AbstractList 骨架实现
    return new AbstractList<Integer>() {
        @Override public Integer get(int i) { return a[i]; }
        @Override public int size() { return a.length; }
    };
}
```

Java 8 起接口可以有默认方法，甚至可以在接口中发放骨架实现。经验法则：用接口定义类型（公有 API），骨架实现类帮助实现。

### 条目 21：为后代设计接口（默认方法）

Java 8 的默认方法让现存接口可以加方法，但**不能认为默认方法是万无一失的**：

```java
// Java 8 在 Collection 中加的 removeIf 默认方法
default boolean removeIf(Predicate<? super E> filter) {
    Objects.requireNonNull(filter);
    boolean removed = false;
    ...
}
```

在默认方法发布前已有的实现类若与默认方法的假设冲突（如线程安全假设），会出问题——`Apache Commons` 的某些集合类当时就因此被破坏。教训：**默认方法可以被现有的实现类继承，谨慎设计**；新接口发布前要充分测试。

### 条目 22：接口只用于定义类型

类实现接口时应表达"我能做什么"，而不是用接口暴露常量：

```java
// 反模式：常量接口
public interface PhysicalConstants {
    static final double AVOGADROS_NUMBER = 6.022_140_857e23;
    static final double BOLTZMANN_CONSTANT = 1.380_648_52e-23;
}
```

实现这个接口会让实现类的 API 混入无关常量、形成编译期依赖。正确做法是**不可实例化的工具类 + 静态导入**：

```java
public class PhysicalConstants {
    private PhysicalConstants() { }
    public static final double AVOGADROS_NUMBER = 6.022_140_857e23;
}

import static com.effectivejava.science.PhysicalConstants.AVOGADROS_NUMBER;
```

### 条目 23：类层次优于标签类

标签类：一个类里用字段区分多种风格的实例，冗长、易错、内存开销大：

```java
// 标签类：一个类既表示圆形又表示矩形
class Figure {
    enum Shape { RECTANGLE, CIRCLE };
    final Shape shape;      // 标签字段
    double length; double width;   // 只用于矩形
    double radius;                 // 只用于圆形
    double area() {
        switch (shape) {
            case RECTANGLE: return length * width;
            case CIRCLE: return Math.PI * (radius * radius);
            ...
        }
    }
}
```

改为类层次——每个类型一个类，字段类型化，编译器兜底：

```java
abstract class Figure {
    abstract double area();
}

class Circle extends Figure {
    final double radius;
    Circle(double radius) { this.radius = radius; }
    @Override double area() { return Math.PI * (radius * radius); }
}

class Rectangle extends Figure {
    final double length; final double width;
    Rectangle(double length, double width) { this.length = length; this.width = width; }
    @Override double area() { return length * width; }
}
```

### 条目 24：静态成员类优于非静态成员类

四种嵌套类：

| 类型 | 场景 | 说明 |
| --- | --- | --- |
| 静态成员类 | 辅助类 | 可以访问外部类所有成员 |
| 非静态成员类 | Adapter（视图） | 每个实例持有一个外部实例引用（`Map.keySet` 的实现） |
| 匿名类 | 现场小实现 | Java 8 前用于函数对象，现在被 lambda 取代；不能 instanceof、命名困难 |
| 局部类 | 方法内部 | 任何可以声明局部变量的地方 |

**如果成员类不需要访问外部实例，就声明为静态的**——非静态成员类会隐式持有外部引用（浪费内存 + 可能泄漏，见条目 7）：

```java
// 典型错误：不必要的非静态成员类
public class MyAdapter extends YourAdapter { ... }  // 应加 static

// 匿名类的现代替代
list.sort((a, b) -> Integer.compare(a.x, b.x));    // lambda
list.sort(Comparator.comparingInt(a -> a.x));       // 方法引用风格
```

### 条目 25：将源文件限制为单个顶级类

一个源文件放多个顶级类会导致"重复类定义"随编译顺序而变的问题：

```java
// Utensil.java 和 Dessert.java 中都定义了 Utensil/Dessert 时，
// javac 哪个先编译，哪个就生效——构建结果不确定
```

解决：一个顶级类一个文件。嵌套类不算（它们有自己的外围类命名空间）。
