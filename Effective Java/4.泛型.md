
### 条目 26：不要使用原生态类型

原生态类型（raw type，如 `List`）放弃了泛型的全部安全性和表达性：

```java
private final Collection stamps = ...;
stamps.add(new Coin(...));                    // 编译通过！
Stamp s = (Stamp) stamps.iterator().next();   // 运行时 ClassCastException
```

```java
private final Collection<Stamp> stamps = ...;
stamps.add(new Coin(...));   // 编译错误，错误在源头被发现
```

| 声明 | 含义 |
| --- | --- |
| `List` | 原生态类型，放弃检查——**不要用** |
| `List<Object>` | 任意类型都合法的列表（异构） |
| `List<?>` | 未知类型列表，只读出 Object，不能 add——需要时用 |

两个允许原生态类型的例外：类字面量（`List.class`，不允许 `List<String>.class`）和 `instanceof`（泛型信息运行时被擦除，`o instanceof Set` 合法，`o instanceof Set<?>` 等价但非法写法 `Set<String>` 不允许）。

### 条目 27：消除非受检警告

每一条 unchecked 警告都可能在运行时抛出 ClassCastException，**要尽可能消除**：

```java
Set<Lark> exaltation = new HashSet();       // 警告
Set<Lark> exaltation = new HashSet<>();     // 消除（Java 7 钻石操作符）
```

确实无法消除且能证明类型安全时，用**最小范围**的 `@SuppressWarnings("unchecked")` 并注释原因：

```java
// 局部变量级（不要放在整个方法上，可能掩盖真正的隐患）
@SuppressWarnings("unchecked")
Set<Lark> exaltation = (Set<Lark>) getResult();
```

### 条目 28：列表优于数组

数组是**协变**的（`Object[]` 可以装 String[]），泛型是**不变**的；数组是**运行时**检查（`ArrayStoreException`），泛型是**编译期**检查。两者不兼容：`new List<String>[]` 非法。

```java
Object[] objects = new Long[1];
objects[0] = "I don't fit in.";       // 编译通过，运行时 ArrayStoreException

List<Object> ol = new ArrayList<Long>(); // 编译不通过
ol.add("I don't fit in.");
```

创建泛型数组非法的原因（类型擦除后无法做数组协变检查）：

```java
List<String>[] stringLists = new List<String>[1];  // 假设合法
List<Integer> intList = List.of(42);
Object[] objects = stringLists;
objects[0] = intList;                        // 通过数组协变检查
String s = stringLists[0].get(0);            // ClassCastException，泛型白设了
```

故泛型集合内部用 `Object[]` + 强转实现（见条目 29），牺牲一点也要换来编译期类型安全。

### 条目 29：优先考虑泛型

把基于 Object 的类泛型化：

```java
public class Stack<E> {
    private E[] elements;
    private int size = 0;

    public Stack() {
        // 不能 new E[]，用 (E[]) new Object[]，并抑制警告（证明类型安全）
        elements = (E[]) new Object[16];
    }

    public void push(E e) { elements[size++] = e; }
    public E pop() {
        if (size == 0) throw new EmptyStackException();
        E result = elements[--size];
        elements[size] = null;
        return result;
    }
}
```

第二种做法是字段用 `Object[]`、取值处强转（`E result = (E) elements[--size]`）。客户端不改代码就获得类型安全与复用（`Stack<String>`、`Stack<int[]>`）。类型参数不能是基本类型（`Stack<int>` 非法，用 `Stack<Integer>`，见条目 61）。

### 条目 30：优先考虑泛型方法

```java
// 原始版本：参数和返回值都要强转
public static Set union(Set s1, Set s2) { ... }
// 泛型方法
public static <E> Set<E> union(Set<E> s1, Set<E> s2) {
    Set<E> result = new HashSet<>(s1);
    result.addAll(s2);
    return result;
}
```

递归类型参数表达调用限制（条目 30 的 `max`）：

```java
public static <E extends Comparable<E>> E max(Collection<E> c) { ... }
```

### 条目 31：利用有限制通配符来提升 API 的灵活性

`union(Set<E>, Set<E>)` 无法处理 `Set<Integer>` 和 `Set<Double>`——需要 **PECS**（producer-extends, consumer-super）：

```java
// src 是生产者（只读取）→ ? extends E；dst 是消费者（只写入）→ ? super E
public static <E> void copy(List<? super E> dst, List<? extends E> src) { ... }
```

max 的参数对比较器来说是**消费者**（Comparator/Comparable 总是消费者）：

```java
public static <E extends Comparable<? super E>> E max(List<? extends E> list) { ... }
```

如果类型参数只在方法签名中出现一次，用通配符代替它（`swapHelper` 的自限定技巧处理双向）。记住：**不要用通配符作为返回类型**（强迫客户端处理通配符）。

### 条目 32：谨慎并用泛型和可变参数

varargs 是数组（`Object...` 实为 `Object[]`），泛型数组创建非法但 varargs 是历史漏洞——堆污染（heap pollution）：

```java
// 危险：把 List<String> 当作 Object[] 存储
static void dangerous(List<String>... stringLists) {
    Object[] array = stringLists;
    List<Integer> intList = List.of(42);
    array[0] = intList;               // 堆污染
    String s = stringLists[0].get(0); // ClassCastException
}
```

**安全条件**：不把 varargs 数组存到任何地方、不让信任的代码修改其元素、不暴露可变参数的泛型类型。安全时用 `@SafeVarargs` 标注（Java 7 起只能用于 static/final 方法，Java 9 起可用于私有方法）：

```java
@SafeVarargs
static <T> List<T> flatten(List<? extends T>... lists) { ... }
```

更简单的替代：用 `List<List<T>>` 参数代替 varargs。

### 条目 33：优先考虑类型安全的异构容器

用 `Class<T>` 作为键，一个容器存多种类型：

```java
public class Favorites {
    private Map<Class<?>, Object> favorites = new HashMap<>();

    public <T> void putFavorite(Class<T> type, T instance) {
        favorites.put(Objects.requireNonNull(type), instance);
    }

    // Class<T> 的 cast 是类型安全的动态转换
    public <T> T getFavorite(Class<T> type) {
        return type.cast(favorites.get(type));
    }
}

// 使用：一个容器，多种类型，无强转
Favorites f = new Favorites();
f.putFavorite(String.class, "Java");
f.putFavorite(Integer.class, 0xcafebabe);
String s = f.getFavorite(String.class);
```

Object 作为值之所以安全：put/get 由 Class<T> 保证一一对应。局限：Class 是非具体化的（runtime 泛型擦除，`List<String>.class` 不存在）；可通过超类型令牌（super type token）解决。
