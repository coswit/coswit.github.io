
### 条目 34：用 enum 代替 int 常量

```java
public enum Planet {
    MERCURY(3.302e+23, 2.439e6),
    VENUS  (4.869e+24, 6.052e6),
    EARTH  (5.975e+24, 6.378e6);

    private final double mass;
    private final double radius;
    private final double surfaceGravity;

    // 枚举构造器：每个常量带数据与行为
    Planet(double mass, double radius) {
        this.mass = mass;
        this.radius = radius;
        surfaceGravity = G * mass / (radius * radius);
    }
    public double surfaceWeight(double mass) { return mass * surfaceGravity; }
}
```

枚举的优势：

- 编译期类型安全（int 枚举传错值无从检查）；
- 有命名空间、可以加字段和方法（**特定于常量的方法实现**）：

```java
public enum Operation {
    PLUS  { public double apply(double x, double y) { return x + y; } },
    MINUS { public double apply(double x, double y) { return x - y; } },
    TIMES { public double apply(double x, double y) { return x * y; } },
    DIVIDE{ public double apply(double x, double y) { return x / y; } };

    public abstract double apply(double x, double y);
}
```

- `values()`（按声明顺序遍历）、`valueOf(String)`（常量名转常量）、`toString` 可覆写；
- 枚举是不可变的、单例的（见条目 3），配合 `EnumSet`/`EnumMap`（条目 36/37）高效。

策略枚举（strategy enum）：方法实现复杂时按策略字段分发：

```java
enum PayrollDay {
    MONDAY, TUESDAY, ..., SUNDAY;
    private static final int MELT_SHIFT = 8;  // 简化示例
    // 更好的做法：嵌套枚举策略 + 构造器参数
}
```

### 条目 35：使用实例字段而不是序数

永远不要用 `ordinal()` 做与枚举常量绑定的逻辑（重新排序就坏了）：

```java
// 反例
public enum Ensemble {
    SOLO, DUET, TRIO;
    public int numberOfMusicians() { return ordinal() + 1; }
}

// 正例：显式字段
public enum Ensemble {
    SOLO(1), DUET(2), TRIO(3);
    private final int numberOfMusicians;
    Ensemble(int size) { this.numberOfMusicians = size; }
    public int numberOfMusicians() { return numberOfMusicians; }
}
```

`EnumSet`/`EnumMap` 内部用 ordinal 做位图/数组索引，那是它们封装好的用法。

### 条目 36：用 EnumSet 代替位字段

```java
// 位字段：可读性差、易错
public static final int STYLE_BOLD          = 1 << 0;
public static final int STYLE_ITALIC        = 1 << 1;
public void applyStyles(int styles) { ... }

// EnumSet：清晰的类型，性能与位字段相当（位向量实现）
public enum Style { BOLD, ITALIC, UNDERLINE, STRIKETHROUGH }
public void applyStyles(Set<Style> styles) { ... }

text.applyStyles(EnumSet.of(Style.BOLD, Style.ITALIC));
```

### 条目 37：用 EnumMap 代替序数索引

```java
// 反例：用 ordinal() 做数组下标，到处强转与不安全
Herb[] garden = ...;
Set<Herb>[] plantsByLifeCycle = (Set<Herb>[]) new Set[Herb.Lifecycle.values().length];

// 正例：EnumMap
Map<Herb.Lifecycle, Set<Herb>> plantsByLifeCycle =
        new EnumMap<>(Herb.Lifecycle.class);
for (Herb.Lifecycle lc : Herb.Lifecycle.values())
    plantsByLifeCycle.put(lc, new HashSet<>());
for (Herb h : garden)
    plantsByLifeCycle.get(h.lifeCycle).add(h);
```

Stream 版：`Arrays.stream(garden).collect(groupingBy(h -> h.lifeCycle, () -> new EnumMap<>(...), toSet()))`（不指定 EnumMap 时 groupingBy 用 HashMap）。多维时用 `EnumMap<..., EnumMap<...>>` 而不是嵌套数组。

### 条目 38：用接口模拟可扩展枚举

枚举无法继承另一个枚举，但**接口 + 多个枚举实现**可以扩展操作集：

```java
public interface Operation {
    double apply(double x, double y);
}

public enum BasicOperation implements Operation {
    PLUS { public double apply(double x, double y) { return x + y; } },
    MINUS{ public double apply(double x, double y) { return x - y; } };
}

public enum ExtendedOperation implements Operation {
    EXP  { public double apply(double x, double y) { return Math.pow(x, y); } },
    ...
}

// 测试可以用 <T extends Enum<T> & Operation> 接受任意 Operation 枚举
private static <T extends Enum<T> & Operation> void test(Class<T> opSet, ...) { ... }
```

### 条目 39：注解优先于命名模式

命名模式（如 JUnit 3 的 `testXxx()` 约定）拼写错误不报错、无法限定适用目标。注解 + 反射处理器：

```java
// 标记注解：只在方法上有效
@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.METHOD)
public @interface Test { }

// 可重复注解（Java 8）带参数
@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.METHOD)
@Repeatable(ExceptionTestContainer.class)
public @interface ExceptionTest {
    Class<? extends Throwable> value();
}
```

```java
// 运行时用 isAnnotationPresent 识别标记的方法
for (Method m : testClass.getDeclaredMethods()) {
    if (m.isAnnotationPresent(Test.class)) { ... }
    // 可重复注解：getAnnotationsByType
    if (m.isAnnotationPresent(ExceptionTest.class)) { ... }
}
```

工具类的处理器如此、框架（JUnit/Spring）的原理也如此。编译器会对没加 `@Target` 限定的注解放到错误的元素上报错。

### 条目 40：坚持使用 @Override

不写 `@Override` 的覆写签名拼错时会被当成新方法，静默失败：

```java
public class Bigram {
    private final char first;
    private final char second;
    // 想覆写 equals，参数写成了 Bigram——其实是重载！
    public boolean equals(Bigram b) {          // 编译不报错
        return b.first == first && b.second == second;
    }
    @Override public boolean equals(Object o) { ... }  // 加 @Override 编译器兜底
}
```

**每个覆写方法都加 @Override**（接口抽象方法的实现同样适用）。唯一例外：抽象类中覆写接口方法的桩方法（可写可不写）。

### 条目 41：用标记接口定义类型

标记接口（marker interface）：无方法的接口，如 `Serializable`。

- 标记接口定义**类型**（可以被 instanceof、可以被引用），标记注解不定义类型；
- 标记注解能标在任意元素上（方法/字段/参数），且能参与注解处理器/反射工具链，更灵活。

选择原则：只用于**类和接口**的类型标记 → 标记接口；方法或更广的目标 → 标记注解；如果想限定只用于接口（如 Serializable 对 Arrays）可以组合：`Set<? extends Annotation>` 受限（Java 8 前无效）或 `@Target(ElementType.TYPE)`。
