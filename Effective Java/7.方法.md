
### 条目 49：检查参数的有效性

公有方法：**文档化并校验**参数约束（@throws IllegalArgumentException/IndexOutOfBoundsException/NullPointerException）：

```java
public BigInteger mod(BigInteger m) {
    if (m.signum() <= 0)
        throw new ArithmeticException("Modulus <= 0: " + m);
    ... // do the computation
}
```

非公有的方法（包私有/私有）：**断言**（assert，条件不满足抛 AssertionError，-ea 开启时生效）：

```java
private static void sort(long a[], int offset, int length) {
    assert a != null;
    assert offset >= 0 && offset <= a.length;
    ...
}
```

Java 7 起可用 `Objects.requireNonNull()` 便捷判空（可带消息）；Java 9 起还有 `checkFromIndexSize`/`checkIndex` 等。

**例外**：校验成本很高或不切实际、且计算过程会隐式校验时可以不显式前置（如 `Collections.sort` 的列表排序，排序过程自然抛 ClassCastException——但文档要说明）。构造器的参数校验尤为重要（防止构造出非法对象）。

### 条目 50：必要时进行保护性拷贝

不可信的调用方可能修改类的内部状态（可变参数进来后又在别处被改）：

```java
// Broken: Date 可变，调用方可以改 start/end
public final class Period {
    private final Date start;
    private final Date end;

    public Period(Date start, Date end) {
        if (start.compareTo(end) > 0)
            throw new IllegalArgumentException(...);
        this.start = start;
        this.end = end;
    }
    public Date start() { return start; }
}

// 攻击：new Date 引用还在攻击者手里
Date start = new Date();
Date end = new Date();
Period p = new Period(start, end);
end.setYear(78);   // 修改了 p 的内部状态！
```

修复：构造器和访问器都做**保护性拷贝**：

```java
public Period(Date start, Date end) {
    this.start = new Date(start.getTime());   // 拷贝在前，校验在后（防 TOCTOU）
    this.end   = new Date(end.getTime());
    if (this.start.compareTo(this.end) > 0)
        throw new IllegalArgumentException(...);
}
public Date start() { return new Date(start.getTime()); }
public Date end()   { return new Date(end.getTime()); }
```

细节：**先拷贝再校验**（防止校验后到拷贝前的窗口被改）；**不要用 clone 做拷贝**（Date 可被继承，clone 可能返回恶意子类）。更好的做法：用不可变类型（`Instant` 代替 `Date`），从此不需要保护性拷贝。

### 条目 51：谨慎设计方法签名

- **谨慎选择方法名**：遵循命名惯例（条目 68），清晰、风格一致；
- **不要过于追求提供便利的方法**：太多方法让类难以学习/使用/测试，有疑虑就不加；
- **避免过长的参数列表**（目标 ≤4 个）：
  - 拆成多个方法（如 `List` 的 `indexOf/subList` 替代越界版本的 `findFirstIndex/findLastIndex`）；
  - 创建参数类（`Customer`），builder 模式（条目 2）或 JavaBean；
  - 结合前两者的适配器；
- **参数类型优先使用接口而非类**：`Map` 而不是 `HashMap`（可以传 TreeMap/匿名 Map.of）；
- **对于 boolean 参数，优先使用两个元素的枚举**：`public void applyStyles(boolean isBold)` → `enum Style { BOLD, ITALIC }`。

### 条目 52：慎用重载

**重载在编译期按静态类型选择**（与覆写相反）：

```java
public class CollectionClassifier {
    public static String classify(Set<?> s) { return "Set"; }
    public static String classify(List<?> lst) { return "List"; }
    public static String classify(Collection<?> c) { return "Collection"; }

    public static void main(String[] args) {
        Collection<?>[] collections = {
                new HashSet<String>(), new ArrayList<Integer>(), new HashMap<String, String>().values() };
        for (Collection<?> c : collections)
            System.out.println(classify(c));   // 三次都打印 "Collection"！
    }                                          // 重载按编译期类型 Collection 决定
}
```

规则：

- **不要让同一参数经强转后可以走不同重载**（避免歧义）；
- 尽量不同参数个数、不同类型；相同个数时保持**类型差异显著**；
- `List<E>` 的 `remove(int index)` vs `remove(Object o)` 是典型陷阱（`Set<Integer>` 的 `remove(i)` 优先匹配 `remove(int)`）；
- 自动装箱时代，基本类型和包装类型重载混用极易出错；
- 泛型擦除后 `identity` 与 `erase` 的重载签名可能相同——非法；
- **可变参数与固定参数重载并存**时优先匹配固定版本，也易困惑；
- lambda/方法引用作为参数时，不同函数式接口的重载会产生歧义（需要强转指定）。

保守做法：不确定就换个方法名（`writeBoolean(boolean)`、`writeInt(int)`）。

### 条目 53：慎用可变参数

可变参数接受零个或多个参数：

```java
static int sum(int... args) {
    int sum = 0;
    for (int arg : args) sum += arg;
    return sum;
}
```

要求至少一个参数时（min），单独声明：

```java
static int min(int firstArg, int... remainingArgs) { ... }   // 调用至少传一个
```

性能敏感的场景（`Arrays.asList`、`EnumSet.of` 等），已知参数个数的热路径可以定义多个重载（of() of(E) of(E,E) ... 到 5 个）再落到 varargs 版本：

```java
public interface Stream<T> {
    static <T> Stream<T> of(T t) { ... }
    static <T> Stream<T> of(T t1, T t2) { ... }
    static <T> Stream<T> of(T... values) { ... }  // 兜底
}
```

### 条目 54：返回空集合或数组，而不是 null

```java
// 反例：调用方被迫写防御性 null 检查
private final List<Cheese> cheesesInStock = ...;
public List<Cheese> getCheeses() {
    return cheesesInStock.isEmpty() ? null : new ArrayList<>(cheesesInStock);
}
// 调用方
if (cheeses != null && cheeses.contains(Cheese.STILTON)) ...

// 正例：返回空集合
public List<Cheese> getCheeses() {
    return new ArrayList<>(cheesesInStock);
}
// 不想分配：返回共享的不可变空集合（Collections.emptyList）
public List<Cheese> getCheeses() {
    return cheesesInStock.isEmpty() ? Collections.emptyList()
                                    : new ArrayList<>(cheesesInStock);
}
```

数组同理：返回零长度数组 `new Cheese[0]`（分配廉价），频繁调用可复用一个缓存的零长度数组：

```java
private static final Cheese[] EMPTY_CHEESE_ARRAY = new Cheese[0];

public Cheese[] getCheeses() {
    return cheesesInStock.toArray(EMPTY_CHEESE_ARRAY);
}
```

返回 null 的 C 风格在 Java 中只会带来 NPE 和冗余判断。

### 条目 55：谨慎返回 Optional

`Optional<T>` 表示"可能没有返回值"的方法（代替返回 null 或抛异常）：

```java
// 极值不存在的场景：empty Optional 而不是 null/异常
public static <E extends Comparable<E>> Optional<E> max(Collection<E> c) {
    E result = null;
    for (E e : c)
        if (result == null || e.compareTo(result) > 0)
            result = e;
    return Optional.ofNullable(result);
}
```

使用约定：

- **永远不要返回包装基本类型的 Optional**（`Optional<Integer>`）——用 `OptionalInt/OptionalLong/OptionalDouble`；
- Optional 只用于返回值，**不要做字段/集合元素/方法参数**（本身的创建开销与非可序列化性）；
- 作为集合元素返回时劣于空集合（条目 54 优先）；
- 客户端用法：`orElse(default)`、`orElseThrow()`、`map/filter`、`isPresent()+get()`（避免裸 get）。

```java
max(words).orElse("No words...");           // 默认值
max(words).orElseThrow(NoSuchElementException::new);
String lastWordInDictionary = max(words).orElse("...");
```

### 条目 56：为所有导出的 API 元素写文档注释

文档注释的要点（javadoc）：

```java
/**
 * Returns the element at the specified position in this list.
 *
 * <p>This method is <i>not</i> guaranteed to be constant-time...</p>
 *
 * @param  index index of the element to return
 * @return the element at the specified position in this list
 * @throws IndexOutOfBoundsException if the index is out of range
 *         ({@code index < 0 || index >= size()})
 */
E get(int index);
```

- 每个导出的类/接口/构造器/方法/字段都要文档化；
- 方法文档要说**做什么**（而非内部怎么做）、前置/后置条件、`@throws` 条件、`@param/@return`（不含句号）；
- `{@code}` 用于代码片段（等宽+转义 HTML），`{@literal}` 处理特殊字符；
- 泛型要说明类型参数，注解要说明成员；线程安全性与序列化形式必须写；
- **文档与代码不一致比没文档更糟糕**——保持同步（IDE/javadoc 工具校验）。
