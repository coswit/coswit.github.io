### 条目 57：将局部变量的作用域最小化

- **在第一次使用的地方声明**，声明时就初始化（还没有足够信息初始化说明作用域太早）；
- **for 循环优于 while**：循环变量作用域天然限制在循环内：

```java
// while 版：复制粘贴到别处忘记改 i2 → 编译不报错（i2 忘记声明倒会报错）
Iterator<Element> i = c.iterator();
while (i.hasNext()) doSomething(i.next());

// for 版：i 作用域限制在循环内，重名/复用错误编译期暴露
for (Iterator<Element> i = c.iterator(); i.hasNext(); ) {
    doSomething(i.next());
}
// for-each 更好（条目 58）
```

- 方法小而专注（一个功能一个方法）。

### 条目 58：for-each 循环优于传统 for 循环

```java
for (Element e : elements) {   // 无索引、无迭代器、不会写错
    doSomething(e);
}
```

无法使用 for-each 的场景：

- **过滤**（需要删除元素，需显式 iterator）；
- **转换**（需要替换元素，需索引）；
- **并行迭代**（多个集合同步推进）；
- **倒序或跳步遍历**。

for-each 可用于数组、集合、实现 Iterable 的任何对象（自定义类型实现 Iterable 就能享受）。

### 条目 59：了解并使用库

```java
// 手写生成随机数常见错误：Math.abs(rng.nextInt()) % n —— abs 可能返回负数（MIN_VALUE）！
// 常见错误2：范围偏差
// 标准库直接给：
int i = ThreadLocalRandom.current().nextInt(n);
```

使用库的理由：专家写好了、时间省下来、性能随版本演进、功能逐渐丰富。每个程序员应该熟悉 `java.lang`、`java.util`、`java.io` 及其子包，`java.util.concurrent`（条目 80-84）。

### 条目 60：如果需要精确的答案，请避免使用 float 和 double

float/double 是**二进制浮点**，无法精确表示 0.1 之类的小数：

```java
System.out.println(1.03 - 0.42);   // 0.6100000000000001
System.out.println(1.00 - 9 * 0.10); // 0.09999999999999998
```

- 精确的十进制计算用 **BigDecimal**（慢，但精确，可控制舍入）；
- 性能敏感、位数不超过 9 位（int）或 18 位（long）时，**以分为单位存 int/long**：

```java
// 买幾本 0.1 元/本、0.2 元/本、0.3 元/本的书，1.00 元能买几本？
// 错误：double 计算 funds -= price 出现 0.3999999999999999
// 正确：用 BigDecimal 或以分为单位：10, 20, 30（int）
```

### 条目 61：基本数据类型优于包装数据类型

基本类型 vs 包装类型：更快、更小、== 语义明确。

```java
// 三个坑：
Comparator<Integer> naturalOrder = (i, j) -> (i < j) ? -1 : (i == j ? 0 : 1);
// i == j 比较的是对象引用！Integer.valueOf 缓存范围外的值永远不相等
// 自然顺序比较 Integer 应该用 Integer.compare(i, j)

Long sum = 0L;               // 装箱：循环中反复拆装箱，性能大幅下降
for (long i = 0; i < Integer.MAX_VALUE; i++) sum += i;

if (i == 42) ...             // i 是 Integer 且为 null 时拆箱抛 NPE
```

必须用包装类型的场景：泛型参数/集合元素（`List<Integer>`，条目 26 反过来说明）、反射方法引用、`ThreadLocal<Integer>` 等。

### 条目 62：如果其他类型更适合，则尽量避免使用字符串

字符串不适合代替的领域：

- **值类型**：int/float/BigDecimal（`"123"` 不校验、不可比较）；
- **枚举类型**：`"yes"/"no"` 应该用 enum；
- **聚合类型**：`"name,age"` 应该用对象（解析脆弱）；
- **能力（capabilities）**：`ThreadLocal` 的键用字符串会被共享，应使用不可伪造的类型（`private static class Key {}`）。

字符串是 poor man 的结构化数据，设计良好的类总是更好。

### 条目 63：了解字符串连接的性能

```java
// n 个字符串用 + 拼接：O(n²)（每次都复制整个已拼内容）
String statement = "";
for (int i = 0; i < numItems(); i++)
    statement += lineForItem(i);   // 不要在循环里这样做

// StringBuilder：线性时间
StringBuilder b = new StringBuilder(numItems() * LINE_WIDTH);
for (int i = 0; i < numItems(); i++)
    b.append(lineForItem(i));
String statement = b.toString();
```

原则：**拼接数量有限/一次成型用 + 即可；循环/不确定数量用 StringBuilder**。

### 条目 64：通过接口引用对象

```java
// 好：后续换成 LinkedList/静态工厂返回的新实现，一行都不用改
List<Subscriber> subscribers = new Vector<>();

// 差：绑死具体类
Vector<Subscriber> subscribers = new Vector<>();
```

如果有合适的接口类型存在，**参数、返回值、变量、字段都应用接口类型声明**；只有构造时才引用具体类。没有接口时（值类如 String），用类的层次结构中"最抽象"的类型（如 `ArrayList` → `AbstractList` 一般不必，直接 List 即可）。

### 条目 65：接口优先于反射机制

反射（`java.lang.reflect`）的代价：

- 编译期类型检查全部丧失；
- 代码冗长乏味（异常处理、参数装箱）；
- 性能损失。

常见场景（通过名字实例化类）只需要**一次反射 + 接口引用**：

```java
// 反射只用于创建实例，之后全程面向接口编程
Class<? extends Set<String>> cl = Class.forName(args[0]).asSubclass(Set.class);
Constructor<? extends Set<String>> cons = cl.getConstructor();
Set<String> s = cons.newInstance();
```

核心思想：**用反射创建对象，用接口/超类访问对象**。程序运行时链接不存在的类会失败，这是相对小的代价。

### 条目 66：谨慎地使用本地方法

JNI（本地方法）的历史用途：访问平台特定设施（注册表/文件锁）、利用遗留库、性能关键部分。

现代不建议的原因：

- **内存安全不由 JVM 保证**（本地代码的错误可能破坏整个运行时）；
- 可移植性丧失；
- GC 对本地内存不可见（本地代码的资源管理独立）；
- 现代 JVM 纯 Java 性能已足够（java.math 从 C 迁回 Java 后反而更快）。

确实需要时也要谨慎封装、充分测试。

### 条目 67：谨慎地进行优化

三条优化格言：

1. **Wulf**："以'效率'之名犯下的计算罪过比其他任何单一原因都多（还不一定真有效率）——包括彻底的愚蠢在内"——错误的优化让程序既慢又难维护；
2. **Knuth**："在 97% 的时间里，我们应该忘掉小的效率：过早优化是万恶之源"——但剩下 3% 需要重视；
3. **M.A. Jackson**："优化第一法则：不要优化；第二法则（仅限专家）：还是不要优化——现在还不到时候"；

核心是**先测量再优化**：猜测性能瓶颈通常是错的，用 profiler 找热点。

正确姿势：

- **先写好结构清晰的代码**（好的架构/模块化让优化局部化）；
- **测量**：性能剖析器（profiler）告诉你问题在哪，基准测试（如 JMH）验证改进；
- 系统相关：API、网络、磁盘 I/O 的设计决定往往比代码级微优化影响大得多（好的 API 设计本身就是性能决策）。

### 条目 68：遵守普遍接受的命名惯例

| 类别 | 规则 | 示例 |
| --- | --- | --- |
| 包 | 全小写、层次反转域名 | `com.google.common.collect` |
| 类/接口 | 大驼峰（名词） | `Collection`、`ClassLoader` |
| 方法/字段 | 小驼峰（动词/名词） | `remove`、`ensureCapacity` |
| 常量 | 大写+下划线 | `MAX_VALUE`、`NEGATIVE_INFINITY` |
| 局部变量 | 小驼峰、可缩写 | `i`、`housekeeping`、`c` |
| 类型参数 | 单大写字母 + 语义 | `T`（Type）、`E`（Element）、`K/V`、`R`（Return）、`T1/T2` |

接口命名：能力名词（`Readable`、`Iterable`）；返回 boolean 的方法：`isXxx/hasXxx`；转换方法：`toXxx`；视图方法：`asXxx`；静态工厂：`valueOf/of/getInstance/newType`（条目 1）。

命名惯例是**事实标准**（JLS 只规定了一小部分），违反会让其他程序员困惑。
