### 同步容器类的问题

Vector、Hashtable 及 Collections.synchronizedXxx 是"早期"的同步容器：**每个方法各自同步**，单个方法线程安全，**复合操作不安全**：

- 迭代（遍历时别的线程修改）抛 ConcurrentModificationException（fail-fast 是"尽力而为"的启发式检测）；
- check-then-act（没有才添加）需要客户端加锁（见 03 篇）；
- 迭代期间持锁时间过长会导致活跃性问题。

**新代码不要再用同步容器，用并发容器。**

### 并发容器

针对并发访问重新设计的容器，**大幅提高吞吐的同时保证安全**：

**ConcurrentHashMap**

- 代替同步 HashMap/Hashtable。Java 8 前采用**锁分段（lock striping）**（默认 16 段，不同段可并行写），Java 8 起改为 **CAS + 少量 synchronized 桶级锁**（链表头/红黑树根）；
- **读操作无锁**（volatile 读表与节点）；
- 迭代器**弱一致性（weakly consistent）**：不抛 CME，反映"开始迭代时或之后的部分"状态，不保证实时；
- size()/isEmpty() 是**估计值**（并发下精确统计代价大）；
- 复合操作原子化：**putIfAbsent、replace、computeIfAbsent** 等，替代"客户端加锁"；
- 注意：**批量操作（size、containsAll）语义弱化**——并发环境下的精确瞬时值本身意义有限。

**CopyOnWriteArrayList**

- 代替同步 List，适合**读多写极少**（监听器列表、配置）；
- 每次修改复制底层数组，**读永远无锁**且迭代是快照（不抛 CME、不会看到中间态）；
- 写代价高（复制 + 可能引发 GC 压力）。

**ConcurrentSkipListMap / Set**：跳表实现的有序并发容器（对应同步 TreeMap）。

> 【演进】Java 8 的 ConcurrentHashMap 还提供了并行批量操作（forEach/search/reduce），支持并行流（parallelStream）的底层基石。

### 阻塞队列与生产者-消费者

**BlockingQueue**：put/take 在满/空时**阻塞等待**，天然的流量控制与解耦：

| 实现 | 特点 |
| --- | --- |
| ArrayBlockingQueue | 有界，环形数组 |
| LinkedBlockingQueue | 可选有界，链表 |
| PriorityBlockingQueue | 按优先级出队，无界 |
| SynchronousQueue | **零容量**——put 直接交给 take（交接点，直接握手） |
| DelayQueue | 延迟到期才能取走 |

生产者-消费者模式的价值：**解耦**（生产与消费速率互不依赖）+ **削峰**（有界队列提供"背压"：队列满时生产者阻塞，而不是内存爆掉）。

> 双端队列 Deque（ArrayDeque/LinkedBlockingDeque）：工作密取（work stealing）——每个消费者有自己的双端队列，偷别人的从另一端取，减少竞争（ForkJoin 的调度基础）。

### 阻塞方法与中断方法

阻塞方法（take/put/sleep/join）可能抛 **InterruptedException**——这是**可中断阻塞**的信号。调用阻塞方法的两种选择：传递异常（方法声明 throws）或恢复中断状态（`Thread.currentThread().interrupt()`）。**绝不要捕获后忽略**（吞掉中断剥夺了调用者取消的能力）。

### 同步工具类

**1. 闭锁 CountDownLatch（一次性倒计数）**

`await()` 阻塞直到计数为 0；countDown() 减一。用途：等待 N 个并行任务都完成：

```java
// 测试 N 个线程并发执行某任务的总耗时
public long timeTasks(int nThreads, final Runnable task) throws InterruptedException {
    final CountDownLatch startGate = new CountDownLatch(1);
    final CountDownLatch endGate = new CountDownLatch(nThreads);

    for (int i = 0; i < nThreads; i++) {
        Thread t = new Thread(() -> {
            try {
                startGate.await();          // 等待同时发令
                task.run();
            } catch (InterruptedException ignored) {
            } finally {
                endGate.countDown();        // 完成
            }
        });
        t.start();
    }
    long start = System.nanoTime();
    startGate.countDown();                  // 发令
    endGate.await();                        // 等全部完成
    return System.nanoTime() - start;
}
```

FutureTask.get() 阻塞取结果（可带超时），任务只执行一次。用做**异步计算的句柄**，也可以做"昂贵结果只算一次"的加载器。书中缓存例子：FutureTask 放在 Map 里，计算完成的直接命中：

**3. 信号量 Semaphore（许可计数）**

acquire 获取许可（无则阻塞）、release 归还。用途：**限制并发访问资源数**——有界阻塞容器：

```java
// 用信号量把普通容器变成"有界阻塞"容器
class BoundedHashSet<T> {
    private final Set<T> set;
    private final Semaphore sem;
    public BoundedHashSet(int bound) {
        set = Collections.synchronizedSet(new HashSet<>());
        sem = new Semaphore(bound);
    }
    public boolean add(T o) throws InterruptedException {
        sem.acquire();                       // 先拿许可
        boolean wasAdded = false;
        try {
            wasAdded = set.add(o);
            return wasAdded;
        } finally {
            if (!wasAdded) sem.release();    // 没加成功要还许可
        }
    }
    public boolean remove(Object o) {
        boolean wasRemoved = set.remove(o);
        if (wasRemoved) sem.release();       // 移除后还许可
        return wasRemoved;
    }
}
```

**4. 栅栏 CyclicBarrier（可重用的汇合点）**

所有线程到达 await() 才一起继续（可携带 barrierAction 回调）；**可重复使用**（区别于闭锁），适合**多轮迭代**的并行算法（细胞自动机、并行模拟）。所有线程到齐 → 执行栅栏动作 → 一起进入下一轮。

> 【演进】java.util.concurrent 的后续补充：Java 7 的 **Phaser**（多阶段、可动态增减参与方，比 CyclicBarrier 灵活）、**TransferQueue/LinkedTransferQueue**（融合 put 与 take 的交接语义）、Java 8 的 **CompletableFuture**（替代手工 Future 编排，见第 8 篇）、**StampedLock**（乐观读，见第 11 篇）。
