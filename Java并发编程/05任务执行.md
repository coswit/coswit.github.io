### 在线程中执行任务

任务（Runnable）与执行（怎么跑、在哪个线程、几个并发）应当**分离**。直接 `new Thread(runnable).start()` 的问题：

- 线程生命周期的开销（创建/销毁成本高）；
- 资源消耗（无节制创建线程会耗尽内存/CPU——每个线程默认栈 1MB 左右）；
- **稳定性**：创建过多线程导致 OutOfMemoryError。

### Executor 框架

```java
Executor executor = anExecutor;
executor.execute(runnable);   // 提交任务，怎么执行由执行策略决定
```

Executor 是**执行策略的载体**。执行策略要回答的问题：任务在**什么线程**中执行、按**什么顺序**执行（FIFO/LIFO/优先级）、可以有多少任务**并发**执行、可以有多少任务**排队**等候、系统过载时需要**放弃**哪些任务（拒绝策略）、任务开始/结束时应该执行**哪些动作**。

**线程池**——执行策略的标准实现：

| 工厂方法 | 配置 | 适用 |
| --- | --- | --- |
| newFixedThreadPool(n) | 固定 n 线程，无界队列 | 负载稳定的场景 |
| newCachedThreadPool | 0 核心、上限 ∞、SynchronousQueue | 大量短命小任务 |
| newSingleThreadExecutor | 单线程 + 无界队列 | 任务需要严格串行 |
| newScheduledThreadPool(n) | 定时/周期 | 替代 Timer |

（完整版是 ThreadPoolExecutor 的七个参数与执行流程，见 QA/3.Java三 线程池一节：核心线程、队列、非核心线程、拒绝策略。）

**生命周期**：ExecutorService 的状态机——运行 → 关闭（shutdown：不再接新任务，存量跑完）/ 立即关闭（shutdownNow：中断运行中的任务，返回未执行任务列表）→ 终止（awaitTermination 等待）。

### 延迟任务与周期任务

**ScheduledThreadPoolExecutor 优于 Timer**：

- Timer 只有**一个线程**执行所有定时任务——一个慢任务会推迟所有任务；一个任务抛出未捕获异常，**Timer 认为整个调度器坏了**，后续任务不再执行（ScheduleThreadPoolExecutor 的任务异常只影响自己）；
- Timer 对**系统时钟敏感**（用绝对时间），NTP 调整会出问题；ScheduledThreadPoolExecutor 用相对时间。

### 携带结果的任务：Callable 与 Future

Runnable 没有返回值、不能抛受检异常。**Callable\<V\>** 的 call 有返回值可抛异常；**Future** 是结果的句柄：

```java
Callable<V> task = () -> { ...; return result; };
Future<V> future = exec.submit(task);   // 提交后立刻返回 Future
V result = future.get();                // 阻塞直到完成（可带超时 get(timeout, unit)）
// future.cancel(true)：尝试取消（中断正在运行的任务）
// future.isDone() / isCancelled()
```

**ExecutorCompletionService**：把"完成"与"结果获取"解耦——完成的任务进入结果队列，take() 按完成顺序取（见第 8 篇页面渲染的例子）。

### 任务与负载：为任务选择合适的执行策略

- 任务有类型：**短小独立**（好调度）/ **长任务**（占死线程）/ **依赖任务**（可能死锁，见第 8 篇）/ **要求独占资源**；
- 有界队列 + 拒绝策略：数据库连接、内存都有限，**无界队列会积累成灾**——用有界队列让过载"尽早失败"（ caller-runs 或抛异常），好过慢慢 OOM。

> 【演进】书中写作时（Java 5/6）Executor 是新鲜事物；今天它已是基础。现代选择：Java 8 **CompletableFuture** 声明式编排异步任务；Java 21 **虚拟线程**（`Executors.newVirtualThreadPerTaskExecutor()`）让"每任务一线程"的模式复活——阻塞式写法 + 虚拟线程的低成本阻塞，特别适合 IO 密集服务。注意虚拟线程场景**不要池化**（每任务一个虚拟线程即可），且慎用 ThreadLocal（数量巨大时内存放大）。
