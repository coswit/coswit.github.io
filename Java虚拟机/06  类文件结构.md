## 1. 概述

> 本篇按《深入理解Java虚拟机(第3版)》第6章结构整理。示例可用 `javap -v Test.class` 对照观察。

Class 文件是"无关性"的基石:

- **平台无关**(platform-independent):一次编写,到处运行——不同 OS/CPU 上的 JVM 都认同一份 Class 文件
- **语言无关**(language-independent):虚拟机不关心 Class 来自 Java 还是 Kotlin/Groovy/Scala……只认字节码。无数语言因此获得了直接跑在 JVM 上的能力

## 2. Class类文件的结构

Class 文件是一组以 8 字节为基础单位的**二进制流**,各数据项按固定顺序紧凑排列,没有分隔符。两种数据类型:

- **无符号数**:u1/u2/u4/u8,描述数字、索引引用、字符串
- **表**(table):多个无符号数+其他表构成的复合结构,以 `_info` 结尾

整体布局:

```text
magic(魔数) → minor_version → major_version
→ constant_pool_count → constant_pool(常量池)
→ access_flags(访问标志)
→ this_class / super_class / interfaces(类、父类、接口索引)
→ fields(字段表集合)
→ methods(方法表集合)
→ attributes(属性表集合)
```

### 2.1 魔数与Class文件的版本

- 魔数(magic number):`0xCAFEBABE`,确定这个文件是能被虚拟机接受的 Class 文件(比扩展名可靠)
- 主版本号对照:

| JDK | major | JDK | major |
| --- | --- | --- | --- |
| 8 | 52 | 11 | 55 |
| 9 | 53 | 17 | 61 |

高版本虚拟机能跑低版本的 Class,反之报 `UnsupportedClassVersionError`。

### 2.2 常量池

常量池是 Class 文件的"资源仓库",被后续所有表引用,入口放 `constant_pool_count`。存放两大类常量:

- **字面量**(literal):文本字符串、final 常量
- **符号引用**(symbolic reference):类与接口的全限定名、字段名与描述符、方法名与描述符——**不是内存地址,只是"名字"**

常量类型(第3版共 17 种 `CONSTANT_*` 结构)速览:

| 类别 | 常量类型 |
| --- | --- |
| 数值/字符串字面量 | Utf8、String、Integer、Float、Long、Double |
| 类与接口 | Class |
| 名字与类型 | NameAndType |
| 成员引用 | Fieldref、Methodref、InterfaceMethodref |
| 动态调用( invokedynamic 相关) | MethodHandle、MethodType、Dynamic、InvokeDynamic |
| 模块/包(JDK 9+) | Module、Package |

```text
// javap -v 输出片段:方法引用 = Methodref → Class + NameAndType 组合
#2 = Methodref   #5.#24   // java/lang/Object."<init>":()V
#5 = Class       #31      // java/lang/Object
#24 = NameAndType #10:#11  // "<init>":()V
```

### 2.3 访问标志

`access_flags`(u2)描述类/接口的访问属性:

| 标志 | 值 | 含义 |
| --- | --- | --- |
| ACC_PUBLIC | 0x0001 | public |
| ACC_FINAL | 0x0010 | final,不可继承 |
| ACC_SUPER | 0x0020 | 使用新的 invokespecial 语义 |
| ACC_INTERFACE | 0x0200 | 接口 |
| ACC_ABSTRACT | 0x0400 | 抽象类/接口 |
| ACC_SYNTHETIC | 0x1000 | 编译器自动生成,非源码存在 |
| ACC_ANNOTATION | 0x2000 | 注解类型 |
| ACC_ENUM | 0x4000 | 枚举 |

### 2.4 类索引、父类索引与接口索引集合

`this_class`、`super_class`(java.lang.Object 的父类索引为 0)、`interfaces_count` + `interfaces[]`——全部是指向常量池中 `CONSTANT_Class` 的**索引**,由此确定类型的继承关系。

### 2.5 字段表集合

`field_info` 描述字段:访问标志 → 名字索引 → **描述符**(descriptor)索引 → 属性表。

描述符用紧凑字符表示类型:

| 字符 | 类型 | 字符 | 类型 |
| --- | --- | --- | --- |
| B | byte | J | long |
| C | char | S | short |
| D | double | Z | boolean |
| F | float | V | void(方法返回) |
| I | int | Ljava/lang/String; | 对象类型 |
| [ | 数组维度 | [[I / [Ljava/lang/Object; | int[] / Object[] |

```text
int m;                    → 描述符 "I"
String name;              → 描述符 "Ljava/lang/String;"
Object method(int i, String s) → 描述符 "(ILjava/lang/String;)Ljava/lang/Object;"
```

> 字段表里**不出现**被继承自父类的字段;但可能出现源码中不存在的 `this$0`、`access$000` 等合成字段(内部类、泛型签名等场景)。

### 2.6 方法表集合

`method_info` 结构与字段表一致。方法体不存在方法表里,而是放在**属性表**的 `Code` 属性中;native/abstract 方法没有 Code。

重载方法的合法性由**方法名+描述符**(合称方法的简单签名)共同决定——仅返回值不同不构成重载。

### 2.7 属性表集合

属性(attribute)是 Class 文件里最具扩展性的部分,预定义了 20+ 种:

| 属性 | 作用 |
| --- | --- |
| Code | 方法体字节码、操作数栈深度、局部变量表大小、异常表 |
| ConstantValue | static final 常量(准备阶段直接赋值的依据,见第7章) |
| Exceptions | 方法声明抛出的异常 |
| LineNumberTable | 字节码行号→源码行号(异常栈能带行号就靠它) |
| LocalVariableTable | 局部变量名(调试信息,-g:none 可去掉) |
| SourceFile | 源文件名 |
| StackMapTable | 类型校验数据(加快类验证,见第7章验证阶段) |
| BootstrapMethods | invokedynamic 的引导方法(见第8章) |
| Signature / Synthetic | 泛型签名 / 编译器合成标记 |

## 3. 字节码指令简介

Java 虚拟机的指令集是**面向操作数栈的**(stack-based),指令只占 1 字节(所以又叫"字节码"),分类速览:

| 类别 | 代表指令 |
| --- | --- |
| 加载/存储 | iload、istore、aload、astore、ldc |
| 运算 | iadd、isub、imul、idiv、ineg |
| 类型转换 | i2l、i2f、l2i、checkcast |
| 对象创建与访问 | new、getfield、putfield、getstatic、arraylength |
| 操作数栈管理 | pop、dup、swap |
| 控制转移 | if_icmpge、goto、tableswitch、lookupswitch |
| 方法调用与返回 | invokevirtual、invokestatic、invokespecial、invokeinterface、invokedynamic、*return |
| 异常与同步 | athrow;monitorenter / monitorexit |

## 4. 公开设计与私有实现

虚拟机规范只约束了 Class 文件的**外观**(字节码如何被解释),不约束**实现**:解释执行、全即时编译、混合模式都合法——这给了各 JVM 实现自由竞争的空间(HotSpot 的混合模式、JRockit 的纯编译、GraalVM 的 AOT,见第11章)。
