当我们定义一个类时，可以显式或隐式地指定在此类型对象上**拷贝、移动、赋值和销毁**时做什么。类通过定义五种特殊的成员函数来控制这些操作：

- **拷贝构造函数（copy constructor）**：拷贝初始化时使用。
- **拷贝赋值运算符（copy-assignment operator）**：将一个对象赋值给另一个对象时使用。
- **移动构造函数（move constructor）**：将对象从内存中移动而非拷贝时使用。
- **移动赋值运算符（move-assignment operator）**：移动赋值时使用。
- **析构函数（destructor）**：对象销毁时使用。

拷贝构造函数、拷贝赋值运算符和析构函数合称为**拷贝控制操作（copy control）**。如果一个类没有定义这些成员，编译器会自动为它定义缺失的成员，即**合成的版本（synthesized version）**。

## 拷贝、赋值与销毁

### 拷贝构造函数

如果一个构造函数的第一个参数是自身类类型的引用，且任何额外参数都有默认值，则此构造函数是拷贝构造函数：

```cpp
class Foo {
public:
    Foo();            // 默认构造函数
    Foo(const Foo&);  // 拷贝构造函数
    // ...
};
```

拷贝构造函数的第一个参数必须是一个引用类型（几乎总是 const 引用）。虽然也可以定义一个接受非 const 引用的拷贝构造函数，但这样的参数几乎不能用于拷贝一个 const 对象。

**合成拷贝构造函数（synthesized copy constructor）**：如果我们没有为一个类定义拷贝构造函数，编译器会为我们定义一个。与合成默认构造函数不同，即使我们定义了其他构造函数，编译器也会为我们合成一个拷贝构造函数。合成拷贝构造函数会从给定对象中依次将每个非 static 成员拷贝到正在创建的对象中（memberwise copy，成员依次拷贝）。

拷贝初始化（copy initialization）和直接初始化（direct initialization）：

```cpp
string dots(10, '.');            // 直接初始化
string s(dots);                  // 直接初始化，这里使用拷贝构造函数
string s2 = dots;                // 拷贝初始化
string null_book = "9-999-99999-9"; // 拷贝初始化
string empty_copy = string();    // 拷贝初始化
string empty_direct;             // 直接初始化（默认构造函数）
```

直接初始化要求编译器使用普通的函数匹配来选择与参数最匹配的构造函数；拷贝初始化则要求编译器将右侧运算对象拷贝到正在创建的对象中，如果需要的话还要进行类型转换。

拷贝初始化通常使用拷贝构造函数完成，有时（如 string 与字符指针之间）会先用一个转换构造函数创建一个临时对象，再拷贝。

拷贝初始化不仅在用 `=` 定义变量时会发生，在下列情况下也会发生：

- 将一个对象作为实参传递给一个非引用类型的形参。
- 从一个返回类型为非引用类型的函数返回一个对象。
- 用花括号列表初始化一个数组中的元素或一个聚合类中的成员。

某些类类型还会在分配或释放对象时使用拷贝初始化。

### 拷贝赋值运算符

与类名同名的函数（如 `operator=`）定义了赋值运算。赋值运算符通常应返回一个指向其左侧运算对象的引用：

```cpp
class Foo {
public:
    Foo& operator=(const Foo&); // 赋值运算符
    // ...
};
```

合成拷贝赋值运算符（synthesized copy-assignment operator）：类似拷贝构造函数，如果没有定义，编译器会生成一个。它会将右侧运算对象的每个非 static 成员赋予左侧运算对象的对应成员：

```cpp
Sales_data trans, accum;
// 使用 Sales_data 的合成拷贝赋值运算符
// 等价于：
// trans.bookNo = accum.bookNo;
// trans.units_sold = accum.units_sold;
// trans.revenue = accum.revenue;
trans = accum;
```

### 析构函数

析构函数执行与构造函数相反的操作：构造函数初始化对象的非 static 数据成员，析构函数释放对象使用的资源，并销毁成员。

析构函数是类的一个成员函数，名字由波浪号接类名构成，没有返回值，也不接受参数：

```cpp
class Foo {
public:
    ~Foo(); // 析构函数
    // ...
};
```

由于析构函数不接受参数，因此它不能被重载。一个给定类只会有唯一一个析构函数。

析构函数有一个函数体和一个析构部分（destructuring part）。析构函数首先执行函数体，然后销毁成员。成员按初始化顺序的逆序销毁。

析构函数自身并不直接销毁成员，成员的销毁是在析构函数体之后的隐含的析构阶段完成的。成员销毁时发生什么完全依赖于成员的类型：销毁类类型的成员需要执行成员自己的析构函数；销毁内置类型成员什么也不需要做（尤其是，隐式销毁一个内置指针类型的成员不会 delete 它所指向的对象）。

```cpp
// 下面的类没有显式定义析构函数
class Sales_data {
public:
    // ...
private:
    std::string bookNo;       // string 的析构函数会释放 bookNo 使用的内存
    unsigned units_sold = 0;
    double revenue = 0.0;
};
```

析构函数被调用的时机（无论何时，一个对象被销毁，就会调用其析构函数）：

- 变量在离开其作用域时被销毁。
- 当一个对象被销毁时，其成员被销毁。
- 容器（无论是标准库容器还是数组）被销毁时，其元素被销毁。
- 对于动态分配的对象，当指向它的指针应用 delete 运算符时被销毁。
- 对于临时对象，当创建它的完整表达式结束时被销毁。

注意：当指向一个对象的引用或指针离开作用域时，析构函数不会执行。

合成析构函数（synthesized destructor）：当一个类未定义自己的析构函数时，编译器会为它定义一个合成析构函数。一般来说，合成析构函数的函数体为空：

```cpp
class Sales_data {
public:
    // 没有定义析构函数，编译器会合成一个
    // ~Sales_data() { }          // 合成析构函数等价于这样
    // ...
};
```

### 三/五法则

基本规则：如果你为一个类定义了任何一个拷贝控制成员（析构函数、拷贝构造函数或拷贝赋值运算符），那么通常也应该定义所有三个。原因：

- 如果一个类需要自定义析构函数，几乎可以肯定它也需要自定义拷贝赋值运算符和拷贝构造函数。典型例子是管理动态内存的类：合成的析构函数不会 delete 一个指针成员指向的对象，而合成的拷贝操作会进行浅拷贝，导致两个对象指向同一块内存（双重释放问题）。
- 如果一个类需要一个拷贝构造函数，几乎可以肯定它也需要一个拷贝赋值运算符，反之亦然。但它们不一定需要析构函数。

五个操作（拷贝构造、拷贝赋值、析构、移动构造、移动赋值）应当视为一个整体：如果一个类定义了任何一个，那么通常所有五个都需要定义。

### 使用=default

可以通过将拷贝控制成员定义为 `=default` 来显式地要求编译器生成合成的版本：

```cpp
class Sales_data {
public:
    // 对合成版本的显式请求
    Sales_data() = default;                          // 默认构造函数
    Sales_data(const Sales_data&) = default;         // 拷贝构造函数
    Sales_data& operator=(const Sales_data &);       // 拷贝赋值运算符
    ~Sales_data() = default;                         // 析构函数
};
Sales_data& Sales_data::operator=(const Sales_data&) = default;
```

当我们在类内用 `=default` 修饰成员时，合成的函数将隐式地声明为内联的。如果不希望合成的成员是内联函数，应该只对成员的类外定义使用 `=default`。

### 阻止拷贝

某些类不应该被拷贝，如 iostream 类（拷贝一个 IO 对象将导致多个对象写同一个流）。

新标准下，可以通过将拷贝构造函数和拷贝赋值运算符定义为**删除的函数（deleted function）**来阻止拷贝。删除的函数是这样一种函数：虽然声明了它们，但不能以任何方式使用它们。在函数参数列表后加上 `=delete`：

```cpp
class NoCopy {
    // 类处于一种「不可拷贝」状态
    NoCopy(const NoCopy&) = delete;            // 阻止拷贝
    NoCopy& operator=(const NoCopy&) = delete; // 阻止赋值
    NoCopy() = default;                        // 使用合成的默认构造函数
    ~NoCopy();                                 // 不要删除析构函数
};
```

`=delete` 与 `=default` 的区别：

- `=delete` 必须出现在函数第一次声明的时候（编译器需要知道一个函数是否是删除的，以便阻止使用它的操作）。
- 可以对任何函数指定 `=delete`（不限于成员函数），而 `=default` 只能用于编译器可以合成的默认构造函数或拷贝控制成员。

析构函数不能是删除的成员。如果类的析构函数是删除的，就不能创建该类的对象（包括临时对象）：

```cpp
class NoDtor {
public:
    NoDtor() = default;             // 使用合成默认构造函数
    ~NoDtor() = delete;             // 我们不能销毁 NoDtor 类型的对象
};
NoDtor nd;   // 错误: NoDtor 的析构函数是删除的
NoDtor *p = new NoDtor(); // 正确: 但不能 delete p
delete p;   // 错误: NoDtor 的析构函数是删除的
```

本质上，当不可能拷贝、赋值或销毁类的成员时，类的合成拷贝控制成员就是删除的：

- 如果类的某个成员的析构函数是删除的或不可访问的（例如 private 的），则类的合成析构函数和合成拷贝构造函数被定义为删除的。
- 如果类的某个成员的拷贝构造函数是删除的或不可访问的，则类的合成拷贝构造函数被定义为删除的。
- 如果类的某个成员的拷贝赋值运算符是删除的或不可访问的，则类的合成拷贝赋值运算符被定义为删除的。
- 如果类的某个成员的析构函数是删除的或不可访问的，则类合成的默认构造函数被定义为删除的（因为无法销毁成员）。
- 如果一个类有引用成员，且该类未定义拷贝赋值运算符，则合成的拷贝赋值运算符是删除的（无法改变引用绑定的对象）。
- 如果一个类有 const 成员，且它未定义拷贝赋值运算符，则合成的拷贝赋值运算符是删除的。

本质上，如果一个类有 const 成员或引用成员，这个类就不能使用合成的拷贝赋值运算符（应该定义自己的版本或禁止赋值）。

老式的阻止拷贝方法：将拷贝构造函数和拷贝赋值运算符声明为 private 的（iostream 类就是这样做的），但不定义它们。

## 拷贝控制和资源管理

通常，管理类外资源的类必须定义拷贝控制成员。这种类需要通过析构函数来释放对象分配的资源，一旦定义了析构函数，几乎肯定也需要定义拷贝构造函数和拷贝赋值运算符。

定义拷贝控制成员有两种选择：

- **行为像值（acting like a value）**：类的行为像一个普通值，拷贝一个对象时，副本和原对象是完全独立的，改变副本不会影响原对象。
- **行为像指针（acting like a pointer）**：共享底层资源，拷贝一个对象时，副本和原对象使用同一份底层资源，改变副本会影响原对象。

标准库中的 string 和 shared_ptr 是行为像值的例子，而指针类型和 weak_ptr 是行为像指针的例子。

### 行为像值的类

HasPtr 类的行为像一个值，每个 HasPtr 对象拥有自己的 string 拷贝：

```cpp
class HasPtr {
public:
    HasPtr(const std::string &s = std::string()):
        ps(new std::string(s)), i(0) { }
    // 对 ps 指向的 string，每个 HasPtr 对象都有自己的拷贝
    HasPtr(const HasPtr &p):
        ps(new std::string(*p.ps)), i(p.i) { }
    HasPtr& operator=(const HasPtr &);
    ~HasPtr() { delete ps; }
private:
    std::string *ps;
    int i;
};
```

赋值运算符必须正确处理自赋值（self-assignment），且必须在销毁左侧运算对象的资源之前拷贝右侧运算对象的资源：

```cpp
HasPtr& HasPtr::operator=(const HasPtr &rhs) {
    auto newp = new std::string(*rhs.ps);  // 拷贝底层 string
    delete ps;         // 释放旧内存
    ps = newp;         // 从右侧运算对象拷贝数据到本对象
    i = rhs.i;
    return *this;      // 返回本对象
}
```

一个技巧是先拷贝再销毁旧值，这样即使 new 抛出异常，对象也保持有效状态。

### 行为像指针的类

让 HasPtr 行为像指针，用引用计数（reference count）来记录有多少个对象共享同一个 string：

```cpp
class HasPtr {
public:
    // 构造函数分配新的 string 和新的计数器，将计数器置为 1
    HasPtr(const std::string &s = std::string()):
        ps(new std::string(s)), i(0), use(new std::size_t(1)) {}
    // 拷贝构造函数拷贝所有三个数据成员，并递增计数器
    HasPtr(const HasPtr &p):
        ps(p.ps), i(p.i), use(p.use) { ++*use; }
    HasPtr& operator=(const HasPtr&);
    ~HasPtr();
private:
    std::string *ps;
    int i;
    std::size_t *use; // 成员 use 记录有多少个对象共享 *ps 成员
};

HasPtr::~HasPtr() {
    if (--*use == 0) {  // 如果引用计数变为 0
        delete ps;      // 释放 string 内存
        delete use;     // 释放计数器内存
    }
}

HasPtr& HasPtr::operator=(const HasPtr &rhs) {
    ++*rhs.use;         // 递增右侧运算对象的引用计数
    if (--*use == 0) {  // 然后递减本对象的引用计数
        delete ps;      // 如果没有其他用户
        delete use;     // 释放本对象分配的成员
    }
    ps = rhs.ps;        // 将数据从 rhs 拷贝到本对象
    i = rhs.i;
    use = rhs.use;
    return *this;       // 返回本对象
}
```

拷贝赋值运算符先递增右侧对象的计数再递减左侧对象的计数，这样正确处理了自赋值。

### swap（交换操作）

除了定义拷贝控制成员，管理资源的类通常还定义一个名为 swap 的函数。如果一个类定义了自己的 swap，算法将使用类自定义的版本，否则使用 std::swap 的默认版本（默认版本会进行一次拷贝和两次赋值）：

```cpp
inline
void swap(HasPtr &lhs, HasPtr &rhs) {
    using std::swap;
    swap(lhs.ps, rhs.ps);   // 交换指针，而不是 string 数据
    swap(lhs.i, rhs.i);     // 交换 int 成员
}
```

与拷贝控制成员不同，swap 不是必要的。但是，对于打算与那些重排元素顺序的算法（如 sort）一起使用的类，定义 swap 非常重要，这类算法在交换两个元素时调用 swap。

定义 swap 的类通常用 swap 来定义它们的赋值运算符，使用一种名为**拷贝并交换（copy and swap）**的技术：将左侧运算对象与右侧运算对象的一个拷贝进行交换：

```cpp
// 注意: rhs 是按值传递的，这意味着 HasPtr 的拷贝构造函数
// 将右侧运算对象中的 string 拷贝到 rhs
HasPtr& HasPtr::operator=(HasPtr rhs) {
    // 交换左侧运算对象和局部变量 rhs 的成员
    swap(*this, rhs); // rhs 现在指向本对象曾经使用过的内存
    return *this;     // rhs 被销毁，从而 delete 了本对象原来的指针
}
```

这个技巧天然正确地处理了自赋值，且异常安全。

## 对象移动

新标准的一个最主要的特性是可以**移动（move）**而非拷贝对象的能力。移动而非拷贝对象会大大提高性能：移动构造函数将资源从给定对象「移动」而不是拷贝到正在创建的对象中。

标准库容器、string 和 shared_ptr 类既支持移动也支持拷贝；IO 类和 unique_ptr 类可以移动但不能拷贝。

### 右值引用

**右值引用（rvalue reference）**就是必须绑定到右值的引用，通过 `&&` 来获得。右值引用只能绑定到一个将要销毁的对象，因此可以自由地移动其资源：

```cpp
int i = 42;
int &r = i;             // 正确: r 引用 i
int &&rr = i;           // 错误: 不能将一个右值引用绑定到一个左值上
int &r2 = i * 42;       // 错误: i * 42 是一个右值
const int &r3 = i * 42; // 正确: 我们可以将一个 const 引用绑定到一个右值上
int &&rr2 = i * 42;     // 正确: 将 rr2 绑定到乘法结果上
```

左值（lvalue）持久存在，右值（rvalue）是短暂的：左值有持久的状态，而右值要么是字面常量，要么是在表达式求值过程中创建的临时对象。

由于右值引用只能绑定到临时对象，因此：

- 所引用的对象将要被销毁。
- 该对象没有其他用户。

这两个特性意味着：使用右值引用的代码可以自由地接管所引用的对象的资源。

变量是左值；变量表达式是左值。因此不能将一个右值引用直接绑定到另一个右值引用类型的变量上：

```cpp
int &&rr1 = 42;     // 正确: 字面常量是右值
int &&rr2 = rr1;    // 错误: 表达式 rr1 是左值!
```

### 标准库move函数

虽然不能直接将一个右值引用绑定到一个左值上，但可以显式地将一个左值转换为对应的右值引用类型。通过调用 `move` 函数（定义在 utility 头文件中）可以获得绑定到左值上的右值引用：

```cpp
int &&rr1 = 42;     // 正确: 字面常量是右值
int &&rr3 = std::move(rr1); // 正确
```

move 调用告诉编译器：我们有一个左值，但我们希望像一个右值一样处理它。我们必须认识到：调用 move 就意味着承诺：除了对 rr1 赋值或销毁它外，我们将不再使用它。在调用 move 之后，我们不能对移后源对象的值做任何假设（移后源对象处于有效但未指定的状态）。

使用 move 的代码应该使用 `std::move` 而不是简单的 move，避免名字冲突。我们可以销毁一个移后的源对象，也可以赋予它一个新值，但不能使用一个移后源对象的值。

### 移动构造函数和移动赋值运算符

移动构造函数的第一个参数是该类类型的一个右值引用，任何额外的参数都必须有默认实参。

除了完成资源移动，移动构造函数还必须确保移后源对象处于这样一个状态——销毁它是无害的。特别是它必须将任何指向被移动资源的指针置为 nullptr：

```cpp
// StrVec 是一个管理 string 动态数组的类
StrVec::StrVec(StrVec &&s) noexcept // 移动操作不应抛出任何异常
    : elements(s.elements), first_free(s.first_free), cap(s.cap) {
    // 将 s 置于可析构状态
    s.elements = s.first_free = s.cap = nullptr;
}
```

**移动操作、标准库容器和异常**：由于移动操作「窃取」资源，它通常不分配内存，因此通常不会抛出异常。我们必须在类头文件的声明和定义中指定 `noexcept` 来承诺这一点。noexcept 出现在参数列表后、初始化列表前的冒号前。如果不承诺 noexcept，vector 在重新分配内存时将使用拷贝而不是移动（为了保证异常安全：如果移动过程中抛出异常，旧数据已被破坏，而拷贝可以保留原数据）。

移动赋值运算符执行与析构函数和移动构造函数相同的工作：

```cpp
StrVec& StrVec::operator=(StrVec &&rhs) noexcept {
    // 直接检测自我赋值
    if (this != &rhs) {
        free();                  // 释放已有元素
        elements = rhs.elements; // 从 rhs 接管旧内存
        first_free = rhs.first_free;
        cap = rhs.cap;
        // 将 rhs 置于可析构状态
        rhs.elements = rhs.first_free = rhs.cap = nullptr;
    }
    return *this;
}
```

移后源对象必须可析构：在移动（或销毁）源对象后，源对象必须保持有效（可以安全地被赋予新值或被销毁）但状态未指定。

**合成的移动操作**：编译器会合成移动构造函数和移动赋值运算符，但只有在类没有定义任何拷贝控制成员（拷贝构造、拷贝赋值、析构），且每个非 static 数据成员都可以移动时。编译器可以移动内置类型的成员；如果一个成员是类类型，且该类有对应的移动操作，编译器也能移动该成员。

与拷贝操作不同，移动操作永远不会被隐式定义为删除的。但如果显式地要求编译器生成 `=default` 的移动操作，而编译器无法移动所有成员，则移动操作被定义为删除的。

移动操作与合成的拷贝控制成员的相互作用：

- 如果一个类定义了一个移动构造函数和/或一个移动赋值运算符，则该类的合成拷贝构造函数和拷贝赋值运算符会被定义为删除的。因此，定义了一个移动构造函数或移动赋值运算符的类必须也定义自己的拷贝操作，否则这些成员默认被删除。

### 移动迭代器

新标准库中有一种**移动迭代器（move iterator）**适配器，通过 make_move_iterator 函数将一个普通迭代器转换为一个移动迭代器。解引用一个移动迭代器返回一个右值引用：

```cpp
void StrVec::reallocate() {
    // 分配大小两倍于当前规模的内存空间
    auto newcapacity = size() ? 2 * size() : 1;
    auto first = alloc.allocate(newcapacity);
    // 移动元素
    auto last = uninitialized_copy(make_move_iterator(begin()),
                                   make_move_iterator(end()),
                                   first);
    free(); // 释放旧空间
    elements = first; // 更新指针
    first_free = last;
    cap = elements + newcapacity;
}
```

由于移动一个对象会销毁原对象，因此只有在确信算法在移动之后不再访问移后源对象时，才能使用移动迭代器（如向新内存移动元素后，旧内存将被释放）。

### 右值和左值引用成员函数

引用限定符（reference qualifier）可以指出 this 的左值/右值属性：在参数列表之后放置 `&` 或 `&&`。`&` 只能被左值调用，`&&` 只能被右值调用：

```cpp
class Foo {
public:
    Foo &operator=(const Foo&) &; // 只能向可修改的左值赋值
    // ...
    Foo sorted() &&;      // 可用于可修改的右值
    Foo sorted() const &; // 可用于任何类型的 Foo 对象
};
```

引用限定符只能用于成员函数，且必须同时出现在函数的声明和定义中。
