## 基本概念

重载的运算符是特殊的函数：它们的名字由关键字 operator 和其后要定义的运算符号共同组成。与其他函数一样，重载的运算符也包含返回类型、参数列表以及函数体。

```cpp
// 非成员运算符函数的等价调用形式
data1 + data2;             // 普通的表达式
operator+(data1, data2);   // 等价的函数调用
```

除了重载的函数调用运算符 operator() 之外，其他重载运算符不能含有默认实参。

对于一个运算符函数来说，它或者是类的成员，或者至少含有一个类类型的参数：

```cpp
// 错误: 不能为 int 重定义内置的 + 运算符
int operator+(int, int);
```

这一约束意味着不能改变内置类型运算符的含义，包括指针类型。

我们可以重载大多数（但不是全部）运算符。「::」、「.」、「.*」、「?:」不能被重载。只能重载已存在的运算符，不能发明新的运算符号。

重载运算符的优先级、结合律与运算对象的数目都与内置版本一致。

是否应该重载运算符的经验原则：

- 只有当操作的含义对于用户来说清晰明了时才使用运算符（如 `+` 表示加法）。
- 不要为了图省事而滥用运算符。

### 直接调用一个重载的运算符函数

```cpp
// 一个非成员运算符函数的等价调用
data1 + data2;             // 普通的表达式
operator+(data1, data2);   // 等价的函数调用

// 一个成员运算符函数的等价调用
data1 += data2;            // 基于调用的表达式
data1.operator+=(data2);   // 对成员运算符函数的等价调用
```

### 某些运算符不应该被重载

某些运算符重载后无法保留求值顺序：逻辑与运算符、逻辑或运算符和逗号运算符在内置版本中保留求值顺序（先左后右），重载版本无法保留。逗号运算符和取址运算符的重载一般不应使用——取址运算符作用于类对象时默认返回该对象的地址。

### 使用与内置类型一致的定义

重载运算符与内置版本的语义差距越大，使用者的困惑就越大。明智的准则：尽量不要偏离内置版本的语义。

选择作为成员还是非成员：

- 赋值（=）、下标（[]）、调用（()）和成员访问箭头（->）运算符必须是成员。
- 复合赋值运算符一般来说应该是成员，但并非必须。
- 改变对象状态的运算符或者与给定类型密切相关的运算符，如递增、递减和解引用，通常应该是成员。
- 具有对称性的运算符可能转换任意一端的运算对象，如算术、相等性、关系和位运算符，通常应该是非成员函数。

## 输入和输出运算符

IO 标准库为普通输入输出流定义了 >> 和 << 运算符，它们分别是 istream 和 ostream 的成员。因此我们自己的类需要定义自己的版本。

### 重载输出运算符<<

通常情况下，输出运算符的第一个形参是一个非常量 ostream 对象的引用，第二个形参一般是一个常量的引用：

```cpp
ostream &operator<<(ostream &os, const Sales_data &item) {
    os << item.isbn() << " " << item.units_sold << " "
       << item.revenue << " " << item.avg_price();
    return os;
}
```

输出运算符应该尽量减少格式化操作，尤其不应该打印换行符。

与 iostream 标准库兼容的输出运算符必须是普通非成员函数（因为左侧运算对象是 ostream 而非自定义类）。而且，如果需要在类内将其声明为友元：

```cpp
class Sales_data {
    friend ostream &operator<<(ostream&, const Sales_data&);
    // ...
};
```

### 重载输入运算符>>

输入运算符的第一个形参是运算符将要读取的流的引用，第二个形参是将要读入到的（非常量）对象的引用：

```cpp
istream &operator>>(istream &in, Sales_data &s) {
    double price;
    in >> s.bookNo >> s.units_sold >> price;
    // 检查是否输入成功
    if (in)
        s.revenue = s.units_sold * price;
    else
        s = Sales_data(); // 输入失败: 对象被赋予默认状态
    return in;
}
```

输入运算符必须处理输入可能失败的情况，而输出运算符不需要。输入失败时，将对象置为合法状态是一种好的做法。

## 算术和关系运算符

通常情况下，把算术和关系运算符定义成非成员函数，因为不需要改变操作对象的状态，主要优点是可以与内置类型的转换规则保持对称：

```cpp
// 假定两个对象表示同一本书
Sales_data
operator+(const Sales_data &lhs, const Sales_data &rhs) {
    Sales_data sum = lhs;  // 把 lhs 的数据成员拷贝到 sum
    sum += rhs;            // 将 rhs 的数据成员加到 sum 中
    return sum;
}
```

如果类定义了算术运算符，则最好也定义对应的复合赋值运算符。一般使用复合赋值来实现算术运算符。

### 相等运算符

通常情况下，相等运算符应该具有传递性（如果 a==b 且 b==c，则 a==c）：

```cpp
bool operator==(const Sales_data &lhs, const Sales_data &rhs) {
    // 必须比较 isbn、售出数量和总销售额
    return lhs.isbn() == rhs.isbn() &&
           lhs.units_sold == rhs.units_sold &&
           lhs.revenue == rhs.revenue;
}
bool operator!=(const Sales_data &lhs, const Sales_data &rhs) {
    return !(lhs == rhs);
}
```

如果某个类在逻辑上有相等性的含义，则该类应该定义 operator==。如果一个类定义了 operator==，则这个类也应该定义 operator!=。相等运算符和不相等运算符中的一个应该把工作委托给另一个。

### 关系运算符

定义了相等运算符的类也常常（但不总是）需要定义关系运算符。因为关联容器和一些算法要用到小于运算符，定义 operator< 会很有用。

如果存在唯一一种逻辑可靠的 < 定义，则可以考虑为这个类定义 < 运算符。如果类同时包含 ==，则当且仅当 < 的定义和 == 产生的结果完全一致（即 a<b 为真当且仅当 a==b 为假）时才定义它。

## 赋值运算符

赋值运算符必须定义为成员函数，复合赋值运算符也如此。无论形参的类型是什么，赋值运算符都必须定义为成员函数，且都应该返回左侧运算对象的引用：

```cpp
// 假定 lhs 和 rhs 是两个 StrVec 对象
StrVec &StrVec::operator=(const StrVec &rhs) {
    // ...（拷贝赋值，见第 13 章）
    return *this;
}
StrVec &StrVec::operator=(StrVec &&rhs) noexcept {
    // ...（移动赋值）
    return *this;
}
// 作为成员函数的 operator+=
Sales_data& Sales_data::operator+=(const Sales_data &rhs) {
    units_sold += rhs.units_sold;
    revenue += rhs.revenue;
    return *this;
}
```

赋值运算符（=）无论形参为何种类型都必须定义为成员函数，除了拷贝赋值和移动赋值之外，还可以定义其他赋值运算符以使用别的类型作为右侧运算对象：

```cpp
class StrVec {
public:
    // 接受一个 initializer_list<string> 的赋值运算符
    StrVec &operator=(std::initializer_list<std::string>);
};
```

值得注意的是，标准库 vector 类的赋值运算符接受一个 initializer_list 参数。

## 下标运算符

下标运算符必须是成员函数。

为了让下标运算符对 const 对象也可用，通常会定义一个 const 版本和一个非 const 版本：

```cpp
class StrVec {
public:
    std::string& operator[](std::size_t n)
        { return elements[n]; }
    const std::string& operator[](std::size_t n) const
        { return elements[n]; }
private:
    std::string *elements;   // 指向数组首元素的指针
};
```

返回访问元素的引用是一种好的习惯：这样得到的返回值可以作为左值使用。

```cpp
// 假定 svec 是一个 StrVec 对象
const StrVec cvec = svec;
if (svec.size() && svec[0].empty()) {  // ok: 下标运算符的 const 版本
    svec[0] = "zero";                  // ok: 下标运算符的非 const 版本
    // cvec[0] = "Zip";                // 错误: 对 cvec 取下标时返回的是常量引用
}
```

## 递增和递减运算符

C++ 语言并不要求递增和递减运算符必须是类的成员，但是因为它们改变的正好是所操作对象的状态，所以建议将其定义为成员函数。

定义递增/递减运算符的类应该同时定义前置版本和后置版本。前置版本返回递增/递减后的对象（返回引用），后置版本返回递增/递减之前的状态（返回值）：

```cpp
class StrBlobPtr {
public:
    // 前置运算符: 递增然后返回递增后的对象的引用
    StrBlobPtr& operator++();
    StrBlobPtr& operator--();
    // 后置运算符: 递增/递减但返回原值
    StrBlobPtr operator++(int);
    StrBlobPtr operator--(int);
    // ...
};
```

后置版本接受一个额外的（不被使用的）int 类型的形参，用于与前置版本区分。当我们使用后置运算符时，编译器为这个形参提供一个值为 0 的实参：

```cpp
StrBlobPtr p(a1);
p.operator++(0); // 调用后置版本的 operator++
p.operator++();  // 调用前置版本的 operator++
```

前置版本：

```cpp
// 前置版本: 检查递增的有效性然后递增
StrBlobPtr& StrBlobPtr::operator++() {
    // 如果 curr 已经指向容器的尾后位置，则无法递增它
    check(curr, "increment past end of StrBlobPtr");
    ++curr;       // 将 curr 移动到下一个位置
    return *this;
}
StrBlobPtr& StrBlobPtr::operator--() {
    // 如果 curr 是 0，则递减它会产生一个无效下标
    --curr;       // 将 curr 移动到前一个位置
    check(curr, "decrement past begin of StrBlobPtr");
    return *this;
}
```

后置版本：

```cpp
// 后置版本: 递增/递减对象但返回原值
StrBlobPtr StrBlobPtr::operator++(int) {
    // 此处无须检查有效性，调用前置运算符时才需要检查
    StrBlobPtr ret = *this;  // 保存当前值
    ++*this;                 // 将当前值向前移动一个元素（调用前置++）
    return ret;              // 返回之前保存的状态
}
StrBlobPtr StrBlobPtr::operator--(int) {
    StrBlobPtr ret = *this;  // 保存当前值
    --*this;                 // 将当前值向后移动一个元素（调用前置--）
    return ret;              // 返回之前保存的状态
}
```

后置版本调用前置版本完成实际工作。

显式调用后置运算符时须为 int 形参传递实参（通常传 0）。

## 成员访问运算符

解引用运算符和箭头运算符在迭代器类及智能指针类中常被重载。解引用运算符*必须是成员函数，箭头运算符->也必须是成员函数，且通常也重载解引用：

```cpp
class StrBlobPtr {
public:
    std::string& operator*() const {
        auto p = check(curr, "dereference past end");
        return (*p)[curr];  // (*p) 是对象所指的 vector
    }
    std::string* operator->() const {
        // 将实际工作委托给解引用运算符
        return & this->operator*();
    }
    // ...
};
```

注意 operator* 和 operator-> 都是 const 成员函数（返回的是非常量 string 的引用——因为 StrBlobPtr 的底层 vector 是 shared_ptr管理的，const 修饰的是指针本身）。

对箭头运算符返回值的限定：point->action 的含义与两个表达式等价（point 是一个类对象）：

```cpp
(*point).action;      // 内置含义: 解引用 point 然后调用 action
point.operator->()->action; // 重载版本
```

重载的箭头运算符必须返回类的指针或者自定义了一个箭头运算符的类对象。

```cpp
StrBlob a1 = {"hi", "bye", "veta"};
StrBlobPtr p(a1);   // p 指向 a1 中的 vector
*p = "okay";        // 给 a1 的首元素赋值
cout << p->size() << endl;     // 使用 StrBlobPtr::operator->，实际上是对 vector 调用 size
cout << (*p).size() << endl;   // 等价于 p->size()
```

## 函数调用运算符

如果类重载了函数调用运算符，则我们可以像使用函数一样使用该类的对象。因为这样的类同时也能存储状态，所以它们比普通函数更灵活：

```cpp
struct absInt {
    int operator()(int val) const {
        return val < 0 ? -val : val;
    }
};

int i = -42;
absInt absObj;           // 包含函数调用运算符的对象
int ui = absObj(i);      // 将 i 传递给 absObj.operator()
```

函数调用运算符必须是成员函数。一个类可以定义多个不同版本的调用运算符，相互之间应该在参数数量或类型上有所区别。

如果类定义了调用运算符，则该类的对象称作**函数对象（function object）**。函数对象常常作为泛型算法的实参。

### 含有状态的函数对象（函数对象的类模板）

```cpp
class PrintString {
public:
    PrintString(ostream &o = cout, char c = ' '):
        os(o), sep(c) { }
    void operator()(const string &s) const { os << s << sep; }
private:
    ostream &os;   // 用于写入的目的流
    char sep;      // 用于将不同输出隔开的字符
};

PrintString printer;     // 使用默认值: 打印到 cout
printer(s);              // 在 cout 中打印 s，后面跟一个空格
PrintString errors(cerr, '\n');
errors(s);               // 在 cerr 中打印 s，后面跟一个换行符

for_each(vs.begin(), vs.end(), PrintString(cerr, '\n'));
```

### lambda是函数对象

编写了一个 lambda 后，编译器将该表达式翻译成一个未命名类的未命名对象，类中含有一个重载的函数调用运算符。默认情况下 lambda 不能改变它捕获的变量，因此函数调用运算符默认是 const 的：

```cpp
// 按单词长度排序 words
stable_sort(words.begin(), words.end(),
            [](const string &a, const string &b)
              { return a.size() < b.size(); });
// 其行为类似于下面的类的未命名对象
class ShorterString {
public:
    bool operator()(const string &s1, const string &s2) const
    { return s1.size() < s2.size(); }
};
```

通过引用捕获变量，或通过值捕获变量——由值捕获的变量被拷贝到 lambda 中，成为 lambda 生成的类的一个数据成员：

```cpp
// 获得第一个满足 size() >= sz 的元素
auto wc = find_if(words.begin(), words.end(),
                  [sz](const string &a) { return a.size() >= sz; });
// 其行为类似于:
class SizeComp {
public:
    SizeComp(size_t n): sz(n) { }  // 形参对应捕获的变量
    // 此调用运算符的返回类型、形参和函数体都与 lambda 一致
    bool operator()(const string &s) const { return s.size() >= sz; }
private:
    size_t sz;       // 捕获的变量
};
auto wc = find_if(words.begin(), words.end(), SizeComp(sz));
```

lambda 产生的类不含默认构造函数、赋值运算符及默认析构函数。通过引用捕获变量的 lambda 产生的类中，引用成员不会在 lambda 对象销毁时被销毁。

### 标准库定义的函数对象

标准库定义了一组表示算术运算符、关系运算符和逻辑运算符的类，每个类分别定义了一个执行命名操作的调用运算符。这些类都定义在 functional 头文件中，都是模板类型：

| 算术              | 关系                | 逻辑           |
| ----------------- | ------------------- | -------------- |
| plus<Type>        | equal_to<Type>      | logical_and<Type> |
| minus<Type>       | not_equal_to<Type>  | logical_or<Type>  |
| multiplies<Type>  | greater<Type>       | logical_not<Type> |
| divides<Type>     | greater_equal<Type> |                 |
| modulus<Type>     | less<Type>          |                 |
| negate<Type>      | less_equal<Type>    |                 |

这些类只重载了调用运算符，不保存数据：

```cpp
plus<int> intAdd;         // 可执行 int 加法的函数对象
negate<int> intNegate;    // 可执行 int 一元求反的函数对象
int sum = intAdd(10, 20);       // sum = 30
sum = intNegate(intAdd(10, 20));// sum = -30
sum = intAdd(10, intNegate(10));// sum = 0
```

使用标准库函数对象和泛型算法：

```cpp
// 传递给 sort 的第三个实参是一个可调用对象
sort(svec.begin(), svec.end(), greater<string>());
// 按逆序排序: 使用 > 运算符而不是 < 运算符
```

一个重要的例子：标准库规定某些算法只能使用特定的运算符。如关联容器的关键字默认用 less 排序，priority_queue 默认用 less：

```cpp
vector<string *> nameTable; // 指针的 vector
// 错误: 指针上的 < 是未定义的
// sort(nameTable.begin(), nameTable.end(),
//      [](string *a, string *b) { return a < b; });
// 正确: 标准库规定指针的 less 是定义良好的
sort(nameTable.begin(), nameTable.end(), less<string*>());
```

### 可调用对象与function

C++ 语言中有几种可调用对象：函数、函数指针、lambda 表达式、bind 创建的对象以及重载了函数调用运算符的类。

不同类型的可调用对象可能共享同一种调用形式（call signature）——调用形式指明了调用返回的类型以及传递给调用的实参类型：

```cpp
int add(int i, int j) { return i + j; }    // 函数
auto mod = [](int i, int j) { return i % j; }; // lambda
struct divide {                            // 函数对象
    int operator()(int denominator, int divisor) {
        return denominator / divisor;
    }
};
```

上面三者都共享同一种调用形式 `int(int, int)`。

标准库 function 类型（C++11，定义在 functional 头文件中）是一个模板，可用于表示上述各种可调用对象的统一类型：

```cpp
function<int(int, int)> f1 = add;      // 函数指针
function<int(int, int)> f2 = divide(); // 函数对象
function<int(int, int)> f3 = [](int i, int j) { return i * j; }; // lambda

cout << f1(4, 2) << endl;  // 打印 6
cout << f2(4, 2) << endl;  // 打印 2
cout << f3(4, 2) << endl;  // 打印 8

// 用 map 来构建一个「函数表」
map<string, function<int(int, int)>> binops = {
    {"+", add},                                // 函数指针
    {"-", std::minus<int>()},                  // 标准库函数对象
    {"/", divide()},                           // 用户定义的函数对象
    {"*", [](int i, int j) { return i * j; }}, // 未命名的 lambda
    {"%", mod}                                 // 命名了的 lambda
};
binops["+"](10, 5); // 调用 add(10, 5)
```

直接将重载函数名存入 function 会产生二义性，可以通过存储函数指针（指定了具体版本）或 lambda 来解决。

## 重载、类型转换与运算符

### 类型转换运算符

类型转换运算符（conversion operator）是类的一种特殊成员函数，它负责将一个类类型的值转换成其他类型。一般形式如下：

```cpp
operator type() const;
```

类型转换函数必须是类的成员函数，不能声明返回类型，形参列表必须为空。类型转换函数通常是 const 的：

```cpp
class SmallInt {
public:
    SmallInt(int i = 0): val(i) { }  // 构造函数: 从 int 转换到 SmallInt
    // 类型转换运算符: 从 SmallInt 转换到 int
    operator int() const { return val; }
private:
    std::size_t val;
};

SmallInt si;
si = 4;    // 首先将 4 隐式地转换为 SmallInt，然后调用 SmallInt::operator=
si + 3;    // 首先将 si 隐式地转换为 int，然后执行整数的加法
```

### 避免过度使用类型转换函数

类型转换运算符可能在无意中被使用，产生意外结果。一个经典的例子是 bool 类型转换：

```cpp
int i = 42;
cin << i; // 如果 cin 能向 bool 转换，则本代码合法（但含义错误）
//cin 会转换为 bool，然后 bool 提升为 int，左移 42 位！
```

### 显式的类型转换运算符

C++11 引入了显式的类型转换运算符（explicit conversion operator）：

```cpp
class SmallInt {
public:
    SmallInt(int i = 0): val(i) { }
    // 编译器不会自动执行这一转换
    explicit operator int() const { return val; }
private:
    std::size_t val;
};

SmallInt si = 3;              // 正确: SmallInt 的构造函数不是显式的
// si + 3;                    // 错误: 不能隐式地进行类型转换
static_cast<int>(si) + 3;     // 正确: 显式地请求类型转换
```

一个例外：表达式被用作条件（如 if、while、for 的条件部分、三目运算符的条件、!、&&、|| 的运算对象）时，显式的类型转换将被隐式地执行。因此，向 bool 的类型转换一般定义成 explicit 的：

```cpp
while (std::cin >> value)
// std::cin 的 operator bool 是 explicit 的，但在条件中会被隐式执行
```

### 避免有二义性的类型转换

如果类中包含一个或多个类型转换，必须确保在类类型和目标类型之间只存在唯一一种转换方式。两种情况下会产生二义性：

- 两个类定义了相互转换的类型转换（A 定义了接受 B 的构造函数，B 定义了向 A 转换的运算符）。
- 类定义了多个转换规则，而这些转换涉及的类型本身可以通过某些其他转换规则相互转换（如定义了向 int 和向 double 的转换，而 int 可以转换为 double）。

```cpp
struct B;
struct A {
    A() = default;
    A(const B&);        // B 转换为 A
    // ...
};
struct B {
    operator A() const; // B 转换为 A
    // ...
};
A f(const A&);
B b;
// f(b);         // 错误: 二义性——通过 A 的构造函数还是 B 的类型转换运算符？
f(b.operator A()); // 正确: 显式请求
f(A(b));           // 正确
```

通常情况下，不要为类定义相同的类型转换，也不要在类中定义两个及两个以上转换源或转换目标是算术类型的转换。

### 运算符与类型转换

当我们重载运算符时，如果运算对象是类类型且定义了类型转换，也会出现二义性问题。例如在调用重载的运算符时，编译器需要选择用户定义的转换还是内置的运算符版本。

经验规则：

- 不要令两个类执行相同的类型转换：如果 a 定义了接受 b 的构造函数，就不要在 b 中定义向 a 的类型转换运算符。
- 避免定义到内置算术类型的类型转换，特别是已经定义了到其他算术类型的转换时。如果需要，定义一个普通的成员函数来显式地完成转换。
- 在定义转换运算符时，尽可能将其定义为 explicit 的。
