## OOP：概述

面向对象程序设计（object-oriented programming）的核心思想是**数据抽象**、**继承（inheritance）**和**动态绑定（dynamic binding）**。

- 数据抽象：可以将类的接口与实现分离。
- 继承：可以定义相似的类型并对其相似关系建模。
- 动态绑定：可以在一定程度上忽略相似类型的区别，而以统一的方式使用它们的对象。

通过继承联系起来的类构成一种层次关系。层次关系中存在两种类：**基类（base class）**定义层次关系中所有类共同拥有的成员，**派生类（derived class）**定义各自特有的成员。

在 C++ 语言中，基类将类型相关的函数与派生类不做改变直接继承的函数区分开。对于某些函数，基类希望它的派生类各自定义适合自身的版本，此时基类就将这些函数声明为**虚函数（virtual function）**。

```cpp
class Quote {
public:
    std::string isbn() const;
    virtual double net_price(std::size_t n) const;
};
class Bulk_quote : public Quote { // Bulk_quote 继承了 Quote
public:
    double net_price(std::size_t n) const override; // 覆盖基类的虚函数
};
```

动态绑定（在 C++ 中又称运行时绑定）：通过基类的引用或指针调用虚函数时，实际执行的是与被绑定对象的动态类型（而非静态类型）匹配的版本：

```cpp
// 计算并打印销售给定数量的某种书籍所得的费用
double print_total(ostream &os,
                   const Quote &item, // item 的类型是 Quote&，但可以绑定到 Bulk_quote 对象
                   size_t n) {
    // 根据传入 item 的对象的实际类型调用 Quote::net_price 或 Bulk_quote::net_price
    double ret = item.net_price(n);
    os << "ISBN: " << item.isbn()   // 调用 Quote::isbn
       << " # sold: " << n << " total due: " << ret << endl;
    return ret;
}
```

使用动态绑定（基类引用/指针 + 虚函数），我们可以编写一段代码，使其既能处理 Quote 对象也能处理 Bulk_quote 对象。

## 定义基类和派生类

### 定义基类

Quote 类：

```cpp
class Quote {
public:
    Quote() = default;
    Quote(const std::string &book, double sales_price):
        bookNo(book), price(sales_price) { }
    std::string isbn() const { return bookNo; }
    // 派生类负责实现自己的 net_price 版本
    virtual double net_price(std::size_t n) const
        { return n * price; }
    virtual ~Quote() = default; // 对析构函数进行动态绑定
private:
    std::string bookNo; // 书籍的 ISBN 号
protected:
    double price = 0.0; // 代表普通状态下不打折的价格
};
```

基类通常都应该定义一个虚析构函数，即使该函数不执行任何实际操作。

**成员函数与继承**：派生类可以继承基类的成员函数，但是如前所述，有时希望派生类对某些函数提供自己的版本，此时需要将函数声明为 virtual。

**访问控制与继承**：派生类可以访问基类的公有成员和受保护成员，但不能访问私有成员。protected 成员：类的设计者希望派生类有权访问该成员，同时禁止其他用户访问。

### 定义派生类

派生类必须通过**类派生列表（class derivation list）**明确指出它是从哪个（哪些）基类继承而来的。派生列表形式：冒号后紧跟以逗号分隔的基类列表，每个基类前面可以有访问说明符：

```cpp
class Bulk_quote : public Quote {   // 公有继承
public:
    Bulk_quote() = default;
    Bulk_quote(const std::string&, double, std::size_t, double);
    // 覆盖基类的 net_price 函数
    double net_price(std::size_t) const override;
private:
    std::size_t min_qty = 0;    // 适用折扣政策的最低购买量
    double discount = 0.0;      // 折扣额
};

// 派生类构造函数
Bulk_quote::Bulk_quote(const std::string &book, double p,
                       std::size_t qty, double disc) :
                       Quote(book, p), min_qty(qty), discount(disc) { }

// 覆盖基类的函数以实现基于购买数量的折扣政策
double Bulk_quote::net_price(std::size_t cnt) const {
    if (cnt >= min_qty)
        return cnt * (1 - discount) * price;
    else
        return cnt * price;
}
```

派生类中的虚函数：派生类经常（但不总是）覆盖它继承的虚函数。如果派生类没有覆盖其基类中的某个虚函数，则该虚函数的用法与其他普通成员函数一样，派生类会直接继承基类中的版本。

C++11 新标准允许派生类显式地注明它使用某个成员函数覆盖了它继承的虚函数：在函数形参列表之后加 `override`。

派生类对象及派生类向基类的转换：一个派生类对象包含多个组成部分——派生类自己定义的（非静态）成员的子对象，以及一个与派生类继承的基类对应的子对象。因此 Bulk_quote 对象包含两部分：Quote 部分和 Bulk_quote 部分。

```
Bulk_quote 对象:
┌─────────────────────┐
│  Quote 部分          │ ← bookNo(私有不直接可访问), price(受保护)
├─────────────────────┤
│  Bulk_quote 部分     │ ← min_qty, discount
└─────────────────────┘
```

C++ 的这种继承方式称为「组合（composition）」：派生类对象由基类子对象和派生类自己的成员组成。

因为在派生类对象中含有与其基类对应的组成部分，所以我们能把派生类的对象当成基类对象来使用，而且我们也能将基类的指针或引用绑定到派生类对象中的基类部分上：

```cpp
Quote item;          // 基类对象
Bulk_quote bulk;     // 派生类对象
Quote *p = &item;    // p 指向 Quote 对象
p = &bulk;           // p 指向 bulk 的 Quote 部分
Quote &r = bulk;     // r 绑定到 bulk 的 Quote 部分
```

这种转换称为**派生类到基类的（derived-to-base）类型转换**。编译器会隐式地执行这种转换。

### 派生类构造函数

尽管在派生类对象中含有从基类继承而来的成员，但是派生类并不能直接初始化这些成员。与其他初始化基类成员的方式类似，派生类必须使用基类的构造函数来初始化它的基类部分。

每个类控制它自己的成员的初始化过程：派生类构造函数通过构造函数初始化列表来将实参传递给基类构造函数：

```cpp
Bulk_quote::Bulk_quote(const std::string &book, double p,
                       std::size_t qty, double disc) :
                       Quote(book, p), min_qty(qty), discount(disc) { }
```

首先初始化基类的部分，然后按照声明的顺序依次初始化派生类的成员。除非特别指明，否则派生类对象的基类部分会像数据成员一样执行默认初始化。

### 派生类使用基类成员

派生类可以访问基类的公有成员和受保护成员：

```cpp
// 如果达到购买书籍的某个最低限量值，就可以享受折扣
double Bulk_quote::net_price(std::size_t cnt) const {
    if (cnt >= min_qty)
        return cnt * (1 - discount) * price;  // 使用了基类的受保护成员 price
    else
        return cnt * price;
}
```

派生类只能通过派生类对象访问其基类的受保护成员，派生类对于一个基类对象中的受保护成员没有任何访问特权：

```cpp
class Bulk_quote : public Quote {
    double Bulk_quote::net_price(std::size_t cnt) const {
        // 正确: 派生类可以访问自己对象中的基类部分
        // 错误（示意）: 不能通过基类对象访问受保护成员
        // Quote base("xxx", 9.99); return base.price;
    }
};
```

### 继承与静态成员

如果基类定义了一个静态成员，则在整个继承体系中只存在该成员的唯一定义。不论从基类中派生出多少个派生类，对于每个静态成员来说都只存在唯一的实例：

```cpp
class Base {
public:
    static void statmem();
};
class Derived : public Base {
    void f(const Derived&);
};
void Derived::f(const Derived &derived_obj) {
    Base::statmem();      // 正确: Base 定义了 statmem
    Derived::statmem();   // 正确: Derived 继承了 statmem
    derived_obj.statmem();// 正确: 派生类的对象能使用基类的静态成员
    statmem();            // 正确: 隐式通过 this 访问
}
```

### 被用作基类的类

如果我们想将某个类用作基类，则该类必须已经定义而非仅仅声明：

```cpp
class Quote;              // 声明但未定义
// 错误: Quote 必须已经定义
class Bulk_quote : public Quote { /* ... */ };
```

一个类不能派生它本身（防止递归继承）。

### 防止继承的发生

C++11 提供了一种防止继承发生的方法：在类名后跟关键字 final：

```cpp
class NoDerived final { /* ... */ };   // NoDerived 不能作为基类
class Bad : public NoDerived { };      // 错误: NoDerived 是 final 的
```

### 类型转换与继承

理解基类和派生类之间的类型转换是理解 C++ 面向对象编程的关键所在。

**静态类型与动态类型**：

- 静态类型（static type）在编译时总是已知的，它是变量声明时的类型或表达式生成的类型。
- 动态类型（dynamic type）则是变量或表达式表示的内存中的对象的类型，直到运行时才可知。

如果表达式既不是引用也不是指针，则它的动态类型永远与静态类型一致。

不存在从基类向派生类的隐式类型转换：

```cpp
Quote base;
Bulk_quote* bulkP = &base;   // 错误: 不能将基类转换成派生类
Bulk_quote& bulkRef = base;  // 错误: 不能将基类转换成派生类
```

原因在于基类对象可能是派生类对象的一部分，也可能不是。即使转换合法，也存在问题：bulkP 的指针所指的 Quote 对象并没有 Bulk_quote 的成员。

派生类向基类的转换是否可访问由使用该转换的代码决定，同时派生类的基类部分中的成员能否访问也会影响转换。

当我们用一个派生类对象为一个基类对象初始化或赋值时，只有派生类对象中的基类部分会被拷贝、移动或赋值，它的派生类部分将被忽略掉（「切掉（sliced down/slicing）」问题）：

```cpp
Bulk_quote bulk;
Quote item(bulk);  // 使用 Quote::Quote(const Quote&) 构造函数
item = bulk;       // 使用 Quote::operator=(const Quote&)
// 上面的过程中 bulk 的 Bulk_quote 部分被忽略掉了
```

## 虚函数

因为有虚函数的动态绑定特性，我们可以编写具有以下性质的代码：程序既不清楚也无法得知调用者的类型，但程序运行时能正确执行。任意一个静态类型与动态类型不一致的例子必然与虚函数有关。

### 虚函数的调用必须有动态绑定特性

当我们使用基类的引用或指针调用一个虚函数时将发生动态绑定。直到运行时才会知道到底执行了哪个版本，被调用的函数是与绑定到指针或引用上的对象的动态类型匹配的那一个：

```cpp
Quote base("0-201-82470-1", 50);
print_total(cout, base, 10);    // 调用 Quote::net_price
Bulk_quote derived("0-201-82470-1", 50, 5, .19);
print_total(cout, derived, 10); // 调用 Bulk_quote::net_price
```

### 派生类中的虚函数

当派生类覆盖了某个虚函数时，该函数在基类中的形参必须与派生类中的形参严格匹配：

```cpp
class Quote {
public:
    virtual double net_price(std::size_t n) const;
};
class Bulk_quote : public Quote {
public:
    // 错误: 与基类中 net_price 的形参不匹配，实际上是一个新函数
    // double net_price(std::size_t n) const override; // 如果加 override 编译器会报错
};
```

加上 `override` 可以让编译器帮我们检查这种错误。

基类中的虚函数在派生类中隐式地也是虚函数。当派生类覆盖了某个虚函数时，该函数与基类中对应的虚函数的形参和返回类型必须完全一致（有一个例外：如果虚函数的返回类型是类本身的指针或引用，则派生类覆盖版本可以返回基类函数返回类型的派生类的指针或引用，即「协变返回类型」）。

### final和override说明符

override 说明符明确指出该函数覆盖了基类的虚函数，如果不存在这样的虚函数，则程序错误。

final 说明符（用在虚函数后）禁止后续的派生类覆盖该函数：

```cpp
struct D2 : D1 {
    // 该函数与 D1 中的 f(int) 不匹配
    // f(double) 是一个新的虚函数
    // double f(double) override; // 错误: 编译器检测到没有可供覆盖的函数
    // 正确: f(int) 覆盖了 D1::f(int)，且不能被后续的派生类覆盖
    double f(double) final;
};
```

### 虚函数与默认实参

虚函数可以拥有默认实参。如果通过基类的引用或指针调用函数，则使用基类中定义的默认实参，即使实际上运行的是派生类中的函数版本：

```cpp
class Quote {
public:
    virtual double net_price(std::size_t n = 10) const; // 默认实参为 10
};
class Bulk_quote : public Quote {
public:
    // 默认实参与基类不同，实际调用时使用基类的默认实参
    double net_price(std::size_t n = 20) const override; // 默认实参为 20
};
Bulk_quote bulk;
Quote *p = &bulk;
p->net_price(); // 实际调用 Bulk_quote::net_price(10)，使用基类的默认实参
```

因此，虚函数的默认实参最好与基类中保持一致。

### 回避虚函数的机制

某些情况下，我们希望对虚函数的调用不要进行动态绑定，而是强迫执行虚函数的某个特定版本。使用作用域运算符可以实现这一目的：

```cpp
// 强行调用 Quote 的 net_price 函数而不管 bulkP 的动态类型到底是什么
double undiscounted = bulkP->Quote::net_price(42);
```

通常情况下，只有成员函数（或友元）中的代码才需要使用作用域运算符来回避虚函数的机制。

## 抽象基类

假设我们想扩展书店程序，加入另一种折扣策略：购买量超过一定限额，其后购买的书打折扣。这两种策略的共同点是：都依赖于购买量且都受折扣书籍数量的影响。

我们可以将这些共同的特性定义为一个抽象基类 Disc_quote：

```cpp
// 当购买书籍的数量超过一定量时提供折扣
// 抽象基类：含有（或未经覆盖直接继承）纯虚函数的类
class Disc_quote : public Quote {
public:
    Disc_quote() = default;
    Disc_quote(const std::string& book, double price,
               std::size_t qty, double disc):
        Quote(book, price), quantity(qty), discount(disc) { }
    double net_price(std::size_t) const = 0; // 纯虚函数
private:
    std::size_t quantity = 0; // 折扣适用的购买量
    double discount = 0.0;    // 表示折扣的小数值
};
```

**纯虚函数（pure virtual function）**：在函数体的位置（声明语句的分号之前）书写 `= 0` 就可以将一个虚函数说明为纯虚函数。`= 0` 只能出现在类内部的虚函数声明语句处：

```cpp
double net_price(std::size_t) const = 0;
```

值得注意的是，我们也可以为纯虚函数提供定义，不过函数体必须写在类的外部（不能在类的内部、声明语句的分号之前）。

**含有纯虚函数的类是抽象基类（abstract base class）**：抽象基类只负责定义接口，后续的其他类可以覆盖该接口。我们不能（直接）创建一个抽象基类的对象：

```cpp
// Disc_quote 声明了纯虚函数，所以不能创建 Disc_quote 的对象
// Disc_quote discounted; // 错误: 不能定义 Disc_quote 的对象
Bulk_quote bulk;  // 正确: Bulk_quote 覆盖了 net_price
```

Disc_quote 的派生类必须给出 net_price 的定义，否则它们仍将是抽象基类。

我们可以将 Disc_quote 作为继承体系中其他类的基类，定义不同的折扣策略：

```cpp
// 当购买书籍的数量超过一定值时，整批书籍都享受折扣优惠
class Bulk_quote : public Disc_quote {
public:
    Bulk_quote() = default;
    Bulk_quote(const std::string& book, double,
               std::size_t, double);
    // 覆盖基类中的纯虚函数
    double net_price(std::size_t) const override;
};
```

重构（refactoring）：重新设计类的体系以便将公共操作提升到基类中，这个过程很常见。值得注意的是，重构会改变类的层次关系，但不会改变用户层面的代码。

## 访问控制与继承

每个类分别控制其成员对于派生类是否**可访问（accessible）**：

- protected：派生类的成员和友元可以访问受保护成员，但不能通过基类对象访问。
- 派生访问说明符（public、protected、private）控制派生类用户（包括派生类的派生类）对于基类成员的访问权限：

| 派生访问说明符 | 基类中的 public 成员在派生类中变为 | 基类中的 protected 成员在派生类中变为 |
| -------------- | ----------------------------------- | -------------------------------------- |
| public 继承    | public                              | protected                              |
| protected 继承 | protected                           | protected                              |
| private 继承   | private                             | private                                |

```cpp
class Base {
public:
    void pub_mem();
protected:
    int prot_mem;
private:
    char priv_mem;
};
struct Pub_Derv : public Base {
    // 正确: 派生类能访问 protected 成员
    int f() { return prot_mem; }
    // 错误: private 成员对于派生类不可访问
    // char g() { return priv_mem; }
};
struct Priv_Derv : private Base {
    // private 不影响派生类的访问权限
    int f1() const { return prot_mem; }
};
```

派生访问说明符对于派生类的成员（及友元）能否访问其直接基类的成员没什么影响。对基类成员的访问权限由基类本身的访问说明符控制；派生访问说明符的目的是控制**派生类用户**（包括其他派生类）对于基类成员的访问权限：

```cpp
Pub_Derv d1;      // 继承自 Base 的成员是 public 的
Priv_Derv d2;     // 继承自 Base 的成员是 private 的
d1.pub_mem();     // 正确: pub_mem 在派生类中是 public 的
// d2.pub_mem();  // 错误: pub_mem 在派生类中是 private 的
```

派生类向基类转换的可访问性（假定 D 继承自 B）：

- 只有当 D 公有地继承 B 时，用户代码才能使用派生类向基类的转换（d1 的例子）；私有继承或受保护的继承则不行。
- 不论 D 以什么方式继承 B，D 的成员函数和友元都能使用派生类向基类的转换。
- 如果 D 继承 B 的方式是公有的或者受保护的，则 D 的派生类的成员和友元可以使用派生类向基类的转换。

### 友元与继承

就像友元关系不能传递一样，友元关系同样不能继承。基类的友元在访问派生类成员时不具有特殊性，类似的，派生类的友元在访问基类成员时也不具有特殊性：

```cpp
class Base {
    friend class Pal; // Pal 在访问 Base 时没有限制
protected:
    int prot_mem; // protected 成员
};
class Pal {
public:
    int f(Base b) { return b.prot_mem; }  // 正确: Pal 是 Base 的友元
    // int f2(Sneaky s) { return s.j; }  // 错误: Pal 不是 Sneaky 的友元
};
```

### 改变个别成员的可访问性

有时我们需要改变派生类继承的某个名字的访问级别，通过使用 using 声明可以达到这一目的：

```cpp
class Base {
public:
    std::size_t size() const { return n; }
protected:
    std::size_t n;
};
class Derived : private Base {  // 注意: 私有继承
public:
    // 保持 size 和 n 的访问级别与基类中一致
    using Base::size;
protected:
    using Base::n;
};
```

派生类只能为那些它可以访问的名字提供 using 声明。

### 默认的继承保护级别

使用 class 关键字定义的派生类是私有继承的；使用 struct 关键字定义的派生类是公有继承的：

```cpp
class Base { /* ... */ };
struct D1 : Base { /* ... */ };   // 默认 public 继承
class D2 : Base { /* ... */ };    // 默认 private 继承
```

建议显式写出继承访问说明符，而不要依赖默认。

## 继承中的类作用域

每个类定义自己的作用域，派生类的作用域嵌套在基类的作用域之内。如果一个名字在派生类的作用域内无法正确解析，则编译器将继续在外层的基类作用域中寻找该名字的定义。

### 在编译时进行名字查找

一个对象、引用或指针的静态类型决定了该对象的哪些成员是可见的。即使静态类型与动态类型可能不一致（当使用基类的引用或指针时会发生这种情况），我们也能使用静态类型的成员：

```cpp
class Disc_quote : public Quote {
public:
    std::pair<size_t, double> discount_policy() const
        { return {quantity, discount}; }
    // ...
};
Bulk_quote bulk;
Bulk_quote *bulkP = &bulk;   // 静态类型与动态类型一致
Quote *itemP = &bulk;        // 静态类型与动态类型不一致
bulkP->discount_policy();    // 正确: bulkP 的类型是 Bulk_quote*
// itemP->discount_policy(); // 错误: itemP 的类型是 Quote*，Quote 中没有 discount_policy
```

### 名字冲突与继承

与其他作用域一样，派生类也能重用定义在其直接基类或间接基类中的名字，此时定义在内层作用域（派生类）的名字将隐藏定义在外层作用域（基类）的名字：

```cpp
struct Base {
    Base(): mem(0) { }
protected:
    int mem;
};
struct Derived : Base {
    Derived(int i): mem(i) { } // 用 i 初始化 Derived::mem
    // Base::mem 被 Derived::mem 隐藏
    int get_mem() { return mem; } // 返回 Derived::mem
protected:
    int mem; // 隐藏基类中的 mem
};
Derived d(42);
cout << d.get_mem() << endl; // 打印 42
```

### 通过作用域运算符来使用隐藏的成员

可以使用作用域运算符访问被隐藏的基类成员：

```cpp
struct Derived : Base {
    int get_base_mem() { return Base::mem; }
    // ...
};
```

除了覆盖继承而来的虚函数之外，派生类最好不要重用其他定义在基类中的名字。

### 名字查找先于类型检查

如前所述，声明在内层作用域的函数不会重载声明在外层作用域的函数，而是隐藏外层的函数。因此，定义派生类中的函数也不会重载其基类中的成员。如果派生类的成员与基类成员同名，则派生类将在其作用域内隐藏该基类成员：

```cpp
struct Base {
    int memfcn();
};
struct Derived : Base {
    int memfcn(int); // 隐藏基类的 memfcn（形参列表不同也不构成重载）
};
Derived d; Base b;
b.memfcn();       // 正确: 调用 Base::memfcn
d.memfcn(10);     // 正确: 调用 Derived::memfcn
// d.memfcn();    // 错误: 参数列表为空的 memfcn 被隐藏了
d.Base::memfcn(); // 正确: 显式调用 Base::memfcn
```

如果派生类希望使用基类的重载函数版本，可以通过 using 声明把基类中的函数引入派生类作用域：

```cpp
struct Derived : Base {
    using Base::memfcn; // using 声明把 Base 的所有 memfcn 版本引入 Derived
    int memfcn(int); // 在 Derived 中定义 memfcn 的新版本
};
d.memfcn();     // 正确: 调用 Base::memfcn
d.memfcn(10);   // 正确: 调用 Derived::memfcn
```

### 虚函数与作用域

虚函数的名字查找规则与普通函数一致，但虚函数的覆盖（override）要求函数名、形参列表和返回类型都匹配。如果基类与派生类的虚函数接受不同的实参，则派生类的函数将隐藏基类的函数，而不是覆盖它：

```cpp
class Base {
public:
    virtual int fcn();
};
class D1 : public Base {
public:
    int fcn(int);      // 形参列表与 Base 中的 fcn 不匹配，隐藏 Base::fcn（不是覆盖）
    virtual void f2(); // 新函数，与 Base 中的函数无关
};
class D2 : public D1 {
public:
    int fcn(int); // 覆盖 D1 的 fcn(int)，隐藏 Base::fcn()
    int fcn();    // 覆盖 Base 的虚函数 fcn
    void f2();    // 覆盖 D1 的虚函数 f2
};
```

通过基类调用被隐藏的虚函数将使用基类中的版本：

```cpp
Base bobj; D1 d1obj; D2 d2obj;
Base *bp1 = &bobj, *bp2 = &d1obj, *bp3 = &d2obj;
bp1->fcn(); // 虚调用，运行时调用 Base::fcn
bp2->fcn(); // 虚调用，运行时调用 Base::fcn（D1 没有覆盖 fcn()）
bp3->fcn(); // 虚调用，运行时调用 D2::fcn
D1 *d1p = &d1obj; D2 *d2p = &d2obj;
// bp2->f2(); // 错误: Base 没有 f2 成员
d1p->f2();   // 虚调用，运行时调用 D1::f2
d2p->f2();   // 虚调用，运行时调用 D2::f2
```

## 构造函数与拷贝控制

### 虚析构函数

基类通常应定义一个虚析构函数，这样我们就能动态分配继承体系中的对象了：

```cpp
class Quote {
public:
    // 虚析构函数，动态绑定析构函数
    virtual ~Quote() = default;
};
```

当我们 delete 一个动态分配的对象的指针时将执行析构函数。如果该指针（的静态类型）指向基类，则实际被执行的是与指针所指对象的动态类型绑定的析构函数版本：

```cpp
Quote *itemP = new Quote;   // 静态类型与动态类型相同
delete itemP;               // 调用 Quote 的析构函数
itemP = new Bulk_quote;     // 静态类型与动态类型不同
delete itemP;               // 调用 Bulk_quote 的析构函数（由于是虚函数）
```

如果基类的析构函数不是虚函数，则 delete 一个指向派生类对象的基类指针将产生未定义的行为。

一个基类一旦需要虚析构函数，它通常也需要拷贝控制（三/五法则）。

### 继承中的拷贝控制和构造函数

派生类的拷贝构造函数、移动构造函数、拷贝赋值运算符和移动赋值运算符必须首先拷贝/移动/赋值基类部分，然后再处理派生类自己的成员：

```cpp
class Base { /* ... */ };
class D : public Base {
public:
    // D 的拷贝构造函数必须显式调用 Base 的拷贝构造函数
    D(const D& d): Base(d) /*, D 的成员初始化 */ { }
    // D 的拷贝赋值运算符必须显式调用 Base 的拷贝赋值运算符
    D& operator=(const D &rhs) {
        Base::operator=(rhs); // 为派生类部分赋值
        // 为派生类的成员赋值
        return *this;
    }
    // D 的析构函数无须显式调用 Base 的析构函数
    ~D() { /* 释放派生类成员 */ } // Base 的析构函数自动执行
};
```

如果派生类的拷贝/移动构造函数没有显式地调用基类的对应函数，则基类部分将被默认初始化（而非拷贝）。

析构函数的执行顺序与构造函数相反：派生类析构函数首先执行，然后是基类的析构函数，依次沿继承体系的反侧进行。

### 继承的构造函数

派生类可以通过 using 声明语句直接继承基类的构造函数：

```cpp
class Bulk_quote : public Disc_quote {
public:
    Bulk_quote() = default;
    Bulk_quote(const std::string& book, double price,
               std::size_t qty, double disc):
        Disc_quote(book, price, qty, disc) { }
    // 继承基类的构造函数
    using Disc_quote::Disc_quote;
    // ...
};
```

using 声明语句令编译器生成代码：对于基类的每个构造函数，编译器都在派生类中生成一个形参列表完全相同的构造函数。这些编译器生成的构造函数形如：

```cpp
derived(parms) : base(args) { }
```

继承的构造函数与默认构造函数、拷贝/移动构造函数一样，如果派生类有自己的成员，这些成员将被默认初始化。

## 容器与继承

当我们使用容器存放继承体系中的对象时，通常必须采用间接存储方式（存放指针而非对象）。因为向容器中放入对象会发生「切掉」问题（派生类部分被忽略）：

```cpp
vector<Quote> basket;
basket.push_back(Quote("0-201-82470-1", 50));
// 正确，但是只把派生类的 Quote 部分拷贝进 basket
basket.push_back(Bulk_quote("0-201-82470-1", 50, 10, .25));
// 输出将使用 Quote::net_price，Bulk_quote 部分被丢弃了
cout << basket.back().net_price(20) << endl;
```

因为 basket 中存放的是 Quote 对象，所以派生类部分被忽略了。解决办法是存放指针（最好是智能指针）：

```cpp
vector<shared_ptr<Quote>> basket;
basket.push_back(make_shared<Quote>("0-201-82470-1", 50));
basket.push_back(
    make_shared<Bulk_quote>("0-201-82470-1", 50, 10, .25));
// 调用 Bulk_quote::net_price，输出 952（1000 的 75 折再乘以 20 本书）
cout << basket.back()->net_price(20) << endl;
```
