大型程序往往使用多个独立开发的库，其复杂度集中于：异常处理（错误在程序中传播的方式）和命名空间（协同工作的独立开发库之间的命名控制），以及多重继承。

## 异常处理

异常处理（exception handling）为程序中检测到的错误与处理该错误的代码之间的分离提供了支持。C++ 的异常处理包括：

- **throw 表达式（throw expression）**：异常检测部分使用 throw 表达式表示它遇到了无法处理的问题（throw 引发了异常）。
- **try 语句块（try block）**：异常处理部分使用 try 语句块处理异常。try 语句块以关键字 try 开始，并以一个或多个 catch 子句结束。try 语句块中代码抛出的异常通常会被某个 catch 子句处理。因为 catch 子句「处理」异常，所以它们也被称为**异常处理代码（exception handler）**。
- **一套异常类（exception classes）**：用于在 throw 表达式和相关的 catch 子句之间传递异常的具体信息。

```cpp
// 这段代码演示了 throw 表达式和 try/catch 块
throw runtime_error("Data must refer to same ISBN");
// 或
if (item1.isbn() != item2.isbn())
    throw runtime_error("Data must refer to same ISBN");

try {
    program-statements
} catch (exception-declaration) {
    handler-statements
} catch (exception-declaration) {
    handler-statements
} // ...
```

编写处理代码时，应该为不同类型的异常定义不同的 catch 子句。当 try 中的语句抛出异常时，系统按 catch 子句出现的顺序依次检查每个 catch 的异常声明，找到第一个匹配的 catch 执行；如果没有找到匹配的 catch，程序转到外层 try 或终止执行。

栈展开（stack unwinding）：当抛出一个异常后，程序暂停当前函数的执行过程并立即开始寻找与异常匹配的 catch 子句。当 catch 出现在主函数之外时（退出主函数），程序转到标准库函数 terminate 的执行，终止程序的执行。

在栈展开的过程中，运行退出函数的局部对象的析构函数会自动执行（如果块中局部对象需要释放，释放由析构函数完成）。但如果块中是内置类型指针管理的动态内存，栈展开时不会释放（这就是为什么应该使用类类型而不是内置指针管理资源的原因）。

析构函数与异常：析构函数在栈展开的过程中执行，因此它不应该抛出自己的异常（一旦在栈展开过程中析构函数抛出异常且未被捕获，程序将被终止）。析构函数中如果执行可能抛出异常的操作，应该放在 try 语句块中并进行局部处理。

异常对象（exception object）是一种特殊对象，编译器使用异常抛出表达式来对异常对象进行拷贝初始化。异常对象位于独立的内存空间中，与任何函数的局部对象都不在一起。如果我们抛出一个表达式，该表达式的静态编译类型决定了异常对象的类型（如 throw 时抛出的 const char* 会被转换为对应的异常对象）。

### 抛出异常

throw 表达式遵循与其他表达式一样的类型转换规则：抛出的对象必须有可访问的析构函数和拷贝构造函数（异常对象会被拷贝）。

抛出指针通常是一种坏想法：抛出指针要求在任何对应的处理代码存在的地方，指针所指向的对象必须一直存在。

### 捕获异常

catch 子句中的异常声明（exception declaration）看起来像只包含一个形参的函数形参列表。声明的类型决定了处理代码能够捕获的异常种类。

如果 catch 无须访问抛出的表达式，我们可以忽略捕获对象的名字（省略形参名）：`catch(const runtime_error&) { }`。

通常情况下，如果 catch 的异常声明是「非 const 引用」类型，则该 catch 可以修改它所匹配的异常对象，但实际上很少这样做。

查找匹配 catch 的规则：

- 异常声明是基类的引用或指针时，可以匹配派生类对象的异常（catch(const exception&) 可以捕获所有从 exception 派生的异常类型）。
- 非引用类型的异常声明会对异常对象进行拷贝。
- 异常声明的类型必须与抛出对象的类型完全匹配（除了以下几种「允许的转换」：非 const 到 const 的转换、派生类到基类的转换、数组/函数到指针的转换）。
- 与函数匹配不同，catch 匹配过程中不允许算术类型转换和类类型转换。

异常声明的匹配除了少数几种区别之外，要求异常的类型与 catch 严格匹配：

- 允许从非常量向常量类型的转换（非常量对象可以匹配 const 引用的 catch）。
- 允许从派生类到基类的转换。
- 数组或函数被转换成对应的指针。

Catch 重新抛出：有时一个单独的 catch 不能完整地处理某个异常。在执行了某些校正操作之后，catch 可以将异常传递给另一个 catch 子句，通过重新抛出（rethrow）操作实现。重新抛出语句形式是不含表达式的 throw：

```cpp
catch (my_error &eObj) {          // 引用类型
    eObj.status = errCodes::severeErr; // 修改了异常对象
    throw;                         // 异常对象的 status 成员是 severeErr
} catch (other_error eObj) {       // 非引用类型
    eObj.status = errCodes::badErr; // 只修改了异常对象的局部拷贝
    throw;                         // 异常对象的 status 成员未改变
}
```

空的 throw 语句只能出现在 catch 语句块内部或 catch 语句块直接或间接调用的函数中。如果在处理代码之外遇到空 throw，编译器将执行 terminate。

### 捕获所有异常的catch子句

用 `catch(...)` 可以捕获所有异常，它通常与重新抛出语句一起使用，完成当前能做的局部处理工作，然后将异常传递给上层：

```cpp
void manip() {
    try {
        // 这里的操作可能引发异常
    } catch (...) {
        // 处理异常的某些特殊方面
        throw; // 将异常传递给另一个处理代码
    }
}
```

catch(...) 既能匹配内置类型的异常也能匹配类类型的异常。

### 函数try语句块与构造函数

通常情况下，程序发生异常时，异常之前的局部变量的析构函数会自动执行。但构造函数在进入函数体之前执行成员初始化，如果构造函数的初始化列表中的表达式抛出异常，构造函数体内的 try 语句块无法处理（尚未进入函数体）。

函数 try 语句块（function try block）可以解决此问题：

```cpp
template <typename T>
Blob<T>::Blob(std::initializer_list<T> il) try :
    data(std::make_shared<std::vector<T>>(il)) {
    // 空函数体
} catch(const std::bad_alloc &e) {
    handle_out_of_memory(e);
}
```

关键字 try 出现在构造函数初始化列表之前（表示 try 块覆盖函数体和初始化列表），处理代码写在函数的 catch 子句中。

### noexcept异常说明符

通常情况下，无法确定一个函数是否会抛出异常。C++11 中，可以通过 noexcept 说明（noexcept specification）指定某个函数不会抛出异常：

```cpp
void recoup(int) noexcept;   // 不抛出异常
void alloc(int);             // 可能抛出异常
```

noexcept 说明符必须出现在函数的所有的尾置返回类型之后。noexit 说明要么出现在函数的所有声明语句和定义语句中，要么一次也不出现。

noexcept 说明符可以接受一个可转换为 bool 的表达式：`noexcept(cond)`，cond 为 true 时表示不抛出异常。

noexcept 运算符：noexcept 是一个一元运算符，返回一个 bool 类型的常量表达式，用于表示给定的表达式是否被声明为不会抛出异常：

```cpp
void f() noexcept;
void g() noexcept(noexcept(f)); // g 不抛出异常当且仅当 f 不抛出异常
void h(); // h 可能抛出异常
noexcept(g()); // 返回 true: g 被声明为不会抛出异常
noexcept(h()); // 返回 false: h 没有异常说明
```

noexcept 有两种含义：当跟在函数参数列表后面时它是异常说明符；当作为 noexcept 表达式的一部分时它是运算符。

违反异常说明的后果：如果一个函数在承诺了 noexcept 后实际上抛出了异常，程序会调用 terminate（违反 noexcept 说明的异常不会被捕获处理）。

 noexcept 在「函数指针及虚函数」中的使用：

- 基类中的虚函数承诺了 noexcept，其派生类中的覆盖函数也必须承诺 noexcept。
- 编译器不会强制要求函数指针的 noexcept 说明与赋给它的函数的说明一致（但推荐保持一致）。

### 异常类层次

标准库异常类定义在四个头文件中：

- `exception` 头文件定义了最通用的异常类 exception。它只报告异常的产生，不提供任何额外信息。
- `stdexcept` 头文件定义了几种常用的异常类：

| 异常类             | 含义                                     |
| ------------------ | ---------------------------------------- |
| exception          | 最常见的问题                             |
| runtime_error      | 只有在运行时才能检测出的错误              |
| range_error        | 运行时错误：生成的结果超出了有意义的值域   |
| overflow_error     | 运行时错误：计算上溢                     |
| underflow_error    | 运行时错误：计算下溢                     |
| logic_error        | 程序逻辑错误                             |
| domain_error       | 逻辑错误：参数对应的结果值不存在          |
| invalid_argument   | 逻辑错误：无效参数                       |
| length_error       | 逻辑错误：试图创建一个超出该类型最大长度的对象 |
| out_of_range       | 逻辑错误：使用一个超出有效范围的值        |

- `new` 头文件定义了 bad_alloc 异常类型。
- `type_info` 头文件定义了 bad_cast 异常类型。

标准库异常类只定义了少数几个成员。我们可以将 exception 类型的异常对象初始化或赋值为其他任意异常对象（标准库异常类的拷贝控制成员是 const 的）。异常类型只定义了一个名为 what 的虚成员函数，它没有任何参数，返回值是一个指向 C 风格字符串（const char*）的指针，用于提供关于异常的一些文本信息。

应用程序可以自定义继承自 exception（或其他标准库异常类型）的类来扩展异常层次：

```cpp
// 为某书店应用程序定义的特定异常类型，继承自 stdexcept 中的异常类型
class out_of_stock : public std::runtime_error {
public:
    explicit out_of_stock(const std::string &s):
        std::runtime_error(s) { }
};
class isbn_mismatch : public std::logic_error {
public:
    explicit isbn_mismatch(const std::string &s):
        std::logic_error(s) { }
    isbn_mismatch(const std::string &s,
                  const std::string &lhs, const std::string &rhs):
        std::logic_error(s), left(lhs), right(rhs) { }
    const std::string left, right;
};
```

由于异常类层次的使用方式与其他继承体系相同，我们可以将一个派生类的异常对象抛出，由一个接受基类引用的 catch 捕获。

## 命名空间

大型应用程序往往会使用多个独立开发的库，其中的名字难免发生冲突。命名空间（namespace）为防止名字冲突提供了更加可控的机制。

### 命名空间定义

命名空间以关键字 namespace 开始，后接命名空间的名字，接一系列由花括号括起来的声明和定义：

```cpp
namespace cplusplus_primer {
    class Sales_data { /* ... */ }; // Sales_data 是 cplusplus_primer 的成员
    Sales_data operator+(const Sales_data&, const Sales_data&);
    class Query { /* ... */ };
    class Query_base { /* ... */ };
}
```

命名空间既可以定义在全局作用域内，也可以定义在其他命名空间中，但不能定义在函数或类的内部。

命名空间中名字的作用域规则与类的作用域规则相同：命名空间中定义的名字可以被该命名空间中的其他成员直接访问（包括嵌套作用域中的成员）。命名空间外部的代码必须使用限定名（qualified name）来访问：

```cpp
cplusplus_primer::Query q = cplusplus_primer::Query("hello");
```

命名空间可以是不连续的：命名空间可以定义在几个部分中。前面的代码定义了名为 cplusplus_primer 的命名空间的一部分，之后的代码可以重新打开该命名空间继续定义：

```cpp
namespace cplusplus_primer {
    // ...
}
```

命名空间中名字的声明和定义可以分开：如果命名空间中的一个名字没有在命名空间内部定义，则必须显式指出名字所属的命名空间：

```cpp
namespace cplusplus_primer {
    // ...
    class Query;
}
// 命名空间外部定义 Query
cplusplus_primer::Query::Query(std::ostream &os) { /* ... */ }
```

### 嵌套的命名空间

命名空间可以嵌套：

```cpp
namespace cplusplus_primer {
    // 第一个嵌套的命名空间: 定义库的 Query 部分
    namespace QueryLib {
        class Query { /* ... */ };
        Query operator&(const Query&, const Query&);
    }
    // 第二个嵌套的命名空间: 定义库的 bookstore 部分
    namespace Bookstore {
        class Quote { /* ... */ };
        class Disc_quote : public Quote { /* ... */ };
    }
}
```

内层命名空间中的名字会隐藏外层命名空间中的同名名字。嵌套命名空间中成员的名字由外层命名空间的名字和内层命名空间的名字共同限定：

```cpp
cplusplus_primer::QueryLib::Query
```

### 内联命名空间

C++11 新标准引入了**内联命名空间（inline namespace）**：内联命名空间中的名字可以被外层命名空间直接使用：

```cpp
namespace fifthEd { // fifthEd 内联地定义在 cplusplus_primer 中
    inline namespace FifthEd {
        class Query_base { /* ... */ };
    }
}
```

内联命名空间常用于版本控制：当应用程序从一个版本的代码切换到另一个版本时，无须改变代码（如通过外层命名空间直接引用内联命名空间的成员）。

### 未命名的命名空间

未命名的命名空间（unnamed namespace）是指关键字 namespace 后紧跟花括号括起来的声明和定义，省略了命名空间的名字：

```cpp
namespace {
    int i; // i 只在本文件中可见
    // ...
}
```

未命名的命名空间中定义的变量拥有静态生命周期：它们在第一次使用前创建，程序结束时销毁。

一个未命名的命名空间可以在某个给定的文件内不连续，但不能跨越多个文件。其定义于所有花括号之外的名字（即文件作用域中的名字）对于该文件是可见的，但不能在其他文件中访问（类似于 static 关键字的文件级声明作用）。未命名的命名空间取代了文件中的静态声明。

### 使用命名空间的成员

使用 using 声明（using declaration）和 using 指示（using directive）可以简化命名空间成员的使用。

一个 using 声明（using declaration）一次只引入命名空间的一个成员：

```cpp
using namespace_name::name; // 例如 using std::cin;
```

一个 using 指示（using directive）使得某个特定命名空间中的所有名字都可见：

```cpp
using namespace_name; // 例如 using namespace std;
```

using 声明的名字从 using 声明语句开始直到包含该 using 声明语句的作用域结束时为止都有效，并且在外层作用域中可见。

在局部作用域中使用 using 声明：在函数内部（可以是局部作用域）使用的 using 声明将名字引入到局部作用域中，可以像使用其他局部变量一样使用。

头文件中的 using 声明或指示会将名字「泄漏」到包含该头文件的文件中，因此头文件最多只在它的全局作用域（或嵌套作用域）中使用 using 声明。

一个例子，假定命名空间和程序的形式如下：

```cpp
namespace blip {
    int i = 16, j = 15, k = 23;
    // 其他声明
}
int j = 0; // 正确: j 和 blip::j 在不同的作用域中
void manip() {
    // using 指示: blip 中的名字被「添加」到全局作用域中
    using namespace blip; // 如果与全局名字冲突，则使用时必须明确指出
    ++i;       // 正确: blip::i（全局作用域中没有 i）
    ++::j;     // 正确: 全局的 j（若不使用限定符，则二义性）
    // ++blip::j; // 正确: blip::j
}
```

当使用 using 指示注入一个命名空间的所用名字后，如果与全局名字冲突，不会直接报错，使用时才会检测出二义性错误。

### 类、命名空间与作用域

对命名空间内部名字的名字查找（name lookup）遵循常规的查找规则：

```cpp
namespace A {
    int i;
    int k;
    class C1 {
    public:
        C1() = default;             // 默认构造函数
        C1(int ii): i(ii) { }       // 内部使用 C1::i
        int i;
        // ...
    };
}
```

名字查找是在编译时进行的，这一规则有个有趣的副作用：运算符的函数查找机制。当编译器发现一个像 operator+ 这样的运算符调用时：

```cpp
std::string s;
std::cin >> s;
```

第一步: `operator>>(std::istream&, std::string&)`；第二步: 编译器查找 operator>>，它通过「实参相关的查找（argument-dependent lookup，ADL，又称 Koenig 查找）」在实参所属的命名空间中查找。上述例子中，operator>> 定义在 std 命名空间中，而实参 std::cin 和 s 也属于 std 命名空间，因此无需显式的 std:: 限定即可找到该运算符。

友元声明与实参相关的查找：一个另外的命名空间中的类或函数的友元声明（即使未在别处声明）会把外围类的名字加到该类（或函数）所属的命名空间中：

```cpp
namespace A {
    class C {
        // 友元声明在命名空间 A 中「声明」了 f2 和 f3
        friend void f2();                 // 与 f2 一起声明在 A 中
        friend void f(const C&);          // 与 f 一起声明在 A 中
    };
    // f2 必须在 A 中的其他地方声明
}
```

### 重载与命名空间

using 声明或 using 指示可以将函数添加到候选函数集合中：

- using 声明引入的函数与 using 声明所在的声明区域中原有的函数重载。
- using 指示将命名空间中的所有函数声明都提升到外层作用域中。

## 多重继承与虚继承

### 多重继承

多重继承（multiple inheritance）是指一个派生类可以从多个基类继承：

```cpp
class Bear : public ZooAnimal { /* ... */ }; // Bear 继承 ZooAnimal
class Raccoon : public ZooAnimal { /* ... */ }; // Raccoon 继承 ZooAnimal
// Panda 同时继承 Bear 和 Endangered
class Panda : public Bear, public Raccoon, public Endangered {
    /* ... */
};
```

多重继承的派生类对象包含每个基类对应的子对象。Panda 对象包含 Bear 部分（其中又包含 ZooAnimal 部分）、Raccoon 部分（其中又包含 ZooAnimal 部分）和 Endangered 部分。

派生类构造函数的初始化列表中使用逗号分隔的基类列表，基类的构造顺序与派生列表中基类的出现顺序保持一致（与初始化列表中的顺序无关）：

```cpp
Panda::Panda(std::string name, int on_off_flag)
    : Bear(name, on_off_flag),
      Raccoon(name, on_off_flag),
      Endangered(Endangered::critical),
      sleeping_flag(false) { }
```

构造顺序：ZooAnimal（ Bear 的基类）→ Bear → Raccoon → Endangered → Panda。

多重继承下派生类到基类的转换：派生类的指针或引用可以转换为其任意一个基类的指针或引用：

```cpp
void print(const Bear&);
void highlight(const Endangered&);
ostream& operator<<(ostream&, const ZooAnimal&);
Panda ying_yang("ying_yang");
print(ying_yang);     // 把 ying_yang 隐式地转换为 Bear
highlight(ying_yang); // 把 ying_yang 隐式地转换为 Endangered
cout << ying_yang << endl; // 把 ying_yang 隐式地转换为 ZooAnimal
```

在多重继承中，当两个基类中存在同名成员时，直接访问会产生二义性，必须通过作用域运算符显式指定：

```cpp
// 假定 Bear 和 Raccoon 都定义了 max_weight 成员
// double d = ying_yang.max_weight(); // 错误: 二义性
double d1 = ying_yang.Bear::max_weight();
double d2 = ying_yang.Raccoon::max_weight();
```

### 虚继承

在默认情况下，派生类中含有基类的一个拷贝。如 Panda 继承 Bear 和 Raccoon，而两者都继承 ZooAnimal，则 Panda 中含有 ZooAnimal 的两份拷贝（通过 Bear 的路径和通过 Raccoon 的路径）。

虚继承（virtual inheritance）使得某个类做出声明，承诺愿意共享它的基类。共享的基类子对象称为**虚基类（virtual base class）**。在这种机制下，不论虚基类在继承体系中出现了多少次，派生类中都只含有该类的一个子对象：

```cpp
// 关键字 public 和 virtual 的顺序随意
class Raccoon : public virtual ZooAnimal { /* ... */ };
class Bear : virtual public ZooAnimal { /* ... */ };
// Panda 通过 Bear 和 Raccoon 继承 ZooAnimal，
// 但 Panda 中只有一个共享的 ZooAnimal 子对象
class Panda : public Bear, public Raccoon, public Endangered {
    /* ... */
};
```

虚继承的其他方面与普通继承相同。

### 虚基类成员的可见性与构造

虚继承中的名字查找规则与非虚继承相同：首先在派生类中查找，然后沿继承路径向上查找（通过多条路径访问同名成员时会有二义性）。

虚继承中的一个重要细节：虚基类的构造函数由「最底层的派生类（most derived class）」直接初始化。在虚派生中，虚基类是由最低层的派生类初始化的：

```cpp
Panda::Panda(std::string name, int on_off_flag)
    : ZooAnimal(name, on_off_flag), // 直接初始化虚基类
      Bear(name, on_off_flag),
      Raccoon(name, on_off_flag),
      Endangered(Endangered::critical),
      sleeping_flag(false) { }
```

当创建一个 Panda 对象时，Panda 是最底层的派生类，由它负责初始化 ZooAnimal 部分（即使 ZooAnimal 不是 Panda 的直接基类）。创建 Bear（或 Raccoon）的独立对象时，它们自己是最底层派生类，由它们初始化 ZooAnimal。中间的派生类对虚基类的初始化被忽略（仅当作为最低层派生类时其初始化才生效）。

虚基类的构造顺序：首先使用提供给最低层派生类构造函数的初始值初始化该类的虚基类子对象，然后按照直接基类在派生列表中出现的顺序依次初始化（无论虚基类在继承层次中位置多深，总是先于非虚基类构造）。
