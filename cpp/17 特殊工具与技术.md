本章介绍一些较少使用的语言特性，它们适用于某些特殊问题，而非日常编程。

## 控制内存分配

某些应用程序需要自定义内存分配的细节，如自定义分配池或回收池，或者需要追踪 new/delete 的调用。

### 重载new和delete

当使用 new 表达式时：

```cpp
string *sp = new string("a value"); // 分配并初始化一个 string
string *arr = new string[10];       // 分配 10 个默认初始化的 string
```

实际执行了三步操作：

1. new 表达式调用名为 `operator new`（或 `operator new[]`）的标准库函数，分配一块足够大的、原始的、未命名的内存空间以便存储特定类型的对象（或对象数组）。
2. 编译器运行相应的构造函数以构造这些对象，并为其传入初始值。
3. 对象被分配了空间并构造完成，返回一个指向该对象的指针。

当使用 delete 表达式时：

```cpp
delete sp;    // 销毁 *sp，然后释放 sp 所指的内存空间
delete [] arr; // 销毁数组中的元素，然后释放对应的内存空间
```

实际执行了两步操作：

1. 对 sp 所指的对象或者 arr 所指的数组中的元素执行对应的析构函数。
2. 编译器调用名为 `operator delete`（或 `operator delete[]`）的标准库函数释放内存空间。

如果应用程序希望控制内存分配过程，则可以定义自己的 operator new 和 operator delete 函数。此时编译器不会使用标准库版本，而使用我们自定义的版本。

当编译器找到自定义的 operator new 时，将执行我们所期望的操作：先调用 operator new 分配内存，然后调用构造函数；delete 时先执行析构函数，然后调用 operator delete 释放内存。

operator new 和 operator delete 是标准库函数，因此我们可以像重载普通函数一样重载它们（但规则更严格）。它们必须位于全局作用域或类作用域中：

```cpp
// 这些版本可能抛出 bad_alloc 异常
void *operator new(size_t);             // 分配一个对象
void *operator new[](size_t);           // 分配一个数组
void *operator delete(void*) noexcept;  // 释放一个对象
void *operator delete[](void*) noexcept; // 释放一个数组
// 这些版本承诺不抛出异常（配合 nothrow new 使用）
void *operator new(size_t, void*);      // 定位 new，分配一个对象
void *operator new[](size_t, void*);    // 定位 new，分配一个数组
void *operator delete(void*, void*) noexcept;
void *operator delete[](void*, void*) noexcept;
```

operator new 和 operator delete 接口：其中 size_t 形参是必须的，其值表示存储给定类型对象所需的字节数。operator new 和 operator delete 返回 void*，operator delete 返回 void。

重载的 operator new 和 operator delete 函数隐式地是静态的（static），无须显式声明 static（它们只负责内存的分配和释放，不涉及对象本身，因此不需要 this 指针）。它们位于类中时是静态成员函数，且不会操纵所属类的任何数据成员。

### malloc和free

operator new 和 operator delete 的一种简单实现是使用 malloc 和 free：

```cpp
void *operator new(size_t size) {
    if (void *mem = malloc(size))
        return mem;
    else
        throw bad_alloc();
}
void operator delete(void *mem) noexcept { free(mem); }
```

### 定位new表达式

定位 new（placement new）表达式是 operator new 的一种特殊形式，它允许我们在分配内存时提供额外的信息（一般用于在预先分配的内存中构造对象）：

```cpp
new (place_address) type
new (place_address) type (initializers)
new (place_address) type [size]
new (place_address) type [size] { braced initializer list }
```

其中 place_address 必须是一个指针，同时使用初始化器提供的初始值来初始化对象。定位 new 并不「分配」内存，它只是构造对象。

定位 new 与 allocator 类的 construct 成员类似（见第 12 章），可以在给定的内存位置构造对象。

调用析构函数：与调用构造函数不同，我们可以直接调用对象的析构函数（但很少需要这样做，通常用于定位 new 构造的对象，配合共享内存等场景）：

```cpp
string *sp = new string("a value"); // 分配并初始化一个 string 对象
sp->~string();                       // 调用析构函数，但不释放内存
```

## 运行时类型识别

运行时类型识别（run-time type identification，RTTI）的功能由两个运算符实现：

- **typeid 运算符**：用于返回表达式的类型。
- **dynamic_cast 运算符**：用于将基类的指针或引用安全地转换成派生类的指针或引用。

这些运算符用于以下场景：当我们想使用基类对象的指针或引用执行某个派生类操作并且该操作不是虚函数时。一般来说，应该尽量使用虚函数，只有当无法使用虚函数时才使用 RTTI。

### dynamic_cast运算符

dynamic_cast 的形式：

```cpp
dynamic_cast<type*>(e)   // e 必须是一个有效的指针
dynamic_cast<type&>(e)   // e 必须是一个左值
dynamic_cast<type&&>(e)  // e 不能是左值
```

其中 type 必须是一个类类型，并且（通常情况下）含有虚函数。e 的类型必须符合以下三个条件之一：e 是 type 的公有派生类、e 是 type 的公有基类、e 与 type 的类型相同。如果转换成功，返回转换后的类型；否则：

- 指针类型：转换失败，结果为 0（空指针）。
- 引用类型：转换失败，抛出 std::bad_cast 异常（因为没有空引用）。

指针形式的 dynamic_cast：

```cpp
// bp 是否指向一个 Derived 对象？
if (Derived *dp = dynamic_cast<Derived*>(bp)) {
    // 使用 dp 指向的 Derived 对象
} else {
    // 使用 bp 指向的 Base 对象
}
```

在条件部分执行 dynamic_cast 可以确保转换操作和结果检查在同一条表达式中完成。

引用形式的 dynamic_cast：

```cpp
void f(const Base &b) {
    try {
        const Derived &d = dynamic_cast<const Derived&>(b);
        // 使用 b 引用的 Derived 对象
    } catch (const bad_cast &e) {
        // 处理类型转换失败的情况
    }
}
```

### typeid运算符

typeid 运算符（type info 头文件中）允许我们向程序询问一个表达式的类型：`typeid(e)`，其中 e 可以是任意表达式或类型的名字。typeid 操作的结果是一个常量对象的引用，该对象的类型是标准库类型 type_info（或其公有派生类型）。

typeid 可以作用于任意类型的表达式。顶层 const 被忽略；如果表达式是一个引用，则 typeid 返回该引用所引对象的类型；当 typeid 作用于数组或函数时，不会执行向指针的标准类型转换（数组不会退化为指针）。

当运算对象不属于类类型或者是一个不包含任何虚函数的类时，typeid 指出运算对象的静态类型；当运算对象是定义了至少一个虚函数的类的左值时，typeid 的结果直到运行时才会求得。

使用 typeid 运算符：

```cpp
Derived *dp = new Derived;
Base *bp = dp; // 两个指针都指向 Derived 对象

// 在运行时比较两个对象的类型
if (typeid(*bp) == typeid(*dp)) {
    // bp 和 dp 指向同一类型的对象
}
// 检查 bp 是否指向一个 Derived 对象
// 注意: 运行时才会执行类型检查
if (typeid(*bp) == typeid(Derived)) {
    // bp 实际指向一个 Derived 对象
}
```

注意 `typeid(*bp)` 与 `typeid(bp)` 的区别：前者返回 bp 所指对象的动态类型，后者返回 bp 的静态类型（Base*）：

```cpp
// 下面的检查永远是错误的: typeid(bp) 返回 Base*
if (typeid(bp) == typeid(Derived)) { /* ... */ } // 永远不会为 true
```

当 typeid 解引用一个空指针时，若其指针指向的类含有虚函数，则抛出 std::bad_typeid 异常。

type_info 类没有默认构造函数，它的拷贝和赋值运算符都被定义成删除的，因此我们无法定义或拷贝 type_info 类型的对象，只能通过 typeid 运算符返回它的引用。type_info 定义了 `==` 和 `!=` 运算符以及一个 name 成员函数（返回一个 C 风格字符串，表示类型名字的可打印形式，不同编译器返回的格式可能不同）：

```cpp
int arr[10];
Derived d;
Base *p = &d;
cout << typeid(42).name() << ", "
     << typeid(arr).name() << ", "
     << typeid(Sales_data).name() << ", "
     << typeid(std::string).name() << ", "
     << typeid(p).name() << ", "
     << typeid(*p).name() << endl;
```

一个使用 RTTI 的经典场景：为具有继承关系的类实现相等运算符。两个对象相等当且仅当它们的类型相同且对应的成员相等。此时 virtual 函数无法完成类型检查，需要用 typeid：

```cpp
class Base {
    friend bool operator==(const Base&, const Base&);
public:
    // Base 的接口成员
protected:
    virtual bool equal(const Base&) const;
    // Base 的数据成员和其他用于实现的成员
};
class Derived : public Base {
    // Derived 的接口成员
protected:
    bool equal(const Base&) const;
    // Derived 的数据成员和其他用于实现的成员
};

bool operator==(const Base &lhs, const Base &rhs) {
    // 如果 typeid 不相同则返回 false；否则调用 equal
    return typeid(lhs) == typeid(rhs) && lhs.equal(rhs);
}
bool Derived::equal(const Base &rhs) const {
    // 我们已经检查过这两个对象的类型相同，因此转换不会抛出异常
    auto r = dynamic_cast<const Derived&>(rhs);
    // 执行比较 Derived 对象的操作
    // ...
}
```

## 枚举类型

枚举类型（enumeration）使我们可以将一组整型常量组织在一起。C++ 包含两种枚举：限定作用域的（scoped）和不限定作用域的（unscoped）。

C++11 引入了**限定作用域的枚举（scoped enumeration）**，使用关键字 enum class（或 enum struct）：

```cpp
enum class open_modes { input, output, append };
```

**不限定作用域的枚举（unscoped enumeration）**省略掉 class（或 struct）：

```cpp
enum color { red, yellow, green };
enum stopLight { red, yellow, green }; // 错误: 重复定义了枚举成员 red 等
// enum class peppers { red, yellow, green }; // 正确: 限定作用域的枚举成员不会与外层作用域的名字冲突
```

不限定作用域的枚举的枚举成员（enumerator）的作用域与枚举类型本身的作用域相同，而限定作用域的枚举的成员名字一般规则：它们遵循通常的作用域准则，在枚举类型的作用域外不可访问：

```cpp
enum class open_modes { input, output, append };
// open_modes::input 是限定作用域的枚举成员的访问方式
int i = color::red;   // 正确: 不限定作用域枚举的成员可以像枚举类型名字一样使用
int j = red;          // 同上（不限定作用域枚举成员可直接访问）
// int k = input;     // 错误: input 不在作用域内
int l = open_modes::input; // 正确: 使用作用域运算符访问限定作用域枚举的成员
```

枚举成员：默认情况下枚举值从 0 开始，依次加 1。可以显式地提供枚举成员的值，且值不必唯一：

```cpp
enum class intTypes {
    charTyp = 8, shortTyp = 16, intTyp = 16,
    longTyp = 32, long_longTyp = 64
};
enum class intTypes2 { charTyp = 8, shortTyp = 16, intTyp = 16 }; // 与 intTypes 是不同的类型
```

枚举成员是 const 的，初始化枚举成员时所需的初始值必须是常量表达式（字面值常量或其他枚举成员），因此枚举成员本身是常量表达式，可以用在需要常量表达式的地方（如数组的维度）：

```cpp
constexpr intTypes charbits = intTypes::charTyp; // ok
```

与不限定作用域的枚举不同，限定作用域的枚举的枚举成员在需要 int 的地方不会被隐式转换（可以避免意外转换）：

```cpp
int i = color::red;   // 不限定作用域的枚举成员隐式转换成 int，正确
// int j = peppers::red; // 错误: peppers 的枚举成员不会隐式地转换成 int
```

指定 enum 的大小：可以在 enum 的名字后加上冒号以及我们指定的类型（C++11）：

```cpp
enum salts : unsigned long long {
    sodium_cl, potassium_cl // 枚举成员是 unsigned long long 类型
};
// 限定作用域的枚举类型默认使用 int 作为默认类型
enum class intTypes3 : int64_t { /* ... */ }; // 显式指定
```

枚举类型的前置声明：可以声明但不定义 enum，但必须指定成员的大小（限定作用域的枚举默认为 int，无须指定）：

```cpp
enum intValues : unsigned long long; // 不限定作用域的枚举，前置声明必须指定成员类型
enum class open_modes2;              // 限定作用域的枚举，默认 int，无须指定
```

enum 的声明和定义必须匹配：所有声明和定义中枚举成员的类型必须一致，且不能在同一上下文中先声明一个不限定作用域的枚举名字、再声明同名的限定作用域的枚举。

形参匹配与枚举类型：接受枚举类型形参的函数只能用该枚举类型的对象或其成员作为实参（整数不会被转换成枚举类型），这也是有时需要为枚举类型提供重载版本的原因。

## 类成员指针

成员指针（pointer to member）是指可以指向类的非静态成员的指针。一般情况下，指针指向对象，但是成员指针指示的是类的成员，而不是类的对象。成员指针的类型也包括类的类型和成员的类型。

### 数据成员指针

定义成员指针时必须包含成员所属的类：

```cpp
// pdata 可以指向一个常量（const）string 成员，该成员属于 Screen 类
const string Screen::*pdata; // 指向 Screen 类的 const string 成员的指针
```

上述定义中，const string Screen::* 的读法：pdata 是一个指针，它指向 Screen 类的某个 const string 成员。

初始化或赋值成员指针时，指定其指向的具体成员：

```cpp
// pdata 指向 Screen 类的 contents 成员
pdata = &Screen::contents;
// 使用 auto 简化
auto pdata2 = &Screen::contents;
```

成员指针的使用：解引用成员指针得到对象的成员时，必须提供成员所属的对象。使用 `.*` 和 `->*` 两个运算符：

```cpp
Screen myScreen, *pScreen = &myScreen;
// .* 解引用 pdata 以获得 myScreen 对象的 contents 成员
auto s = myScreen.*pdata;
// ->* 解引用 pdata 以获得 pScreen 所指对象的 contents 成员
auto s2 = pScreen->*pdata;
```

### 成员函数指针

定义成员函数指针时，必须指定指针所指的函数类型：

```cpp
// p1 指向一个函数，该函数是 Screen 的成员，接受两个 pos 实参，返回 char
auto p1 = &Screen::get; // 接受两个 pos 实参的 get 函数
```

成员函数的使用方式与普通函数指针类似：

```cpp
char (Screen::*pmf)(Screen::pos, Screen::pos) const; // pmf 是一个指针，指向 Screen 的成员函数
pmf = &Screen::get; // 指向 Screen 类的 get 成员函数（必须显式使用 & 取地址）

Screen myScreen2;
// 通过对象调用成员函数指针
char c1 = (myScreen2.*pmf)(0, 0); // 注意括号必不可少
// 通过对象指针调用
Screen *pScreen2 = &myScreen2;
char c2 = (pScreen2->*pmf)(0, 0);
```

调用成员函数指针时，`.*` 和 `->*` 两侧的括号必不可少：`(obj.*pmf)(args)`。因为函数调用运算符的优先级高于 `.*`，不加括号会被解释为 `obj.*(pmf(args))`，这是错误的。

成员指针函数表：成员函数指针的一个典型应用是构建函数表，根据索引调用不同的成员函数。

### 将成员函数用作可调用对象

使用成员函数指针时，比较繁琐的一种用法是标准库函数需要可调用对象时。可以使用标准库模板 mem_fn（定义在 functional 头文件中），让编译器推断成员的类型：

```cpp
auto fp = &Screen::get_cursor; // 或者
function<char (Screen::pos, Screen::pos)> f = &Screen::get;
// 使用 mem_fn 生成可调用对象
auto get = std::mem_fn(&Screen::get); // get 接受一个 Screen 对象（或指针/引用）以及位置参数
```

mem_fn 生成的对象可以通过对象、指针或引用调用，也能接受任意形式的 Screen 参数。

也可以使用 lambda 达到相同的效果：

```cpp
// 接受一个 Screen 对象和一个位置参数
auto get2 = [](const Screen &s, Screen::pos p) { return s.get(p); };
```

## 嵌套类和局部类

一个类可以定义在另一个类的内部，前者称为嵌套类（nested class）或嵌套类型（nested type）。嵌套类常用于定义作为实现部分的类类型，如 Queue 类的 QueueItem 成员（容器实现中很常见）。

嵌套类是一个独立的类，只是外层类的作用域内部的名字。嵌套类的名字在外层类之外是不可见的，但不会隐藏外层作用域中同名声明。

在外层类之外定义嵌套类成员时，必须以嵌套类所属的外层类的名字限定嵌套类的名字：

```cpp
class Outer {
    class Inner; // 嵌套类的声明
    // ...
};
class Outer::Inner { /* 嵌套类的定义 */ };
```

嵌套类与外层类的关系：嵌套类的成员函数可以访问外层类的成员（包括私有的，如同友元一样），但必须通过外层类的对象、指针或引用进行访问；外层类的成员函数不能直接访问嵌套类的私有成员。

局部类（local class）定义在函数内部。局部类的所有成员（包括函数）都必须定义在类的内部，因此局部类的作用域非常受限。局部类不能访问函数的普通（非静态）局部变量，只能访问函数内的静态变量、类型别名和枚举。

## union：一种节省空间的类

联合（union）是一种特殊的类。一个 union 可以有多个数据成员，但是在任意时刻只有一个数据成员可以有值。当给 union 的某个成员赋值之后，其他成员变为未定义的状态。分配给一个 union 对象的存储空间至少要能容纳它的最大的数据成员。

union 不能包含引用类型的成员；union 的成员通常是 public 的（也可以使用访问说明符），默认也是 public 的。union 可以定义成员函数（包括构造函数和析构函数），但不能继承。

定义 union：

```cpp
// Token 类型的对象只有一个成员，该成员的类型可能是下列类型中的任意一种
union Token {
    char cval;
    int ival;
    double dval;
};
```

默认情况下 union 是未初始化的。可以像显式初始化聚合类一样使用一对花括号内的初始值显式初始化 union：

```cpp
Token first_token = { 'a' }; // 初始化 cval 成员
Token last_token;            // 未初始化的 Token 对象
Token *pt = new Token;       // 指向一个未初始化的 Token 对象的指针
```

访问 union 的成员使用普通的成员访问运算符：

```cpp
last_token.cval = 'z';
pt->ival = 42;
```

匿名 union（anonymous union）是一个未命名的 union，并且在右花括号和分号之间没有任何声明。一旦定义了一个匿名 union，编译器就自动地为该 union 创建一个未命名的对象。匿名 union 的成员可直接访问：

```cpp
union { // 匿名 union
    char cval;
    int ival;
    double dval;
};
cval = 'c'; // 直接访问，无需成员访问运算符
ival = 42;
```

匿名 union 不能包含私有成员或受保护成员，也不能定义成员函数。

含有类类型成员的 union：如果 union 的成员是类类型，且该类定义了自己的构造函数或拷贝控制成员，则 union 的使用会变得更复杂：必须显式地调用/销毁这些类类型成员（union 自己不会自动调用它们的构造/析构函数）。

使用类管理 union 成员：由于 union 在切换活跃成员时需要手动管理类类型成员的构造与销毁，一种常用的做法是把 union 嵌套在一个类中，用类来管理 union 的状态（用枚举成员记录 union 当前存储的是哪种类型的值）。

## 固有的不可移植的特性

### 位域

类可以将其（非静态）数据成员定义成**位域（bit-field）**，在一个位域中含有一定数量的二进制位。位域在内存中的布局是与机器相关的：

```cpp
typedef unsigned int Bit;
class File {
    Bit mode : 2;       // mode 占 2 位
    Bit modified : 1;   // modified 占 1 位
    Bit prot_owner : 3; // prot_owner 占 3 位
    Bit prot_group : 3; // prot_group 占 3 位
    Bit prot_world : 3; // prot_world 占 3 位
public:
    enum modes { READ = 01, WRITE = 02, EXECUTE = 03 };
    File &open(modes);
    void close();
    void write();
    bool isRead() const { return mode & READ; }
    void setWrite() { mode |= WRITE; }
};
```

位域的类型必须是整型或枚举类型。使用位域时通常使用位运算符（&、|、~）操作。

取地址运算符不能用于位域，因此任何指针都无法指向类的位域。

### volatile限定符

volatile 的确切含义与机器有关，只能通过阅读编译器文档来理解。要想让使用了 volatile 的程序在移植到新机器或新编译器后仍然正常工作，必须仔细研究该机器和编译器的语义。

当对象的值可能被程序之外的因素（如操作系统、硬件或另一线程）改变时，应该将对象声明为 volatile。关键字 volatile 告诉编译器不应对这样的对象进行优化：

```cpp
volatile int display_register; // 该 int 值可能发生改变
volatile Task *curr_task;      // curr_task 指向一个 volatile 对象
volatile int iax[10];          // iax 的每个元素都是 volatile
```

const 和 volatile 一次可以同时使用（例如一个只读的硬件寄存器：const volatile int）。

volatile 与指针的关系与 const 类似：可以声明 volatile 指针、指向 volatile 对象的指针以及指向 volatile 对象的 volatile 指针：

```cpp
volatile int v;          // v 是一个 volatile int
int *volatile vip;       // vip 是一个 volatile 指针，指向 int
volatile int *ivp;       // ivp 是一个指针，指向 volatile int
volatile int *volatile vivp; // vivp 是一个 volatile 指针，指向 volatile int
```

与 const 一样，不能将 volatile 对象的地址赋给普通指针（只能赋给指向 volatile 的指针）。

volatile 与类：只有成员函数是 volatile 的（或同时是 const 和 volatile 的）时，volatile 对象才能调用它。可以声明 volatile 成员函数，此时 this 指针是 volatile 的。

volatile 与 const 的区别：不能使用合成的拷贝/赋值操作初始化 volatile 对象或从 volatile 对象赋值（合成的拷贝控制成员的形参是非 volatile 的，不能接受 volatile 实参）。如果需要拷贝 volatile 对象，必须自定义拷贝/赋值操作。

### 链接指示：extern "C"

C++ 程序有时需要调用其他语言编写的函数，最常见的是 C 语言。C++ 使用**链接指示（linkage directive）**指出任意非 C++ 函数所用的语言。

链接指示有两种形式：单个的或复合的：

```cpp
// 单语句的链接指示
extern "C" size_t strlen(const char *);

// 复合形式的链接指示
extern "C" {
    int strcmp(const char*, const char*);
    char *strcat(char*, const char*);
}
```

链接指示不能出现在类定义或函数定义的内部。同样的链接指示必须在函数的每个声明中都出现。

链接指示与头文件：当 C++ 程序需要包含 C 语言编写的头文件时，可以使用链接指示包裹整个头文件：

```cpp
// compound literal statements apply to the function in the header
extern "C" {
#include <string.h>       // 操作 C 风格字符串的 C 函数
}
```

指向extern "C"函数的指针：链接指示不仅作用于函数本身，还作用于指向该函数的指针（函数指针的类型必须与链接指示匹配）：

```cpp
// pf1 指向一个 C 函数
extern "C" void (*pf1)(int);
// pf2 指向一个 C++ 函数
void (*pf2)(int); // 这是一个 C++ 函数
```

链接指示对整个声明都有效，因此当链接指示包含复合语句时，将它与函数指针一起使用时要格外小心。

导出C++函数到其他语言：通过对函数定义使用链接指示，允许其他语言调用 C++ 函数：

```cpp
extern "C" double calc(double dparm) { /* ... */ } // calc 函数可以被 C 程序调用
```

注意：如果函数在多个文件中声明，则该函数的每个声明都必须使用相同的链接指示。链接指示的函数的返回类型或形参类型不能是 C++ 特有的类型（如类类型或引用类型）。

重载函数与链接指示：链接指示与重载函数的相互作用依赖于目标语言。C 语言不支持函数重载，因此一个 C 链接指示的函数不能重载。但是 C 链接指示可以用于一组重载函数中的一个（或者说一组重载函数中只能有一个是 C 函数）。
