## 1. 包:库单元(package: the library unit)

包(package)解决两个问题:一是**为类命名空间分组**——同包的类彼此"相识",可以方便地互相使用;二是**控制访问边界**——访问权限修饰符的"包"级别就是以包为界。

### 代码组织

一个编译单元(.java 文件)以 `package` 语句开头,声明自己属于哪个包;一个编译单元**只能有一个 public 类**,且类名必须与文件名一致(这是运行时定位类的依据)。文件按包名对应的目录结构存放:package `net.mindview.util` 的类应位于 `net/mindview/util/` 目录下,从 CLASSPATH 的根起点查找。

### 创建独一无二的包名

类名会冲突,包名也可能冲突。惯例是把**倒序的互联网域名**作为包名前缀(`com.company.project`),域名全球唯一,包名随之唯一。编译后 class 文件也要放到对应的目录层级中。

### 冲突的名字

两个库都有同名类(如两个 `Vector`)时,用完整限定名 `java.util.Vector` 区分,或只 import 其中一个、另一个写全名。

### 自定义工具库

把常用功能(如打印工具)做成自己的工具库,配合**静态导入**消除重复:

```java
// com/company/util/Print.java
package com.company.util;

public class Print {
    // 打印并换行:类似 System.out.println
    public static void print(Object obj) {
        System.out.println(obj);
    }
    // 打印不换行:类似 System.out.print
    public static void printnb(Object obj) {
        System.out.print(obj);
    }
}

// 使用方:
import static com.company.util.Print.*;
print("Available from now on!");
printnb("100 + 47 = ");
print(100 + 47);
```

> 用自己的 `print()` 包住 `System.out.println`,还便于日后统一改输出目标(如重定向到日志/文件)。

## 2. Java 访问修饰符(Java access specifiers)

四个访问级别(从宽到紧):**public、protected、包访问权限(不写任何修饰符)、private**。

| 修饰符       | 本类 | 同包 | 不同包的子类 | 不同包非子类 |
| ------------ | ---- | ---- | ------------ | ------------ |
| public       | ✓    | ✓    | ✓            | ✓            |
| protected    | ✓    | ✓    | ✓            | ×            |
| 包访问(默认) | ✓    | ✓    | ×            | ×            |
| private      | ✓    | ×    | ×            | ×            |

- **包访问权限(package access)**:默认级别,同包的所有类都能访问,包外不行。它把"相关的类归成一个可互相操作的整体,对外只暴露 public 部分"——这是比 private 更常用的"内部实现隐藏"手段;
- **public**:接口的一部分,对所有人开放;
- **protected**:包访问 + 子类可见。主要场景是:允许子类访问基类的成员,但不让外部碰;
- **private**:除了本类(含本类的其他实例——同类的不同对象可以互访 private 成员),谁都不能碰。

```java
class Sundae {
    private Sundae() { }          // private 构造器:禁止外部 new

    static Sundae makeASundae() { // 只能通过静态方法创建(单例/受控创建)
        return new Sundae();
    }
}

public class IceCream {
    public static void main(String[] args) {
        // Sundae x = new Sundae();  // 编译错误:构造器不可见
        Sundae x = Sundae.makeASundae();  // 唯一的创建途径
    }
}
```

private 构造器 + 静态工厂方法是**单例(singleton)与受控创建**的标准实现;enum 的实例控制正是这一思想的极端形式。

## 3. 接口与实现(Interface and implementation)

访问控制的术语借用自面向对象先驱的表述:**把数据和方法包装进类 + 隐藏实现 = 封装(encapsulation)**。

- **接口(interface,小写,泛指)**:类型暴露给使用者的部分——public 方法与字段;
- **实现(implementation)**:内部的工作方式——private 的字段与方法。

```java
public class Api2 {
    // public 部分:使用者可见的接口
    public void interact() {
        System.out.println("对外服务");
    }

    // 包访问/ private 部分:实现细节,随时可改而不影响使用者
    private void hidden() {
        System.out.println("内部细节");
    }
}
```

隐藏实现的两点价值:**创建者可以自由改实现**而不影响使用者;**使用者无法触及本不该碰的内部状态**,减少 bug。界限清晰后,两者可以并行开发。

## 4. 类的访问权限(Class access)

类的访问级别只能选 **public 或包访问**(不能是 private/protected——但**内部类**可以,见内部类一章)。同一编译单元里的非 public 类对包外完全不可见——这是"仅限包内使用的实现类"的常规做法。

> 看到类没加 public,就理解为"这是包内私有的实现类";要让类被包外使用,必须 public 且独立成文件。

## 5. 小结

访问控制的四档边界,本质是在回答"谁能看到什么":

- 库的设计者用它划定**稳定接口与可变实现**的分界线;
- 使用者通过 public 部分理解"怎么用",实现细节的演化不构成破坏;
- 默认的包访问把"协作的类群"圈成一个整体,是 Java 里最容易被忽视、却最常起作用的一档。
