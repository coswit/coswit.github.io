## 1. 组合语法(Composition syntax)

代码复用最简单的形式:把已有类的对象放进新类里——**组合(has-a)**。对象初始化的四种时机:

```java
class Soap {
    private String s;

    Soap() {
        System.out.println("Soap()");
        s = "Constructed";      // 3. 在构造器中初始化
    }
}

public class Bath {
    private String              // 1. 定义处初始化
        s1 = "Happy",
        s2 = "Happy2";
    private Soap castille;      // 2. 未初始化(得到 null,惰性创建)
    private int i;
    private float toy;

    public Bath() {             // 构造器里才建
        castille = new Soap();
    }

    public String toString() {
        if (toy == 0)           // 4. 使用前才创建(惰性初始化)
            toy = 3.14f;
        return "s1 = " + s1;
    }
}
```

四种时机各有所长:定义处直观;构造器里适合"依赖参数"的成员;惰性初始化适合"创建昂贵且未必用到"的成员。

## 2. 继承语法(Inheritance syntax)

继承(is-a)用 `extends` 实现,自动获得基类的全部成员。语法动作只有两个:**给方法加新签名、覆盖方法(标注 `@Override`)**:

```java
class Cleanser {
    private String s = "Cleanser";

    public void append(String a) { s += a; }
    public void dilute() { append(" dilute()"); }
    public void apply() { append(" apply()"); }

    public static void main(String[] args) {
        Cleanser x = new Cleanser();
        x.dilute(); x.apply();
        System.out.println(x);
    }
}

public class Detergent extends Cleanser {
    // 覆盖:改写行为
    @Override
    public void apply() {
        append(" Detergent.apply()");
        super.apply();          // 调用基类版本
    }

    // 新增:扩展行为
    public void foam() { append(" foam()"); }
}
```

`super.apply()` 让子类在基类行为**前后**加料,而不是全盘替换。main 也可以被继承——`Detergent` 可以直接跑 `Cleanser.main`。

### 初始化基类

继承关系里,基类在导出类之前完成初始化——导出类构造器第一件事就是调基类构造器(默认调无参版;用 `super(参数)` 显式选择带参版,且必须是第一条语句):

```java
class Art {
    Art() { System.out.println("Art constructor"); }
}

class Drawing extends Art {
    Drawing() {
        // 编译器自动插入 super(),等价于显式写:
        // super();
        System.out.println("Drawing constructor");
    }
}

public class Cartoon extends Drawing {
    public static void main(String[] args) {
        new Cartoon();   // 输出: Art → Drawing → Cartoon,自底向上构建
    }
}
```

## 3. 代理(Delegation,On Java 8)

介于组合与继承之间的第三种复用:把一个成员对象放进类里(像组合),同时**暴露该对象的所有方法**(像继承),但方法调用被转发——你可以选择性地转发、在转发前后加逻辑:

```java
public class SpaceShipControls {   // 模拟"飞船控制"的一组方法
    void up(int velocity) { }
    void down(int velocity) { }
    void left(int velocity) { }
    void right(int velocity) { }
}

public class SpaceShipDelegation {
    private SpaceShipControls controls = new SpaceShipControls();

    // 代理方法:签名照抄,内部转发——比继承多一层"拦截点"
    public void up(int velocity) { controls.up(velocity); }
    public void down(int velocity) { controls.down(velocity); }
    public void turboBoost() { }   // 也可以加自己的方法
}
```

Java 没有语言级代理支持(要手写转发;动态代理可以自动化这层)。**"能用继承的地方,考虑用代理替代"**是复用一节的核心忠告——代理保留了组合的灵活性,却提供了继承的便利表象。

## 4. 结合使用组合与继承(Combining composition and inheritance)

两种机制可以同时使用:

```java
class Plate { Plate(int i) { } }
class Table extends Furniture {          // 继承
    private Plate plate = new Plate(1);  // 组合
    Table() { super(1); }
}
```

### 确保正确清理

Java 没有析构器,通常靠垃圾回收。若类持有需要显式释放的资源(文件、连接),要自写 `dispose()` 之类的清理方法,并**按创建的相反顺序**清理(导出类先清理自己,再调 `super.dispose()`,用 try-finally 保证):

```java
class FancyToy extends Toy {
    @Override
    protected void dispose() {
        try {
            System.out.println("FancyToy dispose");
        } finally {
            super.dispose();      // 与构造顺序相反:先自己,再基类
        }
    }
}
```

> Java 7 之后,实现 `AutoCloseable` + try-with-resources 是更安全的资源清理方式,详见异常一章。

## 5. 在组合与继承之间选择(Choosing composition vs. inheritance)

判断标准只有一条:**需不需要向上转型**。

- 组合(has-a):新类只是"使用"已有类的功能——把成员藏进去,只暴露想要的方法;
- 继承(is-a):新类是基类的一种,将以基类的面目出现(多态的前提)。

> 拿不准就用组合。继承every用一次,就多承担一层"基类实现变化会击穿子类"的耦合;组合的委托层恰好挡住这种变化。

## 6. protected

protected = 包访问 + 子类访问。它给继承体系开了"家族内部"的口子:

```java
class Villain {
    private String name;

    protected void set(String nm) {   // 只允许子类改名字
        name = nm;
    }
}

public class Orc extends Villain {
    public void change(String name) {
        set(name);   // 子类可用 protected 成员
    }
}
```

注意 protected 同时包含包访问——同包的非子类也能访问,这点常被忽略。最佳实践:**成员字段尽量 private,把 protected 留给方法**。

## 7. 向上转型(Upcasting)

把子类引用交给基类引用,沿继承图"向上"移动,是**安全**的——子类必然是基类(圆必然是形状),编译器不需要强制转换:

```java
class Instrument {
    public void play() { }
}

public class Wind extends Instrument {
    public static void tune(Instrument i) {
        i.play();
    }

    public static void main(String[] args) {
        Wind flute = new Wind();
        tune(flute);   // 向上转型:Wind → Instrument,自动发生
    }
}
```

"向上"意味着从**特殊类型转向通用类型——不会丢失任何东西**;反之(向下转型)才需要显式强转与运行时检查。如果不需要向上转型,就应重新审视"用继承是否合理"。

## 8. final 关键字(The final keyword)

final 意为"无法改变",可修饰数据、方法、类。

### final 数据

- **编译期常量**:`static final` + 基本类型 + 定义处赋值,全大写命名,值被直接嵌入使用点;
- **运行期初始化的常量**:空白 final(blank final)——声明时不赋值,但**必须在构造器/初始化块里赋且仅赋一次**:

```java
class Poppet {
    private int i;
    Poppet(int ii) { i = ii; }
}

public class BlankFinal {
    private final int i = 0;          // 定义处初始化的 final
    private final int j;              // 空白 final
    private final Poppet p;           // 空白 final 引用

    public BlankFinal() {
        j = 1;                        // 构造器里必须补上
        p = new Poppet(1);
    }
}
```

final 修饰**引用**时,含义是"引用不可再指向别的对象",**对象本身仍可变**:

```java
final Value v = new Value(1);
v.i = 47;         // 合法:改的是对象内容
// v = new Value(2);  // 编译错误:引用本身不能改
```

final 参数:方法内不可重新赋值(主要用于向匿名内部类传参)。

### final 方法

把方法锁定,**禁止子类覆盖**。历史上的理由之一是效率(内联),但现代 JIT 让这个理由消失了——**如今用 final 方法只有一个理由:明确不想让覆盖发生**。类里所有 private 方法都隐含 final。

### final 类

声明"这个类不做继承"。String 就是 final 类。要么出于设计(不想被继承),要么出于安全(防止子类破坏不变式)。

### final 警告

final 的语义边界容易误读:final 引用不等于不可变对象;final 类仍可能包含可变字段。写 final 前问清楚要冻结的是"引用/方法/类"中的哪一层。

## 9. 初始化与类加载(Initialization and class loading)

Java 的类加载时机:**首次使用时**(static 引用、new、访问静态方法)。加载-初始化的顺序:

```java
class Insect {
    private int i = 9;
    protected int j;

    Insect() {
        System.out.println("i = " + i + ", j = " + j);
        j = 39;
    }

    private static int x1 = printInit("static Insect.x1 initialized");

    static int printInit(String s) {
        System.out.println(s);
        return 47;
    }
}

public class Beetle extends Insect {
    private int k = printInit("Beetle.k initialized");

    public Beetle() {
        System.out.println("k = " + k);
        System.out.println("j = " + j);
    }

    private static int x2 = printInit("static Beetle.x2 initialized");

    public static void main(String[] args) {
        System.out.println("Beetle constructor");
        Beetle b = new Beetle();
    }
}
/* Output:
static Insect.x1 initialized    ← 1. 访问 main 触发加载:先基类静态
static Beetle.x2 initialized    ← 2. 再导出类静态
Beetle constructor              ← 3. 进入 main
i = 9, j = 0                    ← 4. 基类实例成员 → 基类构造器
k = 47                          ← 5. 导出类实例成员 → 导出类构造器
j = 39
*/
```

要点:

1. **静态初始化自基类开始、只发生一次**(编译期常量则直接嵌入,不触发加载);
2. 创建对象时,**基类构造器 → 导出类成员初始化 → 导出类构造器**,成员初始化永远先于构造器体。

> 在构造器里调用**可被覆盖的方法**是危险的:导出类的字段还没初始化,覆盖版本却已经被基类构造器调用了——多态一章会展开这个陷阱。
