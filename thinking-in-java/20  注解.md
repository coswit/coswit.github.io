## 1. 基本语法（Basic syntax）

> Annotations (also known as metadata) provide a formalized way to add information to your code so that you can easily use that data at some later point.
>
> 注解（也叫元数据,metadata）提供了一种为代码附加信息的正规方式,这些信息可以在之后由工具读取使用。

注解把"描述性数据"保存在源码里,由编译器检查格式,由工具生成配置/代码——省去样板文件（descriptor files）,得到编译期类型检查与注解 API 的支持。

`java.lang` 内置三个标准注解:

- **@Override**:标注重写父类方法,签名拼错立即编译报错;
- **@Deprecated**:标记过时元素,使用时编译器告警;
- **@SuppressWarnings**:关闭不当的编译器警告。

### 定义注解（Defining annotations）

注解用 `@interface` 定义,看起来像接口,成员则是"方法":

```java
@Target(ElementType.METHOD)
@Retention(RetentionPolicy.RUNTIME)
public @interface UseCase {
    int id();                          // 注解元素

    String description() default "no description";   // 可带默认值
}

// 使用:
public class PasswordUtils {
    @UseCase(id = 47, description =
            "Passwords must contain at least one numeric")
    public boolean validatePassword(String password) {
        return password.matches("\\w*\\d\\w*");
    }

    @UseCase(id = 48)
    public String encryptPassword(String password) {   // 用默认 description
        return new StringBuilder(password).reverse().toString();
    }
}
```

### 元注解（Meta-annotations）

给"注解定义"加的注解:

| 元注解       | 作用                                                       |
| ------------ | ---------------------------------------------------------- |
| @Target      | 注解可以用在哪:TYPE/METHOD/FIELD/PARAMETER/CONSTRUCTOR/... |
| @Retention   | 保留到哪一步:SOURCE（仅源码）/CLASS（默认,不入 JVM）/RUNTIME（运行时可读） |
| @Documented  | 进入 javadoc                                               |
| @Inherited   | 子类可继承父类上的注解                                     |

注解元素不支持继承（注解不能 extends 另一个注解）。

## 2. 编写注解处理器（Writing annotation processors）

没有工具读取的注解只是装饰。读取注解的主流方式是**反射**:

```java
public class UseCaseTracker {
    public static void trackUseCases(List<Integer> useCases, Class<?> cl) {
        for (Method m : cl.getDeclaredMethods()) {
            UseCase uc = m.getAnnotation(UseCase.class);   // 读取方法上的注解
            if (uc != null) {
                System.out.println("Found Use Case:" + uc.id()
                        + " " + uc.description());
                useCases.remove(Integer.valueOf(uc.id())); // 已覆盖的用例划掉
            }
        }
        for (int i : useCases)
            System.out.println("Warning: Missing use case-" + i);
    }

    public static void main(String[] args) {
        List<Integer> useCases = new ArrayList<>();
        Collections.addAll(useCases, 47, 48, 49, 50);
        trackUseCases(useCases, PasswordUtils.class);
    }
}
```

`getAnnotation()` 是核心 API;注解元素通过 `uc.id()` 这样的"方法调用"读取。

### 注解元素（Annotation elements）

允许的元素类型:基本类型、String、Class、enum、注解、以及它们的数组。非法:包装类以外的对象。元素可以有默认值;特殊元素名 `value`（只有一个元素且名为 value 时,使用处可直接 `@注解(值)`）。

### 默认值的限制（Default value constraints）

- 元素默认值**不能是 null**——习惯用空串、-1 之类哨兵值表达"未设置";
- 无法表达"默认就是这个字段不变",只能表达一个具体值;
- 快速诊断:默认值让"部分字段未指定"也能成立,但哨兵值要在处理器里显式识别。

### 生成外部文件（Generating external files）

注解最实的用途之一:**从源码生成附属产物**。原书示例是 Hibernate 风格的 `@Entity/@Table/@Column`——用它描述数据库表结构,由工具自动建表;这个思路即后来 Spring Data JPA、JPA 规范的做法。

### 处理器实现要点

反射式处理器的骨架:`getAnnotations()` 拿全部注解 → 逐个判断类型（注意 **instanceof 对 APT 生成代理类**的坑,用类名字符串匹配最稳妥）→ 提取元素值。注解嵌套（注解的元素又是注解）时递归处理。

## 3. 用 javac 处理注解（Using javac to process annotations）

原书此节用 Sun 的 **apt（annotation processing tool）** 工具;**apt 已在 Java 8 中移除**,它的能力并入了 javac 本身——写法改为标准的**编译期注解处理器（annotation processor）**:

- 处理器处理的是**源码**（不是编译后的 class）;
- 关键限制:**不能修改已有源码**,只能创建新文件;新文件会进入下一轮（round）处理,直到没有新文件产生,最后统一编译。

### 最简单的处理器（The Simplest Processor）

注解与处理器:

```java
// 注解:@Retention 为 SOURCE 也无妨——javac 在编译期就能处理它
@Retention(RetentionPolicy.SOURCE)
@Target({ ElementType.TYPE, ElementType.METHOD,
          ElementType.CONSTRUCTOR, ElementType.FIELD,
          ElementType.LOCAL_VARIABLE })
public @interface Simple {
    String value() default "-default-";
}
```

```java
// 处理器:继承 AbstractProcessor
@SupportedAnnotationTypes("annotations.simplest.Simple")
@SupportedSourceVersion(SourceVersion.RELEASE_8)
public class SimpleProcessor extends AbstractProcessor {
    @Override
    public boolean process(Set<? extends TypeElement> annotations,
                           RoundEnvironment env) {
        for (TypeElement t : annotations)
            System.out.println("Processing annotation: " + t);
        for (Element el : env.getElementsAnnotatedWith(Simple.class))
            System.out.println("==== " + el + " ====");   // 被注解的元素
        return false;   // false:允许其他处理器继续处理
    }
}
```

`process()` 对每轮处理调用一次;`getElementsAnnotatedWith()` 取出全部被注解的**元素（Element）**——注意这是编译期模型（`javax.lang.model.element.Element`）,不是运行期反射的 Method/Field,但概念对应。Element 的 `getKind()`、`getModifiers()` 等提供元素信息。

### 让 javac 找到处理器

编译时指定处理器路径:

```text
javac -processor annotations.simplest.SimpleProcessor 源文件...
```

或将处理器打成 jar 放在编译classpath,通过 `ServiceLoader` 机制（META-INF/services/javax.annotation.processing.Processor）自动发现——Lombok、AutoValue、Dagger 等都是这条路线。

> 编译期注解处理是"注解改变 Java 表达力"的主战场:生成样板代码（Lombok）、依赖注入（Dagger）、值对象（AutoValue）、Builder（Immutables）。运行期反射式（Spring）与编译期生成式（javac processor）是注解的两大生态。

## 4. 基于注解的单元测试（Annotation-based unit testing）

原书用一整节实现了一个自定义的 @Unit 测试框架:`@Test` 标注测试方法,`@TestObjectCreate/@TestObjectCleanup` 标注构建/清理,工具用反射发现并运行这些方法,失败转译为测试报告。

> 时代注:这是作者演示"注解 + 反射构建系统"的教学案例。实践中请直接用 **JUnit**（`@Test` 注解思想同源）或 TestNG;@Unit 框架本身未获社区采用。理解其原理（注解标记 + 反射发现 + 报告失败）依然有助于理解 JUnit 的工作方式。

@Unit 的一个有价值的议题是**注解与泛型**:注解元素不能是泛型 Class 以外的参数化类型,`@TestObjectCreate` 工厂返回泛型时需要额外的泛型方法适配,展示了注解系统的边界。

## 5. 小结（Summary）

注解的价值公式:**源码内嵌元数据 + 编译器格式检查 + 工具消费**。

- 运行期消费:反射 `getAnnotation()`（Spring 的依赖注入、JPA 实体映射）;
- 编译期消费:javac 注解处理器,生成新文件而不能改旧文件（Lombok/Dagger）;
- apt 工具已死,javac 一统编译期处理。

合理使用注解可以"消灭配置文件与样板代码";滥用则把逻辑藏进"魔法",让代码难以追踪——注解应是**声明**,不该承载**控制流**。
