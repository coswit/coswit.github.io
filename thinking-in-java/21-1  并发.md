## 1. 并发的多面性(The many faces of concurrency)

### 更快的执行(Faster execution)

并发最常见的理由是速度。三种途径:

1. **多处理器并行**——任务真正同时跑;主频提升停滞之后,多核成为性能增长的主要来源;
2. **单处理器 + 上下文切换(context switching)**——CPU 在任务间快速轮转,看起来"同时";若无阻塞,切换开销反而让程序更慢;
3. **掩盖阻塞**——一个任务等 I/O 时,处理器去跑别的任务。这是单核机器上并发仍然值得的唯一理由。

实现并发的两条路线:

- **进程(process)**:自包含的程序,运行在独立地址空间。操作系统把进程隔离开,互不干扰,编程容易;但数量与开销受限;
- **线程(thread)**:进程内的执行单元,**共享内存与 I/O** 资源。经济、切换快,但必须协调共享资源的访问——并发的全部难题由此而来。

> Java 选择的是在顺序语言之上加线程,而不是隔离式的进程模型——共享内存带来效率,也埋下了并发的全部根本困难。

### 改进代码设计(Improving code design)

并发不只是提速,某些问题**天然是并发的**:仿真(每个元素是独立生命)、服务端(每个连接一个任务)、媒体播放(播放/进度/下载并行)。把它们硬塞进单线程模型,代码反而复杂——并发的"任务"抽象比"轮询 + 状态标志"更贴近问题结构。

## 2. 基本的线程机制(Basic threading)

### 定义任务(Defining tasks)

任务(task)是实现 `Runnable` 接口的类——`run()` 里写任务逻辑,通常含某种循环,任务"自然结束"或被外部终止:

```java
public class LiftOff implements Runnable {
    protected int countDown = 10;              // 默认倒计时
    private static int taskCount = 0;
    private final int id = taskCount++;        // 任务编号

    public LiftOff() { }
    public LiftOff(int countDown) { this.countDown = countDown; }

    public String status() {
        return "#" + id + "(" +
                (countDown > 0 ? countDown : "Liftoff!") + "), ";
    }

    @Override
    public void run() {
        while (countDown-- > 0) {
            System.out.print(status());
            Thread.yield();   // 建议调度器切换:重要部分已完成
        }
    }
}
```

`Thread.yield()` 是对线程调度器(thread scheduler)的**建议**:"我已到周期尾声,可以换别的任务了"。仅直接 `run()` 调用(如 `launch.run()`)是普通方法调用,不涉及并发。

### Thread 类

把 Runnable 交给 Thread 并 `start()`,才真正产生并发——`start()` 完成初始化并调用 run,随即返回:

```java
public class BasicThreads {
    public static void main(String[] args) {
        Thread t = new Thread(new LiftOff());
        t.start();
        System.out.println("Waiting for LiftOff");
        // 输出顺序不定:main 与新线程已并发
    }
}
```

一个 Runnable 可交给多个 Thread——它们共享任务对象的状态,资源竞争问题由此而生。

### 使用 Executors(Using Executors)

**ExecutorService** 替你管理线程:复用线程避免频繁创建销毁。这是"推荐的线程起步方式":

```java
import java.util.concurrent.*;

public class CachedThreadPool {
    public static void main(String[] args) {
        ExecutorService exec = Executors.newCachedThreadPool();
        for (int i = 0; i < 5; i++)
            exec.execute(new LiftOff());   // 提交任务
        exec.shutdown();                   // 拒绝新任务,等已有任务完成后退出
    }
}
```

常用工厂:

| 工厂方法                    | 行为                                       |
| --------------------------- | ------------------------------------------ |
| newCachedThreadPool()       | 按需建线程,空闲 60s 回收;任务数可变时用  |
| newFixedThreadPool(n)       | 固定 n 线程,提交过多则排队;负载可控      |
| newSingleThreadExecutor()   | 单线程串行执行——像队列一样逐个跑任务      |

SingleThreadExecutor 有个隐藏福利:**强制串行使非线程安全的任务也能安全运行**(线程封闭,thread confinement)。

### 从任务产生返回值(Producing return values from tasks)

Runnable 的 run() 无返回值。需要结果时用 **Callable**——`call()` 有返回值、可抛异常:

```java
class TaskWithResult implements Callable<String> {
    private int id;

    public TaskWithResult(int id) { this.id = id; }

    @Override
    public String call() {
        return "result of TaskWithResult " + id;
    }
}

ExecutorService exec = Executors.newCachedThreadPool();
Future<String> future = exec.submit(new TaskWithResult(0));  // 提交即返回凭据
System.out.println(future.get());   // get() 阻塞直到结果就绪
```

**Future** 是"还没有就绪的结果"的凭据:可以先用 `isDone()` 探测,或直接 `get()` 阻塞等;`get(timeout, unit)` 支持限时。Future 的局限是 `get()` 只是把等待往后推,并不能把多个异步步骤**组合**成流水线——这正是 Java 8 引入 CompletableFuture 要解决的问题。

### 休眠(Sleeping)

`TimeUnit.MILLISECONDS.sleep(100)` 让当前线程暂停指定时间——阻塞期间调度器去跑别的线程,这正是单核上并发仍有价值的原因:

```java
@Override
public void run() {
    try {
        while (countDown-- > 0) {
            System.out.print(status());
            TimeUnit.MILLISECONDS.sleep(100);
        }
    } catch (InterruptedException e) {
        System.err.println("Interrupted");
    }
}
```

sleep 抛出的 InterruptedException 是**中断式终止**的历史残留,必须处理,但不要依赖中断去终止任务。

### 优先级(Priority)

`setPriority()` 传 `Thread.MIN_PRIORITY(1)` / `NORM_PRIORITY(5)` / `MAX_PRIORITY(10)`。优先级只是**给调度器的建议**,具体映射到 OS 后效果不定(Windows/Linux 策略完全不同),不要依赖优先级做正确性保证。多数情况下用默认值。

### 让步(Yielding)

`Thread.yield()` 建议"切走我"。若调度器已有足够别的可跑任务,该建议会被采纳;它只是**提示**,不保证任何行为。

### 后台线程(Daemon threads)

**后台线程(守护线程,daemon thread)**"程序里只要还有前台线程就陪着跑,前台都结束就突然死掉"——`finally` 子句都不会执行:

```java
public class SimpleDaemons implements Runnable {
    @Override
    public void run() {
        try {
            while (true) {
                TimeUnit.MILLISECONDS.sleep(100);
                System.out.println(Thread.currentThread() + " " + this);
            }
        } catch (InterruptedException e) {
            System.out.println("sleep() interrupted");
        }
    }

    public static void main(String[] args) throws Exception {
        for (int i = 0; i < 10; i++) {
            Thread daemon = new Thread(new SimpleDaemons());
            daemon.setDaemon(true);   // 必须在 start() 之前设置
            daemon.start();
        }
        System.out.println("All daemons started");
        TimeUnit.MILLISECONDS.sleep(175);   // main 一结束,守护线程全体消亡
    }
}
```

守护线程适合"后台陪伴"性质的工作(心跳、监控);**不能承担需要善后的任务**(它没机会清理)。`t.isDaemon()` 判断;main 里创建的线程默认非守护。Executor 的版本:`Executors.newCachedThreadPool(daemonThreadFactory)`——用 ThreadFactory 产出守护线程。

### 编码的变体(Coding variations)

任务与线程的写法可自由组合:内部类、匿名内部类都行。Java 8 之后最简:

```java
new Thread(() -> System.out.println("task")).start();
```

### 加入一个线程(Joining a thread)

`t.join()` 让当前线程**挂起,等 t 结束**再继续;`t.join(ms)` 限时等待,超时继续。可以在任务内部 join 别的任务;join 期间可被中断(抛 InterruptedException)。

### 创建响应式用户界面(Creating responsive user interfaces)

单线程程序里做耗时计算,界面就冻结——把长任务放后台线程,界面事件循环才能持续响应。这是并发"改进设计"的典型场景(Swing 的事件分发线程、Android 主线程都是这个模型)。

### 捕获异常(Catching exceptions)

线程里抛出的异常**不会传播到外部 try-catch**,直接打到控制台。要接管,给线程装 `UncaughtExceptionHandler`:

```java
Thread t = new Thread(() -> { throw new RuntimeException("boom"); });
t.setUncaughtExceptionHandler(
        (thread, e) -> System.out.println("caught " + e));
t.start();

// 全局默认:
Thread.setDefaultUncaughtExceptionHandler(
        (thread, e) -> System.out.println("DEFAULT: " + e));
```

Executor 场景要经 ThreadFactory 传递:

```java
class HandlerThreadFactory implements ThreadFactory {
    @Override
    public Thread newThread(Runnable r) {
        Thread t = new Thread(r);
        t.setUncaughtExceptionHandler(
                (thread, e) -> System.out.println("caught " + e));
        return t;
    }
}
```

> 时代注:ThreadGroup 与 `Thread.stop()/suspend()/resume()` 属 Java 1.0 的失败实验,均已废弃(deprecated);`stop()` 释放锁会破坏对象一致性,新代码禁用。线程组的未捕获异常处理能力已由 UncaughtExceptionHandler 完全取代。
