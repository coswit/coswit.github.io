# 第1章 Vim 解决问题的方式（The Vim Way）

> 本章通过 `.` 命令引出全书最重要的方法论：**把重复的编辑工作交给"一键移动 + 一键执行"**。

## 认识 `.` 命令（the dot command）

- `.` 重复**上一次修改**（last change）。修改可以小到一个字符，也可以大到一个整段，甚至是命令行命令的效果。
- `.` 是一个"微型宏"：不需要刻意录制，天然存在。
- 三类修改范围的例子：

| 例子 | 说明 |
| ---- | ---- |
| `x` / `s` / `dw` | 作用于字符/单词级 |
| `dd` / `>G` / `itext<Esc>` | 作用范围到整行/到文件尾 |
| `:s/target/replacement/` | 命令行修改也一样可被 `.` 重复 |

## 不要自我重复（Don't Repeat Yourself）

把"定位 + 修改"组合成一个**可重复的修改单元**，让 `.` 来干剩下的活。

经典例子：给若干行行尾加分号：

```bash
A;<Esc>    " 进入插入模式并把光标移到行尾，输入分号
j.         " 下一行，重复
j.         " 再下一行……
```

- `A` = `$a`，它把"移动到行尾 + 进入插入模式"合并成一个命令，从而让后续的 `.` 一步到位。
- 同理：每行行首加注释用 `I// <Esc>`，然后 `j.` 逐行重复。
- 结论：**用复合命令（compound command，如 A/I/C/s）构造可重复修改**，而不是手动重复"移动 + 输入"。

## 以退为进（Take One Step Back, Then Three Forward）

有时为了可重复，宁可做一步"看似多余"的操作。

例子：把 `foo+bar` 改为 `foo + bar`（加号两侧补空格）：

```bash
f+        " 定位到 +
s + <Esc> " s 删除字符并进入插入模式：先退一步（删掉+），再输入" + "
;         " 重复行内查找下一个 +
.         " 重复修改
;.        " 一直重复到行尾
```

- 直接 `i <Esc>` 也能改一处，但 `s` 让"删除 + 输入"成为一个修改单元，`.` 才能整体重复。
- `;` 与 `.` 配合：一个负责移动，一个负责修改。

## 执行、重复、回退（Act, Repeat, Reverse）

| 目的 | 操作 | 重复 | 回退 |
| ---- | ---- | ---- | ---- |
| 做一次修改 | `{edit}` | `.` | `u` |
| 行内查找下一个指定字符 | `f{char}` / `t{char}` | `;` | `,` |
| 行内查找上一个指定字符 | `F{char}` / `T{char}` | `;` | `,` |
| 文档中查找下一处匹配项 | `/pattern<CR>` | `n` | `N` |
| 文档中查找上一处匹配项 | `?pattern<CR>` | `n` | `N` |
| 行内替换 | `:s/target/replacement` | `&` | `u` |
| 执行一系列修改 | `qx{changes}q` | `@x` | `u` |

- 大多数 Vim 命令成对出现（重复/回退）；遇到重复任务时，先想想"重复键是什么"。

## 查找并手动替换（Find and Replace by Hand）

替换不必非用 `:s`：**查找（`n`/`N`）+ 修改（`.`）** 的组合往往更快、更可控。

```bash
/target<CR>      " 查找
cwreplaced<Esc>  " 修改第一处：cw 修改到词尾
n                " 跳到下一处
.                " 重复修改（不想改就再按 n 跳过）
```

- 把"决定要不要改"（`n` 跳过）与"执行修改"（`.`）分开，比 `:%s//gc` 的问答节奏更顺手。

## 认识 `.` 范式（The Dot Formula）

**理想的编辑模式：用一次按键移动，用一次按键执行。**

- `;. ` 组合（行内）、`n.` 组合（全文）都是 `.` 范式的实例。
- 评估一个编辑方案的优劣，就看它离 `.` 范式有多近：移动一键、执行一键。
