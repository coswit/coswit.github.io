# 第2章 普通模式（Normal mode）

> 核心观念：**普通模式是 Vim 的默认模式**。像画家一样——大部分时间在观察思考，落笔（进入插入模式）只是短暂瞬间。

## 停顿时请移开画笔（Pause with Purpose）

- 新手的坏习惯：长时间停留在插入模式。插入模式只该在"输入文本"时存在，一旦停顿（思考、移动、翻页），就该按 `<Esc>` 回到普通模式。
- 普通模式下双手处在"起始位"，随时可以发出任何命令；插入模式只干一件事——输入字符。

## 把撤销单元切成块（Chunk Your Undos）

`u` 撤销的是"一个修改单元"，因此**用 `<Esc>` 把大段输入切成多个可撤销的块**：

- 每完成一小段输入就 `<Esc>` 一次，undo 粒度才合理；
- 两种情况会把修改"一分为二"，注意规避：
  - 插入模式中用 `<C-u>`（删到行首）会重置修改状态，之前的输入与之后的输入成为两个修改块；
  - 插入模式中按 `<CR>` 换行也会分割修改块。
- 想让一次撤销覆盖一大段：中间不要出现上述分割点。

## 尽量构造可重复的修改（Compose Repeatable Changes）

删除一个单词（含尾随空格）的三种做法，对 `.` 的友好度完全不同：

| 做法 | 步骤 | `.` 重复时的效果 |
| ---- | ---- | ---------------- |
| `dbx` | 先删到词首，再删最后一个字符 | 两个修改，`.` 只重复 `x`，不可控 |
| `dw`（光标在词首） | 删除到下一词首 | 一次修改，但含尾随空格的语义取决于位置 |
| `daw` | 删除"一个单词"这个文本对象 | **一次修改，语义完整，`.` 完美重复** |

- 结论：优先用**文本对象**（`daw`/`diw`/`dap` 等）构造修改，它们让修改单元有稳定语义。

## 用次数做简单的算术运算（Use Counts to Do Simple Arithmetic）

- `<C-a>`：把光标所在或之后的第一个数字加 1；`<C-x>`：减 1。
- 可以带次数：`10<C-a>` 加 10；光标在行首时可直接作用于本行第一个数字。
- 处理 `007` 这类数字时默认按**八进制**解释，建议在 vimrc 中：

```bash
set nrformats=      " 只按十进制处理数字（去掉 octal 等）
```

## 能够重复，就别用次数（Prefer `.` to Counts）

删除两个单词：`d2w`、`2dw`、`dw.` 都能完成，但后续 `.` 的行为不同：

- `dw` + `.`：每次重复删一个词——**修改小而灵活**；
- `d2w` / `2dw` 的 `.` 每次删两个词——万一中途只想删一个就失控。

结论：**除非确定要一次处理多个，否则保持修改粒度最小**，把"重复"留给 `.`。

## 操作符（operator）+ 动作命令（motion）= 操作（Vim 的语法）

**语法规则：`[次数] 操作符 [次数] 动作命令`**

| 操作符 | 用途 | 双击（作用于整行） |
| ------ | ---- | ------------------ |
| `c` | 修改（modify） | `cc` |
| `d` | 删除 | `dd` |
| `y` | 复制到寄存器 | `yy` |
| `g~` | 反转大小写 | `g~~` |
| `gu` | 转为小写 | `guu` |
| `gU` | 转为大写 | `gUU` |
| `>` | 增加缩进 | `>>` |
| `<` | 减小缩进 | `<<` |
| `=` | 自动缩进 | `==` |
| `!` | 用外部程序过滤（filter） | `!!` |

- 动作命令可以是 `l`、`w`、`ap`（一个段落）、`G`、`/text<CR>` 等——**动作命令学得越多，会用的编辑命令呈乘法增长**。
- 例子：`gUaw` 把一个单词全大写；`d2w` 删除两个词；`>G` 从当前行缩进到文件尾。
- 按下操作符后、动作命令前，Vim 处于**操作符等待模式**（operator-pending mode）。
- 扩展阅读：`:h operator`
