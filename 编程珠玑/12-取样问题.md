小程序常常既长知识又有趣；本篇讲的小程序除此之外还对公司有用。

## 12.1 问题

1980 年代初，某民意调查公司刚买了第一批个人电脑。主系统跑起来后，作者鼓励大家留意办公室里能程序化的活。一位机警的员工提议：**从打印的选区列表里随机抽取样本**——手工做要用随机数表熬一小时。

她的原始规格：输入是选区名列表和整数 m，输出是随机选中的 m 个选区（选区名几百个，m 常为 20~40）。动手编码前，对问题定义有什么建议？

作者肯定了想法后指出：敲几百个名字仍然乏味易错——**程序反正要忽略大部分输入，准备一大堆输入就是蠢**。于是规格改成：**输入两个整数 m 与 n（m < n），输出 0..n-1 范围内 m 个随机整数的不重复有序列表**——概率论说法：等概率的无放回有序选取。用户按输出的 4, 15, 17, ... 数着纸面清单勾选第 4、15、17 个名字即可。新规格大受欢迎，一小时的工作缩到几分钟。

## 12.2 一个解

问题定下后，作者直奔手边 Knuth 的《Seminumerical Algorithms》（家里和办公室各备一套三卷本，物有所值），找到 3.4.2 节的 **Algorithm S**：**按序考察 0..n-1，用适当的随机测试决定选不选**——按序访问天然保证输出有序。

选择准则：m=2、n=5 时，第一个整数 0 应以 2/5 概率被选（`bigrand() % 5 < 2`）；但 1 不能也用 2/5——总数可能凑不齐 2 个。所以要偏置：0 被选了，1 以 1/4 被选；0 没被选，1 以 2/4 被选。一般地，**剩 r 个数、还要选 s 个时，下一个数以 s/r 的概率被选**：

```c
select = m
remaining = n
for i = [0, n)
    if (bigrand() % remaining) < select
        print i
        select--
    remaining--
```

只要 m ≤ n，程序恰好选出 m 个：select 减到 0 后不再选；select/remaining 到 1 后必然选。每个子集等可能（Knuth 给出概率证明）。C++ 版：

```c
void genknuth(int m, int n)
{   for (int i = 0; i < n; i++)
        /* select m of remaining n-i */
        if ((bigrand() % (n-i)) < m) {
            cout << i << "\n";
            m--;
        }
}
```

含标题、输入输出、范围检查在内只用了十三行 Basic，问题定义后半小时完成，用了很多年没出问题。它只花几十字节内存，对公司的需求飞快——**但 n 很大时慢**：用它生成几个随机 32 位正整数（n = 2³²）约要 12 分钟。信封小测：用它生成一个随机 48 位或 64 位整数要多久？

## 12.3 解空间

程序员的工作一半是解今天的问题，另一半（也许更重要）是为解明天的问题做准备——最主要的准备方式，就是**追问"这题还能怎么解"的心智体操**。先从一个学生答说起：作者在西点军校研讨班上问有没有比"敲进 200 个名字"更好的办法，一名学员建议：**复印选区清单、用切纸机切开、纸袋里摇匀、抽出要的张数**——教科书级的 conceptual blockbusting（Koestler 会称之为 haha! 洞察：高技术问题的低技术答案，喜剧式的灵感）。

以下都限于"从 0..n-1 随机写 m 个有序整数"的程序方案：

**方案一（Knuth Algorithm S）**：时间 O(n)、空间几十字节——n 巨大时不可行。

**方案二（集合）**：往空集合里插随机整数，插够 m 个为止：

```c
initialize set S to empty
size = 0
while size < m do
    t = bigrand() % n
    if t is not in S
        insert t into S
        size++
print the elements of S in sorted order
```

搁今天不用纠结链表还是搜索树，**C++ 标准模板库（Standard Template Library, STL）直接 `set<int>`**：

```c
void gensets(int m, int n)
{   set<int> S;
    while (S.size() < m)
        S.insert(bigrand() % n);
    set<int>::iterator i;
    for (i = S.begin(); i != S.end(); ++i)
        cout << *i << "\n";
}
```

真代码与伪代码一样长。百万个有序不重复 31 位随机整数约 20 秒——其中光生成打印百万个无序整数就要 12.5 秒，集合操作只占 7.5 秒。STL 保证插入 O(log m)、遍历 O(m)，总时间 **O(m log m)**（m ≪ n 时）；但空间贵：128MB 机器在 m ≈ 1,700,000 附近开始颠簸（集合的实现正是下一篇的主题）。

**方案三（打乱）**：把 0..n-1 装进数组，用 Knuth 3.4.2 的 **Algorithm P** 打乱后取前 m 个：

```c
for i = [0, n)
    swap(i, randint(i, n-1))
```

Ashley Shepherd 与 Alex Woronow 指出只需打乱前 m 个：

```c
void genshuf(int m, int n)
{   int i, j;
    int *x = new int[n];
    for (i = 0; i < n; i++)
        x[i] = i;
    for (i = 0; i < m; i++) {
        j = randint(i, n-1);
        int t = x[i]; x[i] = x[j]; x[j] = t;
    }
    sort(x, x+m);
    for (i = 0; i < m; i++)
        cout << x[i] << "\n";
}
```

n 个字的内存、O(n + m log m) 时间（1.9 题的技术可降到 O(m log m)）。可以看成方案二的变体：**已选集放在 x[0..i-1]、未选集放在 x[i..n-1]——显式表示未选元素，就免去了"新数是否已选"的测试**；但 O(n) 时空使它通常不敌 Knuth 的算法。

**解空间远未穷尽**：n 一百万、m = n−10 时——生成 10 个随机数，输出**不在其中**的那些；n 一千万、m 接近 2³¹ 时——先造去重列表再从中抽样；Solution 9 还有 Bob Floyd 基于搜索的聪明算法（见习题选）。

## 12.4 原则

以下步骤按一种自然顺序列出，但真实设计过程活跃得多：**在各活动间跳来跳去，反复迭代**。

- **Understand the Perceived Problem（理解感知到的问题）**：与用户谈问题的语境。问题陈述里常掺着解法的主意——和所有早期主意一样，该考虑但别只考虑它。
- **Specify an Abstract Problem（规格化抽象问题）**：干净利落的问题陈述先帮我们解这一题，再帮我们看清解法能推广到哪里。
- **Explore the Design Space（探索解空间）**：太多程序员太快跳到"那个"解——**想一分钟、写一天，而不是想一小时、写一小时**。伪代码表达控制流、抽象数据类型表达关键结构；文献知识在此阶段价值连城。
- **Implement One Solution（实现一个解）**：用可用的最强操作、直白地实现选定的设计。（作者批改过程序风格题：多数学生一页纸得中评；两个在大项目泡过一夏天的学生交了五页、一打函数、考究的头注释——不及格。最好程序五行就能工作，六十倍的膨胀太多了。二人抱怨"我们用的是标准软件工程工具"，作者本该引 Pamela Zave 的话：**软件工程的目的是控制复杂度，不是制造复杂度**。)
- **Retrospect（复盘）**：Polya《How To Solve It》第 15 页：**"总有事情可做：足够深入地研究，任何解都能改进；无论如何，我们总能改进对解的理解。"**

## 12.5 习题选

**1.C 库 rand() 约返回 15 个随机位，实现 bigrand()（≥30 位）与 randint(l, u)。**

```c
int bigrand()
{   return RAND_MAX*rand() + rand(); }
int randint(int l, int u)
{   return l + bigrand() % (u-l+1); }
```

**2."每个子集等概率"强于"每个整数以 m/n 被选"。给一个每数等概率、子集不等概率的算法。** 随机选 i，输出 i, i+1, ..., i+m-1（可回绕）——每个整数都以 m/n 被选，但强烈偏向连号子集。

**9.[R. W. Floyd] m 接近 n 时集合法浪费随机数，能否最坏情况也只用 m 个？** Floyd 算法：

```c
void genfloyd(int m, int n)
{   set<int> S;
    set<int>::iterator i;
    for (int j = n-m; j < n; j++) {
        int t = bigrand() % (j+1);
        if (S.find(t) == S.end())
            S.insert(t); // t not in S
        else
            S.insert(j); // t in S
    }
    for (i = S.begin(); i != S.end(); ++i)
        cout << *i << "\n";
}
```

**10.顺序看到 n 个对象但事先不知道 n，如何随机选一个？**（如不知行数地读文件选一行）——**蓄水池抽样（Reservoir Sampling）**：第一行总选；第二行以 1/2 换掉、第三行以 1/3 换掉……结束时每行被选中的概率都是 1/n：

```c
i = 0
while more input lines
    with probability 1.0/++i
        choice = this input line
print choice
```

**11.[Shamos] 促销卡 16 个格点藏 1..16 的随机排列，刮开若先见 3 则输、1 和 2 都露出则赢，限一小时的 CPU 算获胜概率。** 满分答案：4..16 与胜负无关——赢 ⟺ 1、2 都在 3 之前 ⟺ **3 是三者中最后被选的，概率恰 1/3**。几分钟 CPU 的方案零分，"去问统计教授"半分。**别被问题陈述误导：CPU 时间在那儿，不代表非用不可。**
