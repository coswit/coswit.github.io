本篇讲**堆（heap）**——一个用来解决两个重要问题的数据结构：

- **排序**：Heapsort 排 n 元素数组**最坏情况也不超过 $O(n\log n)$**，额外空间只有几个字。
- **优先队列（priority queue）**：在"插入新元素"与"提取最小元素"两个操作下维护一个集合，每个操作 $O(\log n)$。

两个问题里，堆都编码简单、计算高效。本篇自底向上组织：从细节起步爬到大图景。

## 14.1 数据结构

（术语澄清：其他语境里 "heap" 指分配变长节点的大块内存——本篇忽略那个含义。）

二叉树成为堆靠两条性质。**序（order）**：任何节点的值 ≤ 其子节点的值——最小元素必在根（例中是 12），但左右子节点之间无大小约束。**形（shape）**：叶节点至多出现在两层上，且最底层尽量靠左——树中没有"洞"，n 个节点中任何节点离根不超过 $\log_2 n$。两条性质合起来：**严到能立刻找到最小元素，松到插入删除后能高效重组**。

实现不用记录加指针，而用**隐式表示**：有 shape 性质的二叉树恰好映射进数组 x[1..n]——根在 x[1]，其子节点在 x[2]、x[3]，以此类推（声明 x[n+1]、浪费 x[0]）：

```c
root = 1
value(i) = x[i]
leftchild(i) = 2*i
rightchild(i) = 2*i+1
parent(i) = i / 2
null(i) = (i < 1) or (i > n)
```

n 元素的隐式树天然具有 shape 性质（表示法不提供"缺元素"的位置）。从此 **heap 就意味着数组 x[1..n] 满足**：

$$\forall\ 2 \le i \le n:\quad x[i/2] \le x[i]$$

（"/" 整除向下取整，4/2 与 5/2 都是 2。）子数组 x[l..u] 的堆性质相应记作 heap(l, u)。

## 14.2 两个关键函数

堆性质在一端被破坏时如何修复？两个函数，各约 $\log n$ 步。

**siftup**：x[1..n-1] 已是堆、往 x[n] 塞了个任意元素——把新元素**向上筛**，一路与父节点交换，直到 ≥ 父节点或到达根。循环不变量：

```c
loop
    /* invariant: heap(1, n) except perhaps
            between i and its parent */
```

i == 1 则无父节点，堆性质处处成立，终止；否则 p = i/2，若 x[p] ≤ x[i] 同样终止；失序则交换。交换后五处皆序（原高处的 b < d、b < e；测试失败说明 a < b；结合 a < b < c 得 a < c）——堆性质除 p 与其父之间外处处成立，令 i = p 恢复不变量：

```c
void siftup(n)
         pre n > 0 && heap(1, n-1)
         post heap(1, n)
     i = n
     loop
         /* invariant: heap(1, n) except perhaps
                 between i and its parent */
         if i == 1
             break
         p = i / 2
         if x[p] <= x[i]
             break
         swap(p, i)
         i = p
```

（Knuth 指出这个不变量还不够精确，严格版应是"heap(1, n) 在 i 无父时成立；否则把 x[i] 换成 x[p] 便成立"——siftdown 同理。）

**siftdown**：x[1..n] 已是堆、给 x[1] 赋了新值——heap(2, n) 成立，把 x[1] **向下筛**，直到无子节点或 ≤ 子节点。向上筛只会奔向根；向下筛更复杂：**失序元素与较小的那个子节点交换**（例中 18 一路下筛，最后小于其唯一子节点 19）。不变量与代码：

```c
void siftdown(n)
        pre   heap(2, n) && n >= 0
        post  heap(1, n)
    i = 1
    loop
        /* invariant: heap(1, n) except perhaps between
                i and its (0, 1 or 2) children */
        c = 2*i
        if c > n
            break
        /* c is the left child of i */
        if c+1 <= n
            /* c+1 is the right child of i */
            if x[c+1] < x[c]
                c++
        /* c is the lesser child of i */
        if x[i] <= x[c]
            break
        swap(c, i)
        i = c
```

两个函数都在堆的每层做常量工作，时间正比于 $\log n$。

## 14.3 优先队列

数据结构都有两面：**外面**看规格（做什么），**里面**看实现（怎么做）。优先队列操作一个初始为空的（多重）集合 S：

```c
void insert(t)
        pre   |S| < maxsize
        post  current S = original S ∪ {t}

int extractmin()
        pre   |S| > 0
        post  original S = current S ∪ {result}
                && result = min(original S)
```

C++ 类规格：

```c
template<class T>
class priqueue {
public:
    priqueue(int maxsize);  // init set S to empty
    void insert(T t);       // add t to S
    T extractmin();         // return smallest in S
};
```

应用遍地：操作系统用它管理任务集（任意序插入、提取下一个要执行的）；离散事件模拟里元素是事件时间，模拟循环提取下一事件并可能加入新事件。线性结构两头不讨好：**有序序列易取最小难插入，无序序列反反过来**——n 元集合上两种都是一侧 $O(1)$ 另一侧 $O(n)$（忘了 $O(n^2)$ 与 $O(n\log n)$ 差别的，复习 8.5 节：n 为一百万时是三小时对一秒）。

**堆实现**是两个极端之间的中道：集合放满足堆性质的 x[1..n]（声明 x[maxsize+1]，不用 x[0]）。插入：n 加一、新元素放 x[n]——正是 siftup 的前置状态。取最小：最小在 x[1]；把 x[n] 移到 x[1] 并把 n 减一——heap(2, n) 成立，正是 siftdown 的前置状态：

```c
void insert(t)
    if n >= maxsize
        /* report error */
    n++
    x[n] = t
    /* heap(1, n-1) */
    siftup(n)
    /* heap(1, n) */

int extractmin()
    if n < 1
        /* report error */
    t = x[1]
    x[1] = x[n--]
    /* heap(2, n) */
    siftdown(n)
    /* heap(1, n) */
    return t
```

两操作都是 $O(\log n)$。完整 C++ 实现（玩具接口无错误检查无析构，但算法内核尽出；与正文的松散伪代码相对，这是致密风格的另一极端）：

```c
template<class T>
class priqueue {
private:
    int n, maxsize;
    T *x;
    void swap(int i, int j)
    {   T t = x[i]; x[i] = x[j]; x[j] = t; }
public:
    priqueue(int m)
    {   maxsize = m;
        x = new T[maxsize+1];
        n = 0;
    }
    void insert(T t)
    {   int i, p;
        x[++n] = t;
        for (i = n; i > 1 && x[p=i/2] > x[i]; i = p)
            swap(p, i);
    }
    T extractmin()
    {   int i, c;
        T t = x[1];
        x[1] = x[n--];
        for (i = 1; (c = 2*i) <= n; i = c) {
            if (c+1 <= n && x[c+1] < x[c])
                c++;
            if (x[i] <= x[c])
                break;
            swap(c, i);
        }
        return t;
    }
};
```

## 14.4 一种排序算法

优先队列给出朴素的排序：逐个插入，再按序取出——n 次 insert 加 n 次 extractmin，最坏 $O(n\log n)$，胜过 Column 11 各 Quicksort 的 $O(n^2)$ 最坏情形；代价是堆数组 x[0..n] 要 n+1 个额外字。

**Heapsort** 改进这条路：代码更少、不用辅助数组、时间更少。为此设 siftup/siftdown 已改成**大元素在顶**的版本（交换 "<" 与 ">" 即可）。单个数组 x 同时表示两个抽象结构：**左端是堆，右端是序列**（起初任意序，最终排好序）——时间沿纵轴向下、数组沿横轴演化的图景：

两阶段。第一阶段**建堆**（不变量：x[1..i-1] 是堆）：

```c
for i = [2, n]
    /* invariant: heap(1, i-1) */
    siftup(i)
    /* heap(1, i) */
```

第二阶段**从右往左建有序序列**（不变量：前 i 个是堆、其后有序、且堆中元素 ≤ 序列元素）：x[1] 是前 i 个中最大者，与 x[i] 交换就把有序段扩一格；交换破坏堆性质，对新顶元素 siftdown 修复：

```c
for (i = n; i >= 2; i--)
    /* heap(1, i)   && sorted(i+1, n) && x[1..i]   <= x[i+1..n] */
    swap(1, i)
    /* heap(2, i-1) && sorted(i, n)   && x[1..i-1] <= x[i..n] */
    siftdown(i-1)
    /* heap(1, i-1) && sorted(i, n)   && x[1..i-1] <= x[i..n] */
```

靠已造好的零件，**完整 Heapsort 只要五行**：

```c
for i = [2, n]
    siftup(i)
for (i = n; i >= 2; i--)
    swap(1, i)
    siftdown(i-1)
```

n−1 次 siftup 加 siftdown、每次至多 $O(\log n)$，**最坏也是 $O(n\log n)$**。但注意：尽管 Heapsort 保证最坏性能，**典型输入上最快的 Heapsort 通常仍慢于 11.2 节的简单 Quicksort**。

## 14.5 原则

- **Efficiency（效率）**：shape 性质保证所有节点距根 $\log_2 n$ 层以内——siftup/siftdown 快正因为树平衡；Heapsort 把堆与序列两个抽象结构**叠加（overlay）**进同一实现数组，省掉额外空间。
- **Correctness（正确性）**：写循环先精确陈述不变量，循环向终止推进的同时维持不变量；shape 与 order 则是另一种不变量——**数据结构的不变性质**：操作堆的函数可以假定它们起初为真，也必须保证结束时仍为真。
- **Abstraction（抽象）**：好工程师区分组件"做什么"（用户看到的抽象）与"怎么做"（黑箱内的实现）。本篇把黑箱打包了两种方式：**过程抽象**（procedural abstraction）——siftup/siftdown 定义一次，组装出优先队列与 Heapsort 两种工具；**抽象数据类型（Abstract Data Type, ADT）**——priqueue 类与上篇的 IntSet 类只凭规格就能推理正确性，实现只影响性能。

## 14.6 习题选

**2.把 siftdown 改成 `siftdown(l, u)`（pre: heap(l+1, u); post: heap(l, u)），如何用它 O(n) 建堆、得到更快更省代码的 Heapsort？** 从 n/2 到 1 反复 siftdown：`for i = [n/2, 1] siftdown(i)`——自底向上建堆，总代价收敛到 O(n)。

**4.堆式优先队列怎么解这些问题？输入已排序时答案有何变化？** (a) **Huffman 编码**：反复取最小的两棵树合并——正是 extractmin×2 + insert；(b) 大量浮点数求和：朴素顺序相加会把小数加进大数里损失精度，改为**反复取集合中最小的两个相加、和放回**（与 Huffman 同构）；(c) 十亿数中找最大的一百万个：维护一百万元素的最小堆，扫文件时元素大于堆顶则替换；(d) 多个小有序文件归并成一个大文件：每文件当前元素进堆，每次取最小写出并从其文件补入，n 路归并每步 O(log n)。

**5.装箱问题 first-fit 启发式如何用堆式结构 O(n log n) 实现？**（Johnson 的 MIT 论文）在箱子序列上盖一棵堆式树，每个节点记录其子树中**最满可用箱**的剩余容量；放新重量时"能走左就走左，必须才走右"，深度 O(log n)，放入后回溯修正路径上的容量。

**6.McCreight 在 Xerox PARC 设计磁盘控制器：每块加一个额外指针，使读第 i 块从 O(i) 降到 O(log i)——怎么实现？与 4.9 题的 log 时间求幂有何共通？** 常规实现是块 i 指向块 i+1；McCreight 让**块 i 再指向块 2i**。读第 n 块：n 为偶则折半、为奇则先减一再折半，O(log n) 次访问——与 4.9 题"反复平方"求幂的递归结构同构。
