我们被字符串包围：位串构成整数与浮点数，数字串构成电话号码，字符串构成单词；长字符串构成网页，更长的构成书；由 A、C、G、T 表示的超长字符串躺在遗传学家的数据库里。程序对字符串做的事五花八门——排序、计数、搜索、分析模式。本篇用几个经典的字符串问题把这些主题过一遍。

## 15.1 单词

第一个问题：生成文档中的单词列表。词的定义取最平凡的"空白符包围的字符序列"——网页里会冒出 `<html>`、`&nbsp;` 这样的"词"（习题 1 处理）。标准模板库（Standard Template Library, STL）的 set 与 string 给出优雅且相当高效的程序：

```c
int main(void)
{   set<string> S;
    set<string>::iterator j;
    string t;
    while (cin >> t)
        S.insert(t);
    for (j = S.begin(); j != S.end(); ++j)
        cout << *j << "\n";
    return 0;
}
```

下一个问题：**统计每个单词的出现次数**。King James 版圣经的前几名：

```text
the  62053           shall 9756           they 6890
and  38546           he    9506           be   6672
of   34375           unto  8929           is   6595
to   13352           I     8699           with 5949
And  12734           his   8352           not  5840
that 12428           a     7940           all  5238
in   12154           for   7139           thou 4629
```

789,616 个词里近 8% 是 "the"（对比：本句里 16%）。STL 的 **map** 把整数计数与字符串关联起来：

```c
int main(void)
{   map<string, int> M;
    map<string, int>::iterator j;
    string t;
    while (cin >> t)
        M[t]++;
    for (j = M.begin(); j != M.end(); ++j)
        cout << j->first << " " << j->second << "\n";
    return 0;
}
```

直白、精炼、快得出奇——处理圣经 7.6 秒（读入 2.4 秒、插入 4.9 秒、输出 0.3 秒）。**自建哈希表还能再快**：节点含指向单词的指针、计数、下一节点指针：

```c
typedef struct node *nodeptr;
typedef struct node {
    char *word;
    int count;
    nodeptr next;
} node;

#define NHASH 29989
#define MULT 31
nodeptr bin[NHASH];
```

圣经按我们的宽定义只有 29,131 个不同的词——老经验取**邻近的素数**做表长，乘数取流行的 31：

```c
unsigned int hash(char *p)
    unsigned int h = 0
    for ( ; *p; p++)
        h = MULT * h + *p
    return h % NHASH
```

（unsigned 保证 h 非负。）统计与建链：

```c
void incword(char *s)
    h = hash(s)
    for (p = bin[h]; p != NULL; p = p->next)
        if strcmp(s, p->word) == 0
            (p->count)++
            return
    p = malloc(sizeof(node))
    p->count = 1
    p->word = malloc(strlen(s)+1)
    strcpy(p->word, s)
    p->next = bin[h]
    bin[h] = p
```

查遍同哈希值的链表：找到则计数加一返回；没找到则建新节点、拷字符串、**插到链表前头**。实测：读入同样 2.4 秒，插入从 4.9 秒降到 **0.5 秒**，输出 0.06 秒——**总计 3.0 秒对 7.6 秒，30 行 C 的定制哈希表比 STL 的 map 快一个数量级**。

单词集合的两大表示法由此分明：**平衡搜索树**把字符串当不可分割的整体操作（多数 STL set/map 的实现），始终保序，高效支持找前驱、按序输出；**哈希**窥进字符内部算哈希函数、把键撒进大表——平均极快，但没有最坏情形保证，也不支持涉及顺序的操作。

## 15.2 短语

单词是文档的基本构件，但人们常在长文本里搜**短语**（"substring searching"、"implicit data structures"）。没见过文本就只能从头扫到尾（算法书里的"子串搜索问题"）；**若能预处理**，可以建"倒排索引"——索引每个不同的词及其每次出现的位置，查短语靠交集（微妙且可能慢，但一些搜索引擎正是这么做的）。

下面用一个**强大结构**解一个小问题：**找出文本中最长的重复子串**。"Ask not what your country can do for you, but what you can do for your country" 里最长重复串是 " can do for you"，" your country" 紧随其后。直接比较所有子串对至少 $O(n^2)$；换条路——**后缀数组（suffix array）**（结构至少 1970 年代就在用，术语 1990 年代才提出）：指针数组 a，每个元素指向输入串的对应位置，于是 a 合起来指向**每个后缀**。"banana" 的后缀数组：

```text
a[0]: banana      排序后:      a[0]: a
a[1]: anana                   a[1]: ana
a[2]: nana                     a[2]: anana
a[3]: ana                      a[3]: banana
a[4]: na                       a[4]: na
a[5]: a                        a[5]: nana
```

**排序把相等的后缀聚到一起**（正如 2.4 节排序聚拢变位词），然后扫一遍比较相邻元素找最长公共前缀——"banana" 的答案是 "ana"。完整程序核心：

```c
#define MAXN 5000000
char c[MAXN], *a[MAXN];

/* 读入: a[n] = &c[n]; c[n++] = ch; 末尾 c[n] = 0 */

int comlen(char *p, char *q)
    i = 0
    while *p && (*p++ == *q++)
        i++
    return i

qsort(a, n, sizeof(char *), pstrcmp)   /* pstrcmp 给 strcmp 加一层间接 */

for i = [0, n)
    if comlen(a[i], a[i+1]) > maxlen
        maxlen = comlen(a[i], a[i+1])
        maxi = i
printf("%.*s\n", maxlen, a[maxi])     /* "*"精度只打 maxlen 个字符 */
```

在 Samuel Butler 译《伊利亚特》的 807,503 字符上运行 4.8 秒，找到的长重复串是 Juno 劝 Minerva、随后 Minerva 又逐字复述给 Ulysses 的同一段话。排序主导，典型文本 $O(n\log n)$。**后缀数组用文本本身加 n 个指针，表示了文本的所有子串**——习题 6 研究如何用它解子串搜索。

## 15.3 生成文本

怎么生成随机文本？经典画面：猴子扑向打字机。等概率敲小写字母与空格，产出是 `uzlpcbizdmddk njsdzyyvfgxbgjjgbtsak rqvpgnsbyputvqqdtmgltz ynqotqigexjumqphujcfwnll jiexpyqzgsdllgcoluphl sefsrvqqytjakmav bfusvirsjl wprwqt`——毫无说服力。按文档字母频率加权（A 出现 300 次、B 100 次，则敲 A 的概率是 B 的三倍）接近一小步。再进一步靠**上下文**：今天是 85°F，明天不太可能是 15°；前一个字母是 Q，下一个多半是 U。让每个字母成为前一字母的随机函数，就有了各阶近似（order-k）：

```text
Order-1: 11 amy, vin. id wht omanly heay atuss n macon aresethe hired boutwhe t, tl, ad torurest t plur I wit hengamind tarer-plarody thishand.
Order-2: Ther I the heingoind of-pleat, blur it dwere wing waske hat trooss. Yout lar on wassing, an sit." "Yould," "I that vide was nots ther.
Order-3: 1 has them the saw the secorrow. And wintails on my my ent, thinks, fore voyager lanated the been elsed helder was of him a very free bottlemarkable,
Order-4: His heard." "Exactly he very glad trouble, and by Hopkins! That it on of the who difficentralia. He rushed likely?" "Blood night that.
```

order-2 用二元组（digram）、order-3 用三元组（trigram）；到 order-4，多数词已是英语——语料是福尔摩斯故事。有数学背景的读者认得这是 **Markov 链**：每个 k-gram 是一个状态，状态间转移概率固定——"有限状态、平稳转移概率的 Markov 链"。词级生成更有趣（order-2 通常最适戏仿）。作者首次见到是在 Shannon 1948 年《通信的数学理论》——Shannon 手工翻书随机取样构造近似文本，并说"下一阶段的劳动量会变得巨大"。程序正可代劳。词级 order-k Markov 链的 C 程序：

```c
int k = 2;
char inputchars[5000000];
char *word[1000000];
int nword = 0;
```

不逐字扫全文，而是把 word 数组当作**只在词边界起始的后缀数组**；读入时每词追加进 inputchars（无须其他分配）：

```c
word[0] = inputchars
while scanf("%s", word[nword]) != EOF
    word[nword+1] = word[nword] + strlen(word[nword]) + 1
    nword++
```

比较函数 `wordncmp` 比较两个指针指向的**前 k 个词**（遇 0 字符计数减一，减到零即相等）。读入后补 k 个 0（防越界）、打印开头 k 个词、排序把指向同一 k 词序列的指针聚拢。k=1、输入 "of the people, by the people, for the people" 时：

```text
word[0]: by the        word[4]: people, for
word[1]: for the       word[5]: people, by
word[2]: of the        word[6]: the people,
word[3]: people        word[7]: the people
                         word[8]: the people,
```

要找 "the" 后面跟什么，在后缀数组里一查：三个候选——"people," 两次、"people" 一次。生成循环（骨架）：

```c
phrase = first phrase in input array
loop
    perform a binary search for phrase in word[0..nword-1]
    for all phrases equal in the first k words
        select one at random, pointed to by p
    phrase = word following p
    if k-th word of phrase is length 0
        break
    print k-th word of phrase
```

二分查找用 **9.3 节的版本**——它恰好返回**第一次出现**，这点至关重要；等值短语中随机选一个用 **Solution 12.10 的蓄水池技巧**（`if rand() % (i+1) == 0` 则更新候选）。完整实现：

```c
phrase = inputchars
for (wordsleft = 10000; wordsleft > 0; wordsleft--)
    l = -1
    u = nword
    while l+1 != u
        m = (l + u) / 2
        if wordncmp(word[m], phrase) < 0
            l = m
        else
            u = m
    for (i = 0; wordncmp(phrase, word[u+i]) == 0; i++)
        if rand() % (i+1) == 0
            p = word[u+i]
    phrase = skip(p, 1)
    if strlen(skip(phrase, k-1)) == 0
        break
    print skip(phrase, k-1)
```

其中 `skip(p, i)` 返回从 p 向后数第 i 个词的起始位置：`skip(p, 1)` 即 p 的下一个词，`skip(phrase, k-1)` 即短语的第 k 个词。

Kernighan 与 Pike《The Practice of Programming》第 3 章正是围绕词级 Markov 文本生成讲"设计与实现"，用 C、Java、C++、Awk、Perl 各实现了一遍。本节程序与他们的 C 版相比：代码约短一半——**用"指向 k 个连续词的指针"表示短语，既省空间又易实现**；MB 级输入速度相当，但因 K&P 用稍大的结构且大量调用低效 malloc，本程序省一个数量级内存；若再按习题 14 把二分与排序换成哈希表，还能再快一倍（内存多五成）。

## 15.4 原则

- **String Problems（字符串问题）**：编译器怎么在符号表里查变量名？帮助系统怎么随你敲字搜遍整张 CD-ROM？搜索引擎怎么查短语？——真实问题用的正是本篇玩具问题里瞥过的技术。
- **Data Structures for Strings（字符串的数据结构）**：**哈希**——平均快、易实现；**平衡树**——怪异输入下也保证性能，STL 的 set/map 打包现成；**后缀数组**——指针指向每个字符（或每个词）、排序即得，扫一遍找近似串，或二分查词查短语。13.8 节还有词典的更多结构。
- **Libraries or Custom-Made Components?（库还是定制组件？）**：STL 的 set/map/string 顺手，但通用强大的接口不及专用哈希函数高效；另一些库组件又非常高效——哈希用了 strcmp，后缀数组用了 qsort；作者还偷看了库的 bsearch 与 strcmp 实现来写 Markov 程序里的二分与 wordncmp。
