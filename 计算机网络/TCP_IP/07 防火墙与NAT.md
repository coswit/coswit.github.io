> 防火墙的类型与部署；NAT/NAPT 的原理、变体与副作用。

## 1. 防火墙（Firewalls）

防火墙是在受信网络与不受信网络之间**实施访问控制策略**的设备/软件（RFC 4948 互联网威胁模型：假定攻击者能读写线路上的任意流量）。

### 按实现位置

- **个人防火墙**：运行在端主机上的软件（如 Windows 防火墙）。
- **边界防火墙**：部署在网络边界（内部网 ↔ Internet）。

### 按技术类型

| 类型 | 工作层次 | 说明 |
| ---- | ---- | ---- |
| **包过滤（Packet-Filtering）** | 网络层/运输层 | 无状态，逐包按规则（五元组、标志位）允许/拒绝；简单高效，但无法关联同一连接的包 |
| **状态防火墙（Stateful）** | 3/4 层 + 连接跟踪 | 维护连接状态表（TCP 状态、UDP 模拟流），只放行"回包"；典型规则"内→外任意，外→内仅限已建连接的回包" |
| **代理防火墙（Proxy / Application-Layer Gateway, ALG）** | 应用层 | 终结两侧连接，按应用协议（HTTP/FTP/SIP…）深度检查/重写；安全性最高、开销最大 |

### 常见部署：DMZ

```
        Internet
           │
      [边界路由器/防火墙]
           │
   ┌───────┴────────┐
   │      DMZ       │  ← 对外服务区 (Web/Mail), 放宽入站规则
   └───────┬────────┘
      [内部防火墙]
           │
       内部网络        ← 严格限制入站
```

- **策略要点**：默认拒绝（default deny）、最小开放；无状态防火墙可近似模拟状态——入站方向放行"带 ACK 标志的包"（连接的首个 SYN 不带 ACK）。
- 防火墙与 ICMP：需放行 PMTUD 所需的 ICMP Destination Unreachable (code 4) / Packet Too Big，否则大包黑洞（第 8 章）。

Linux netfilter 状态防火墙的经典形态（conntrack 跟踪连接状态）：

```bash
iptables -A FORWARD -m conntrack --ctstate ESTABLISHED,RELATED -j ACCEPT  # 放行回包
iptables -A FORWARD -p tcp --dport 443 --syn -m conntrack --ctstate NEW -j ACCEPT
```

## 2. NAT / NAPT（网络地址转换）

### 产生背景

- IPv4 地址耗尽；RFC 1918 私有地址 + NAT 让大量主机共享少量公网地址上网。

### 传统 NAT（Basic NAT）与 NAPT

- **Basic NAT（一对一）**：只转换 IP 地址，一个公网地址同时只能映射一个私网主机——早已不用。
- **NAPT（Network Address and Port Translation，端口转换）**：同时转换 IP 与端口，**一个公网地址可支持数万并发流**——事实上所有家用/企业路由器都做 NAPT（常被直接叫 NAT）。

### NAPT 工作原理

```
内网主机 10.0.0.5:54321 ──▶ 203.0.113.2:80
路由器改写: 源 10.0.0.5:54321 → 公网IP:40001, 记录映射表
             {10.0.0.5:54321 ⇄ 公网IP:40001} | 对端 203.0.113.2:80
回包 公网IP:40001 ← 203.0.113.2:80, 按表改回目的 10.0.0.5:54321
```

- TCP 与 UDP 各自维护映射表；一些实现也能 NAT ICMP（把 ICMP echo 的 ID 当作端口）。
- 映射表项带空闲超时（TCP 常为小时级、UDP 分钟级）。

### 私有地址+ NAT 的代价（破坏端到端）

NAT 违背 Internet 的端到端设计原则：

- 内网主机**不能被外部主动访问**（无映射可寻址）——P2P、VoIP、游戏联机困难。
- 违背分层：中间设备改写运输层内容；协议若把地址/端口编码进载荷（如 FTP PORT 命令、SIP）就需 **ALG** 深度改写，容易出错。
- 重复的私网地址使两网合并/VPN 互连时地址冲突。

### NAT 穿越技术

| 技术 | 原理 |
| ---- | ---- |
| **端口映射（port forwarding）** | 静态配置"公网端口 → 内网主机:端口"，服务器可被外部访问 |
| **UPnP IGD / NAT-PMP / PCP** | 内网应用**主动请求**网关建立映射（RFC 6887 PCP） |
| **打洞（Hole Punching）** | 双方先经服务器（Rendezvous）交换公网/私网地址，再**同时**向对方公网映射发包，在双方 NAT 上各"打出一个洞"（UDP 打洞最成熟；TCP 打洞也可行） |
| **中继（Relay）** | 无法打洞时经公共服务器中转（如 TURN；Skype 早期超级节点） |

- STUN（RFC 5389）：客户端借 STUN 服务器探测自己的公网映射地址与 NAT 行为类型（全锥/受限锥/端口受限锥/对称）。

### 其他 NAT 变体

- **双向 NAT（Bi-directional / Twice NAT）**：**内网与外部地址空间重叠**（两网都使用 10.0.0.0/8）时，同时转换源与目的地址。
- **载波级 NAT（CGN / NAT444）**：ISP 内再叠加一层 NAT，多用户共享公网地址池；带来端口耗尽、滥用追溯困难等问题。
- **NAT64 + DNS64**：IPv6 客户端访问 IPv4 服务器（第 5 章）。

## 3. NAT 对各协议的影响（速查）

| 协议 | 问题/对策 |
| ---- | ---- |
| TCP/UDP 常规客户端 | 基本无感知（出站自动建立映射） |
| 服务器/P2P | 需端口映射/打洞/中继 |
| FTP (主动模式) | PORT 命令含内网 IP → 需 ALG 改写 |
| IPsec AH | AH 校验覆盖 IP 头 → NAT 改地址导致校验失败；ESP + NAT-T（UDP 4500 封装）解决 |
| ICMP | 错误报文需 NAT 网关正确改写内嵌头部的地址/端口 |
| PMTUD | ICMP Too Big 被丢会导致黑洞 |

## 4. 要点回顾

- 防火墙：包过滤（无状态）→ 状态防火墙（连接跟踪）→ 应用层代理（深度检查）；默认拒绝。
- NAPT 同时改 IP 与端口，一张映射表支撑多路复用；代价是打破端到端可达性与分层。
- 穿越：端口映射、UPnP/PCP、打洞（STUN 探测 + 同时发包）、中继（TURN）。
- 地址重叠场景用 Twice NAT；IPv6 时代 NAT64/DNS64 提供 v4 互访。
