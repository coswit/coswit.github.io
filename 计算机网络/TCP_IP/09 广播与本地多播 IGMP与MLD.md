> IPv4 广播地址类型；组播地址与 MAC 映射；IGMP/MLD 如何管理"谁在收组播"。

## 1. 广播（Broadcasting，仅 IPv4）

| 类型 | 地址 | 行为 |
| ---- | ---- | ---- |
| **受限广播（Limited Broadcast）** | `255.255.255.255` | 仅在本链路广播，**路由器不转发**；主机尚无 IP 时（DHCP 阶段）只能用它 |
| **定向广播（Directed Broadcast / Net-directed）** | 主机位全 1，如 `192.0.2.255`（/24） | 发往"某网络/某子网"的广播，**可被路由器转发**（默认通常关闭，防 Smurf 攻击） |
| **子网广播（Subnet-directed）** | 如 `192.0.2.127/26` | 定向广播作用于子网，最常用 |
| **全子网定向广播** | 旧分类网络的所有子网广播（已废弃） | — |

- 广播帧目的 MAC = `ff:ff:ff:ff:ff:ff`，链路上**所有**网卡都要接收并上交处理——大量广播会拖累全网主机。
- IPv6 **没有广播**，一律用组播替代。

## 2. 组播（Multicasting）

### 组播地址

- IPv4 组播地址：**224.0.0.0/4**（224.0.0.0 – 239.255.255.255），高 4 bit 为 `1110`。
  - `224.0.0.0/24`：**链路本地范围**（TTL=1，路由器不转发），如 224.0.0.1 全主机、224.0.0.5/6 OSPF、224.0.0.9 RIPv2、224.0.0.13 所有 PIM 路由器。
  - `239.0.0.0/8`：**管理范围（administratively scoped）**，组织内私用（类比私网 IP）。
- IPv6 组播地址：`ff00::/8`，格式 `ff | flags | scope | group(112bit)`（scope 见第 2 章，如 `ff02::1` 链路上所有节点、`ff02::1:ffXX:XXXX` solicited-node）。
- **范围控制（scoping）**：限制组播传播范围的两种手段——**TTL scoping**（TTL=1 只在本链路，数值大跨区域，粒度粗糙）与**管理范围（administrative scoping）**（239/8 或 IPv6 的 scope 字段，语义明确，现代首选）。

### 组播 IP → MAC 映射

```
IPv4: IP 低 23 bit → MAC 01:00:5e:<IP[bit8] : 低16bit中低7bit+1bit 0>:<...>
      固定前缀 01:00:5e + 第4字节高7bit置0 + 低23bit
例: 224.0.0.1 → 01:00:5e:00:00:01
    (因低23bit映射, 32个组播IP共享同一MAC, 接收方需软件过滤)

IPv6: 组播地址低 32 bit → MAC 33:33:<低32bit>
例: ff02::1:ff5a:9f3d → 33:33:ff:5a:9f:3d
```

### 发送与接收组播

- 发送：目的 IP = 组播组地址，帧目的 MAC = 映射的组播 MAC；不需要特殊权限。
- 接收：应用 `join` 一个组（socket 选项 `IP_ADD_MEMBERSHIP`）；主机在接口上登记该组，从而开始接受该组流量。
- **组播路由**（PIM、DVMRP 等）负责跨网络分发，本书仅涉及**本地（链路内）**组播管理。

## 3. IGMP（Internet Group Management Protocol，IPv4）

IGMP 让主机告诉**同链路路由器**"我在（不在）收某组的流量"，路由器据此决定是否把组播流量引入本链路。IGMP 报文封装在 IPv4（Protocol=2），TTL=1，目的地址为 224.0.0.x。

### 版本演进

| 版本 | 报文 | 特性 |
| ---- | ---- | ---- |
| **IGMPv1** (RFC 1112) | Membership Query(0x11) / Report(0x12) | 查询→应答；离组靠超时（不发离开报文） |
| **IGMPv2** (RFC 2236) | + Leave Group(0x17)、Report(0x16)、v1 Report(0x12) | 显式离组；查询中带 Max Resp Time（响应散布范围可调）；兼容 v1 |
| **IGMPv3** (RFC 3376) | Report(0x22)、Query(0x11 带版本) | 支持**源过滤**（SSM：只收/排除特定源的组播，`INCLUDE/EXCLUDE` 源列表） |

### 基本交互（以 v2 为例）

```
多播路由器(查询者 Querier): 周期(如125s)发 General Query → 224.0.0.1
主机A 想收 239.1.1.1:        随机延迟后发 Membership Report → 组地址
路由器收到 Report:           在链路上维持该组, 继续向链路转发该组流量
主机A 离组:                  发 Leave(→ 224.0.0.2 所有路由器)
路由器:                      发 Group-Specific Query 确认还有无人收, 无应答则停发
```

- **响应抑制**：主机对查询延迟随机时间再答；期间听到别的主机对同组的 Report 就**取消**自己的应答（避免重复报告）。
- 链路上多台组播路由器时，IP 地址最小者当选 **Querier（查询者）**。

## 4. MLD（Multicast Listener Discovery，IPv6）

MLD = ICMPv6 报文（类型 130/131/132/143），功能与 IGMP 对应：

| MLD 版本 | 对应 IGMP | 报文（ICMPv6 Type） |
| ---- | ---- | ---- |
| MLDv1 (RFC 2710) | IGMPv2 | 查询 130 / 报告 131 / 完成 132 |
| MLDv2 (RFC 3810) | IGMPv3 | 查询 130 / 报告 **143**（含源过滤） |

- MLD 报文目的地址：查询用 `ff02::1`，报告/完成发到**被报告组本身的组播地址**（触发该组其他成员的抑制）。
- Hop Limit = 1（仅链路内有效）。

## 5. 组播的典型应用与问题

- 应用：IPTV、视频会议、金融行情组播、路由协议报文（OSPF/RIPv2/PIM 自己就跑在组播上）、SSM 直播。
- **问题**：
  - **欺骗（bogus membership）**：恶意主机大量 join 组，路由器灌入海量流量（DoS）。
  - **伪造 Report/离组**：干扰他人接收。
  - 组播在 Internet 范围部署艰难（跨 AS 的组播路由与商业模型），实际多用 CDN/overlay 替代。

## 6. 广播 vs 组播 vs 单播

| 特性 | 单播 Unicast | 广播 Broadcast | 组播 Multicast |
| ---- | ---- | ---- | ---- |
| 接收者 | 一个 | 链路上所有主机 | 一组（加入了组的）主机 |
| IPv4 支持 | ✔ | ✔ | ✔ |
| IPv6 支持 | ✔ | ✘（无广播） | ✔（大量使用） |
| 跨网转发 | ✔ | 默认不转发 | 需组播路由（PIM 等） |
| 接收端控制 | 无需 | 无（被动全收） | 需 join/leave（IGMP/MLD） |

## 7. 要点回顾

- IPv4 广播：受限 `255.255.255.255`（不出链路）、定向/子网广播（主机位全 1，可转发但默认禁）；IPv6 无广播。
- IPv4 组播 224/4，本地段 224.0.0.x TTL=1 不转发；IPv6 `ff00::/8` 按 scope 组织。
- IP→MAC 映射：IPv4 低 23 bit 到 `01:00:5e:...`（32 组共享一个 MAC）；IPv6 低 32 bit 到 `33:33:...`。
- IGMP/MLD 管理"链路上谁在收组"：查询-报告-抑制-离组；v3/MLDv2 支持源过滤（SSM）。
