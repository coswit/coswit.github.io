> UDP 的头部与校验和；IP 分片机制；UDP-Lite。

## 1. UDP 概述

UDP（RFC 768）提供**最小的、无连接**的运输层服务：

- **无连接**：无握手、无连接状态，开销小、时延低。
- **数据报语义**：保留消息边界（应用每次 sendto 对应一个 UDP 数据报）。
- **不保证可靠**：不确认、不重传、不保证顺序；也不做流控/拥塞控制。
- **支持一对多**：单播、组播、广播皆可（TCP 只能单播）。
- 头部仅 **8 字节**（TCP 至少 20 字节）。

适用场景：DNS、DHCP、SNMP、RTP/流媒体、在线游戏、QUIC（在 UDP 上自建可靠性）等——要么请求-响应短小、要么宁丢不等、要么应用自担可靠性。

| 常见 UDP 应用 | 端口 |
| ---- | ---- |
| DNS | 53 |
| DHCP（服务器/客户端） | 67 / 68 |
| NTP | 123 |
| SNMP（agent / trap） | 161 / 162 |
| Syslog | 514 |
| RTP（实时媒体） | 常用 5004–5005 等区间 |
| QUIC / HTTP/3 | 443（UDP） |

## 2. UDP 头部

```
 0      7 8     15 16    23 24    31
+--------+--------+--------+--------+
|  Source Port   |   Dest Port    |
+--------+--------+--------+--------+
|    Length      |   Checksum     |
+--------+--------+--------+--------+
|          Data ...                 |
```

| 字段 | 说明 |
| ---- | ---- |
| Source / Destination Port | 各 16 bit，分用给应用 |
| **Length** | UDP 头 + 数据的总长度（字节数），最小 8 |
| **Checksum** | 校验和，覆盖伪头部 + UDP 头 + 数据 |

- **端口不可达**：UDP 数据报到达到无人监听的端口时，主机回 ICMP Type 3 Code 3（这是 UDP 上层的唯一"差错反馈"通道，且应用往往收不到，见下）。

## 3. UDP 校验和

### 计算范围（含伪头部 Pseudo Header）

伪头部"虚拟地"参与校验（不实际传输），使校验覆盖 IP 地址与协议号，防止 IP 层误投：

```
IPv4 伪头部 (12B):                       IPv6 伪头部 (40B):
| Source IP (4)        |                 | Source IP (16)          |
| Destination IP (4)   |                 | Destination IP (16)     |
| zero (1) | Proto=17(1)|                | Upper-Layer Length (4)  |
| UDP Length (2)       |                 | zero(3) | Next Hdr=58/17|
```

- 计算方法：16 bit 字反码求和再取反；数据长度为奇数时补零字节；结果为 0 时发送全 1（0xFFFF），因为"校验和=0"另有含义。
- **IPv4 中校验和可选**（0 = 未计算）；**IPv6 中必须计算**（IPv6 头自身无校验和）。
- 差错处理：校验失败**静默丢弃**——不产生 ICMP，应用无感知（数据无声消失是常态）。

## 4. IP 分片（Fragmentation）

### 为什么分片

IP 数据报超过出口链路 MTU 时（Ethernet 1500 B）必须切小。IPv4 中**源主机和中间路由器**都可以分片；IPv6 中**仅源主机**（用分片扩展头），路径超限靠 PMTUD。

### 分片机制（IPv4）

利用 IP 头部三个字段：**Identification、Flags（DF/MF）、Fragment Offset（8 B 单位）**。

```
原始 4000B 数据报 (IP头20 + 载荷3980), ID=111, 链路MTU=1500:
分片1: len=1500, ID=111, MF=1, offset=0    →载荷1480
分片2: len=1500, ID=111, MF=1, offset=185  →载荷1480  (1480/8=185)
分片3: len=1040, ID=111, MF=0, offset=370  →载荷1020
```

- 同一数据报的所有分片共享 **Identification**（源主机每次自增）；**MF=1** 表示后面还有分片；**Offset** 以 8 字节为单位（故除最后一片外每片载荷必是 8 的倍数）。
- **重组（reassembly）只在最终目的主机**进行（沿途路由器不重组）；用 {源 IP, 目的 IP, ID, 协议} 唯一定位一个数据报。
- 重组有超时（如 30–60 s），超时未齐则全部丢弃（可回 ICMP Time Exceeded code 1）。
- 每个分片独立选路，**可能失序、丢失**——任何一片丢失则整个数据报作废，分片放大丢包损失（丢包率 p 时整个报文到达率 (1−p)^n 随片数指数下降）。

### DF 与 PMTUD

- 发送方置 **DF=1** 禁止分片：超 MTU 时路由器丢弃并回 ICMP Type 3 Code 4（携带下一跳 MTU），触发 PMTUD（第 8 章）。
- 现代最佳实践：**尽量避免分片**——发端 MSS/分块适配路径 MTU（TCP 用 MSS 协商 + PMTUD；UDP 应用自己分块或用 PLPMTUD）。

## 5. UDP 与最大数据报长度

- 理论上限：IPv4 Total Length 16 bit → 数据报 ≤ 65535 B；UDP 数据 ≤ 65535 − 20（IP 头） − 8（UDP 头） = **65507 B**。
- 实际上限受**发送缓冲区**与**路径 MTU** 限制；超过接口 MTU 的 UDP 报文在 IPv4 中会触发 IP 分片（或 DF 下被丢弃）。
- 应用层通常把 UDP 报文控制在 PMTU 之内（如 DNS 常限制在 1232 B 左右以稳妥穿越各种网络）。

## 6. UDP-Lite（RFC 3828）

- 变种协议（IPv4 Protocol=136 / IPv6 Next Header=136）：校验和**只覆盖部分载荷**（头部必校验，数据可只校验前 N 字节）。
- 动机：多媒体/语音场景，轻微损坏的帧尚可解码，宁可带错交付也不要整包丢弃。

## 7. 针对 UDP/分片的攻击与问题

- **分片攻击**：交叠分片、超小分片使防火墙看不到完整端口字段而绕过策略（现代防火墙重组后检查）。
- **泪滴攻击（Teardrop）**：构造 offset 矛盾的分片导致老系统重组崩溃。
- **UDP flood**：高流量放大反射（DNS/NTP/memcached 放大攻击利用 UDP 无连接特性 + 伪造源地址）。
- ICMP 不可达黑洞：防火墙吞掉 ICMP 端口不可达，使应用层"连通性探测"失效。

## 8. 要点回顾

- UDP 头 8 B：端口 + 长度 + 校验和；校验和覆盖伪头部，IPv6 下强制。
- UDP 无连接、保边界、不可靠、支持组播；适合短报文与实时流。
- IPv4 分片：ID/MF/Offset(8B 单位)，目的主机重组，任何一片丢失全报文作废；DF+ICMP= PMTUD。
- IPv6 仅源端可分片（分片扩展头），路由器超限回 Packet Too Big。
