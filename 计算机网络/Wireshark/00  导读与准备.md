## 1. 这个系列的由来

本系列由三本书整合而成，主题一致：**用 Wireshark 在数据包层面看清网络**。

- **《Practical Packet Analysis》第 2 版**（Chris Sanders, No Starch Press, 2011，下文称 PPA）：体系最完整的数据包分析教材，前半部讲网络基础与 Wireshark 用法，后半部是三类实战案例（基础故障、慢网络、安全事件）。本系列的工具篇与协议篇以它的章节为骨架。
- **《Wireshark 网络分析就这么简单》**（林沛满，人民邮电出版社 2014，下文称《简单》）：以案例故事讲协议，TCP 窗口、重传、延迟确认与 Nagle 算法等章节是中文世界讲得最清楚的版本之一。
- **《Wireshark 网络分析的艺术》**（林沛满，人民邮电出版社 2016，下文称《艺术》）：进阶案例集，重在分析思路——在途字节数、拥塞点估算、MTU 与分片、用证据定位责任等。

三本书的分工用一句话概括：PPA 教你**用工具**，《简单》带你**看懂协议**，《艺术》教你**像侦探一样思考**。整合时按主题重组，全系列结构如下：

## 2. 阅读路线

- **零基础**：按 01 → 02 → 03 → 04 → 05 → 06 → 07 → 08 顺序通读，09（无线）与 10（方法论）选读。
- **会用 Wireshark 但协议不熟**：直接读 04、05、06，遇到过滤器语法问题回到 02 的过滤器小节。
- **急着排障**：先读 07 的分析框架小节，再按问题类型跳读 05（TCP 类）或 08（安全类）。
- **案例分析控**：07、08 两篇是三本书案例的汇集地，10 篇补充思维方式。

## 3. 抓包环境准备

### 3.1 安装 Wireshark

从官网 [wireshark.org](https://www.wireshark.org) 下载对应平台安装包，支持 Windows、macOS 与 Linux。Windows 安装时会带上 **Npcap** 抓包驱动——它是 Wireshark 与操作系统之间的底层接口，负责把网卡置为混杂模式、抓取原始数据帧并应用过滤规则（PPA 成书时的驱动叫 WinPcap，已停止维护，现由 Npcap 接替，用法一致）。Linux 下各发行版直接用包管理器安装，如 `apt-get install wireshark`。

> 时效注解：PPA 第 2 版基于 2011 年前后的 Wireshark 1.x，本系列涉及界面的描述以当时的菜单结构为参照；现在的 Wireshark 4.x 大同小异，个别对话框位置有调整，工具与过滤器语法完全兼容。

### 3.2 权限与混杂模式

抓包需要把网卡切换为**混杂模式**（promiscuous mode）——正常模式下网卡会丢弃所有目标 MAC 地址不是自己的帧，混杂模式下则把网段上的所有帧都交给系统。因此：

- Windows 与 Linux 下抓包都需要**管理员权限**。拿不到管理员权限的机器，多半也不该在那片网络上抓包。
- 无线抓包还需要网卡与驱动支持**监听模式**（monitor mode，只听不发的无线网卡工作模式）。

### 3.3 准备练习素材

- **官方样例抓包文件**：Wireshark wiki 的 SampleCaptures 页面收录了上百种协议的 `.pcap` 样例。
- **PPA 的配套抓包文件**：原书每章都带示例文件（如 `tcp-con-lost.pcap`、`blaster.pcap`），可在 No Starch Press 的本书页面下载。
- **自己动手造流量**：`ping`、`curl`、浏览网页、`ftp` 一次，都是最简单的练习素材。学习抓包最好的方式就是对着自己产生的流量逐包分析。

## 4. 分析之前先有基线

> When your network is running smoothly, you can set your baseline so that you'll know what its traffic looks like in a normal state.
>
> 趁网络运行正常时先建立基线（baseline），你才能知道正常状态下的流量长什么样。

这是 PPA 反复强调的原则：**大多数分析人员研究正常流量的时间远多于排障的时间**。想靠抓包排查 DHCP 问题，得先知道正常的 DHCP 四步交互长什么样；想知道某台服务器是否异常，得先存一份它健康时的抓包。没有基线，看到异常也无从判断它是异常。

具体做法：在网络空闲与高峰时段各抓一次包，记录 Protocol Hierarchy（协议分布）、典型会话的往返时延、广播流量的占比。这些数字在 07 篇的案例里会一一派上用场。

## 5. 三本书的共同心法

把三本书翻到最后，作者们给的忠告惊人地一致：

1. **一切从数据包出发**——日志会骗人、用户会更会骗人，网卡上的帧不会。
2. **先搞清"已知"，再抓包求"未知"**——每个案例动手前先列清单：我们已知道什么？还差什么？去哪里抓？
3. **不懂协议就读 RFC**——Wireshark 只是把字节翻译给你看，真正理解协议要回到定义它的文档。
4. **保留好奇心**——问题表象（"网速慢""连不上"）与根因（错配的网关、后台的间谍软件、过小的窗口）之间往往隔着好几层，逐包分析就是剥开这些层的工具。
